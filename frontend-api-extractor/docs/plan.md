# 实施计划

实施顺序调整：先执行[黑盒二计划](../../website-js-extractor/docs/plan.md)，验证 JS 分析核心，再推进白盒构建接入。下列 P1 分析基线与黑盒二共用验证材料，构建输入和白盒结果仍单独核验；不因黑盒二完成而自动勾选。

## P0：重置与设计

- [x] 删除旧分析器、CLI、测试、样例、基准、模型、配置和依赖，不保留不可用兼容层。
- [x] 将文档收敛为需求、架构、分析设计、测试和实施计划。
- [x] 明确四项输出、jshound 基线、定向追踪、AI 边界和打勾规则。
- [ ] 评审并冻结第一版阶段协议：Task、Asset、AssetEdge、SendSite、Request、Gap。
- [ ] 选择公开开发集和独立盲测集，冻结 Commit、构建方法和人工标注范围。

## P1：验证 jshound 基线

- [ ] 在同一冻结构建资产上运行原生 jshound 完整目录模式，保存版本、命令、时间、内存和原始结果。
- [ ] 人工核对 URL、参数、Host、JS 文件，形成逐发送点差距表。
- [ ] 验证其 Webpack/Vite chunk 深入、module index、wrapper 和 source map 实际边界。
- [ ] 建立可访问增强 fork，锁定上游 Commit、许可证和补丁分支。
- [ ] 根据实测决定直接增强位置与外层编排边界，不先建空框架。

## P2：最小可用链路

- [ ] 实现任务 CLI：仓库地址、Commit、构建配置、输出目录和进度。
- [ ] 实现受控 checkout、锁定安装、正式构建和失败日志。
- [ ] 建立构建资产清单并调用 jshound 增强核心分析本地目录。
- [ ] 输出四项 JSON；候选、部分和确定结果分开。
- [ ] 输出精简表格：JS 文件、Host、URL、方法、参数、状态、证据位置。
- [ ] 完成最小矩阵和公开开发集验收。

## P3：嵌套 JS 与资产覆盖

- [ ] 逐资产处理全 map、无 map 和部分 map，正确去重。
- [ ] 支持循环、多父、重复内容、同名文件和动态未知边。
- [ ] 增加资产覆盖、停止原因、获取/分析预算和增量缓存。
- [ ] 通过三层以上嵌套资产发布门槛。

## P4：Host、URL 与参数还原

## 打勾规则

每一项必须同时满足：

1. 实现已经进入主干；
2. 正常和反例自动化测试通过；
3. 该项要求的冻结公开输入验证通过；
4. 文档记录实际边界和未完成部分；
5. 没有用减少扫描范围、放宽预期或增加候选数冒充效果提升。

设计完成只能勾设计项，不能勾实现项。部分完成继续保持 `[ ]`，并在条目下记录剩余条件。
