# 开发约定

## 目录和职责

[README](../README.md)是入口。需求只维护 [requirements](requirements.md)，架构维护 [architecture](architecture.md)，当前进度维护 [roadmap](roadmap.md)，可执行命令维护 [usage](usage.md)，验收规则维护 [testing](testing.md)。明确区分当前实现和设计目标。

专题机制放 `docs/reference/`，发布和样本记录放 `docs/archive/`。不再向 README 堆版本报告，不在主仓库 docs/ 另建提取器计划。历史能力记录保留，当前任务集中勾选。

`src/`、`tools/`、`test/`、`profiles/`、`models/`、`baselines/`、`examples/` 各守职责。新核心在本工程替换；语言由验证决定，新增工具链给出锁定、安装和运行说明，不复制第二套完整项目。

参考项目在主仓库 `references/repos/`，增强 fork 提交先推送再引用。外部 checkout、目标依赖、产物、完整报告只写主仓库 `work/`；Git 只收小样例、冻结哈希/预期和第三方链接。

## 一次迭代

1. 从开发计划选有限任务，明确触发条件及预期四项结果。
2. 验证最小反例和冻结公开输入；性能变化同时检查漏报、误报与归属。
3. 完成实现、相关回归及必要的真实对照；失败和缺口不能静默变成成功。
4. 更新计划、使用说明和实际验证证据；未实现继续保持未勾选。
5. 检查主仓库自有 MD 链接和口径，不递归改写第三方子模块。
6. 提交推送并核对远端；核心切换前完成新旧同输入验收。

`[x]` 只表示限定范围实现并验证，不能用写完设计或增加测试数代替能力验收。文档整理不表示分析缺陷已修复。
