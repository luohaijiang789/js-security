# 需求

## 1. 目标

用户提供前端代码仓库地址和必要构建信息。工具固定 Commit、执行可复现构建、递归分析生成的 JS，输出每个可识别请求的 **URL、请求参数、Host、对应 JS 文件**。

方法、行列、源码映射、调用方、条件和未解析原因作为辅助证据，不替代四项主结果。

最终目标是全部前端 API 的可追溯统计，覆盖业务代码和第三方依赖/SDK 请求。按[讨论结论](../../docs/api-discovery-decisions.md)，白盒必须利用源码、依赖声明和模块关系：明确业务请求优先提取，封装和依赖中的请求继续深入。不得以只扫构建目录取代源码上下文，也不得承诺简单规则已获取所有业务 API。保留构建产物核验，具体阶段协议仍待评审。

## 2. 输入

| 输入 | 必需 | 说明 |
| --- | --- | --- |
| 仓库地址 | 是 | 第一版支持 Git HTTPS；其他来源后续适配 |
| Commit | 是 | 必须落为完整 Commit，不使用浮动分支作为最终证据 |
| 项目目录 | 否 | 支持 monorepo 中指定子项目 |
| 构建配置 | 是 | Node/包管理器版本、锁文件、安装和构建命令、产物目录 |
| 构建环境 | 按需 | 只提供构建必要值；来源和是否缺失必须记录 |
| 扫描范围 | 否 | 资产根、允许的外部静态资源域、文件/字节/时间上限 |
| AI 配置 | 否 | OpenAI 兼容接口；未配置时静态主流程仍可运行 |

构建失败必须返回构建失败，不能静默改成源码扫描成功。工具不执行构建产物中的业务逻辑，也不主动调用提取出的 API。

## 3. 输出

| 字段 | 定义 |
| --- | --- |
| URL | 发送调用使用的绝对地址、相对路径或路径模板；动态段保留表达式/占位符和解析状态 |
| 请求参数 | Query、Path、Body、Header 的字段名、嵌套路径和载体；字段存在、值未知、结构未知分别表达 |
| Host | scheme + authority；同时记录来源：字面量、baseURL、构建环境、页面上下文或运行时未知 |
| JS 文件 | 包含最终发送调用的构建资产；保留哈希、可用行列、source map 源文件和引用路径 |

输出至少包括一个面向用户的主表和一个可机器复核的 JSON。未核验候选、已确认发送点、未恢复完整地址的请求必须分组，不能混成同一种结果。

## 4. 必须覆盖

- fetch、XMLHttpRequest、Axios 常见形态及其别名。
- 自定义请求封装和多层函数传参。
- ESM/CommonJS 导入、重导出、动态 `import()`。
- Webpack 4/5、Vite/Rollup、Rspack、Parcel 等可识别的 chunk 引用。
- Worker、SharedWorker、Service Worker 和 `importScripts` 的静态引用。
- 字符串拼接、模板字符串、URL/URLSearchParams、对象展开、条件字段和常见序列化。
- baseURL、客户端实例默认值、构建时环境值和可静态确定的请求 hook。
- 无 source map、完整 source map、部分 source map。
- 多父引用、循环引用、重复内容、同名文件和缺失资产。

## 5. 明确边界

- 不能静态确定的运行时配置、服务端下发地址、`eval` 内容和运行时解密允许保持未知。
- 压缩和变量重命名应支持；任意控制流混淆不承诺完整恢复。
- 构建产物中的请求表示客户端可能发送，不证明服务端接口仍存在或当前用户可访问。
- AI 不能凭字段名补造 Host、URL 或参数，只能提出待静态核验的结构化建议和字段释义。
- 第一阶段不做敏感性识别、风险评级、漏洞判断和主动请求验证。

## 6. 完成标准

1. 对冻结测试范围先人工列出请求发送点和四项预期，再运行工具。
2. 可静态恢复的最小反例全部通过。
3. 至少一个未参与规则开发的公开仓库给出发送点和字段的真实分子/分母。
4. 每个发现资产都有已分析、失败、超限、重复或动态未知状态。
5. 同一共享依赖不会因入口数量线性重复完整分析。
6. 运行过程持续输出阶段、进度和停止原因；空结果与扫描未完成不能都返回成功。
7. 主表中的每条确定结果都能回查对应 JS 和证据。
