# 需求

## 目标

输入前端代码仓，固定版本并正式构建，对得到的 JS 及其嵌套引用做有界深入分析，交付 **URL、接口参数、Host、对应 JS 文件**。

本文件定义目标，不表示当前版本全部实现。实现状态只在[开发计划](roadmap.md)维护。

## 输入

| 输入 | 要求 |
| --- | --- |
| 仓库与版本 | 当前入口接受 GitHub HTTPS 地址；记录完整 Commit。其他来源待适配 |
| 构建配置 | 项目目录、包管理器/版本、锁文件、构建脚本、产物目录 |
| 环境 | 必要构建环境值；部署地址或配置显式提供，保留来源 |
| 范围与预算 | 产物目录、外部资产访问范围、文件/字节/时间等上限 |

构建失败就是该任务失败；源码扫描可独立诊断，不包装为构建成功。允许受控安装和正式构建，不主动调用识别出的 API。

## 四项结果

| 必需信息 | 语义 |
| --- | --- |
| URL | 原始请求地址及可还原的有效地址/路径模板；动态段使用占位符，查询字段另列 |
| 接口参数 | Query、Body、Header 的字段名、嵌套路径和载体，路径参数保留在 URL 模板；字段已知、值未知、结构未知分别表示 |
| Host | 请求目标 authority，包括存在的端口；附来源与状态。不借用脚本下载域名或开发代理来猜 |
| 对应 JS 文件 | 包含发送调用的构建资产路径/URL、哈希及可取得的行列；能关联时附源码与业务调用位置 |

方法保留为辅助列并参与区分请求，不改变四项主目标。源码和构建 JS 位置分开，不能用源码替代缺失的产物归属。未知行列不补造第 1 行。

主表按已定位发送点及业务调用关系组织，条件变体和不同阶段另存关联信息，不将互斥字段无条件并集。未核验候选、已识别但未解析发送点与已恢复请求分组计数。

## 必须覆盖的引用形态

- 构建目录入口 JS、同步模块和动态 `import()`。
- 懒加载 chunk 及其继续引用的 chunk。
- 打包产物内部模块关系；内部模块层数不等于外部获取深度。
- Worker、`importScripts`、HTML/manifest/runtime 声明的脚本线索。
- 多父节点、循环引用、同内容不同地址、同文件名不同目录。
- 动态引用、资产缺失、下载失败和超限：保留未解决边及影响。

分清“资产是否找到”和“请求值是否还原”，找到 chunk 不代表最终 Host/参数都已确定。机制见[架构](architecture.md)。

## 完成标准

1. 每个发现资产和引用都有状态，停止位置可解释，不用少量已分析文件充当整仓分母。
2. 对可静态恢复样本，四项结果与人工预期逐项对照，报告准确率、召回率及误归属。
3. 固定公开仓库分别验证无 map、全 map、部分 map、深层 chunk 和多层封装。
4. 安装/构建、收集、解析、分析、交付分阶段计时，记录峰值资源和未完成任务。
5. 交付 Excel 与可回查底稿，大报告不要求用户手工拼接。

最终值依赖运行时且无输入依据时允许未知，不承诺任意 JS 完整还原。AI 辅助找封装/配置、解释字段，须标来源并核验。敏感性分类、风险分级和主动业务请求不在本阶段。
