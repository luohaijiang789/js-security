# 测试与验收

## 1. 原则

- 预期结果先于工具输出建立，不能从扫描结果反推“正确答案”。
- 最小测试验证语义，公开仓库验证组合效果，性能测试验证可扩展性。
- 候选数量不是召回率；少扫文件也不是性能优化。
- 每次报告输入 Commit、构建配置、资产哈希、引擎版本、分母和失败清单。

## 2. 测试层次

| 层次 | 内容 | 通过条件 |
| --- | --- | --- |
| 单元 | 地址片段、对象字段、绑定、引用边、身份 | 可确定输入全部精确通过 |
| 组合样例 | wrapper、client、hook、chunk、source map | 四项结果和缺口符合人工预期 |
| jshound 上游 | 固定上游测试和真实 bundler fixture | fork 不破坏上游能力 |
| 公开仓库开发集 | 已知仓库固定 Commit | 用于调试，结果不外推 |
| 公开仓库盲测集 | 未参与规则开发的仓库/模块 | 报告真实召回、精确率和资源 |
| 性能图 | 1/10/100 入口、深度、分支和共享依赖 | 时间和内存增长可解释，无重复全量分析 |

## 3. 最小测试矩阵

- 直接 fetch/Axios/XHR/beacon 与同名非网络函数。
- URL 分段、baseURL 分离、条件 Host、运行时 Host。
- Query/Body/Header/Path，嵌套字段、展开、删除和未知 spread。
- 两层、五层和循环 wrapper；多个调用方传入不同参数。
- 两个 client 实例使用不同 Host 和 hook，不能串线。
- ESM/CommonJS、重导出、动态 import、Worker/importScripts。
- Webpack 4/5、Vite/Rollup 的三层以上 chunk、多父与缺 chunk。
- 全 map、无 map、部分 map、同名文件和相同内容不同 URL。
- L0/L1 混淆及 L2/L3 明确降级。
- AI 正确建议、错误建议、拒答和无 AI 四种情况。

## 4. 公开仓库

使用两组：

1. **兼容开发集**：可继续使用固定的阿里/阿里云公开仓库，但重新建立构建快照和人工预期，不继承旧工具结果。
2. **独立盲测集**：选择未用于实现调参、能稳定构建、包含懒加载和请求封装的典型前端仓库；冻结后先人工标注限定范围，再首次运行。

每组至少交付：仓库/Commit、构建步骤、产物哈希、资产数、人工发送点数、工具发现数、正确/漏报/误报明细、四项字段正确率、运行时间、峰值 RSS 和报告大小。

## 5. 指标

| 指标 | 分母 |
| --- | --- |
| 发送点召回率 | 人工标注的全部范围内发送点 |
| 发送点精确率 | 工具输出的确认发送点 |
| URL/Host 正确率 | 人工标注中可静态确定的对应项 |
| 参数字段召回/精确率 | 按调用、载体、字段路径计算 |
| JS 归属正确率 | 有明确构建资产归属的发送点 |
| 资产覆盖 | 已发现资产按分析/失败/超限/未知状态统计 |
| 性能 | 分阶段墙钟时间、峰值 RSS、缓存命中、输入规模 |

运行时才确定的 Host 不进入“静态可恢复 Host”分母。未知位置不算定位成功。条件互斥的请求分别核对，不能合并参数后算一条正确结果。

## 6. 发布门槛

- P1 技术原型：原生 jshound 对冻结输入可复跑，差距报告完成。
- P2 最小版本：最小矩阵全部通过，公开开发集产生可回查四项表。
- P3 嵌套资产：三层以上 chunk、循环、多父、缺失和部分 map 全部通过。
- P4 请求还原：独立盲测给出真实分子/分母，严重误归属为 0。
- P5 默认发布：大仓库在约定时间/内存内完成，失败和空结果退出状态可靠。

每个阶段门槛达到后，才在[实施计划](plan.md)将对应项改为 `[x]`。
