# 验证与性能

## 当前证据

最近一次功能审计的基线为 0.10.0：普通测试 **316/316**、固定 jshound 集成 **8/8** 通过；另六组[审计探针](../tools/audit-design.mjs)均复现缺陷。因此测试通过不能解释为整体目标达成。本次文档整理不重跑目标仓库构建，不新增准确率或性能结论。

[RuoYi 历史对照](archive/releases/release-0.10.md)是开发基准：160 输入，hybrid 精查 20 文件，既有 15 位置/11 字段检查通过；两引擎端到端中位数约 4.1 秒，没有显著提速。它没有证明其他 140 文件经过同样语义分析，也不是独立全仓盲测。

## 可执行检查

从 `frontend-api-extractor/` 执行，先 `npm ci`。实际需要 jshound 时先在主仓库初始化对应子模块。

```bash
npm test
npm run test:jshound
node tools/audit-design.mjs
```

探针 `defect-reproduced` 表示问题仍在；退出 0 只表示诊断完成。修复时将反例转成断言正确结果的回归，不能把“继续复现缺陷”当作质量通过。冻结样本/差异命令见[基准机制](reference/baselines.md)、[人工预期](reference/external-baselines.md)。

纯文档调整检查主仓库自有 MD 链接、迁移目标、代码/配置路径、命令帮助和变更空白；不重跑全部构建，不改第三方子模块。

## 样本与正确性

| 层次 | 检查内容 |
| --- | --- |
| 最小反例 | 拼接、跨文件封装、别名、条件字段、hook、合法特殊字段和失败状态 |
| 资产图 | 3 层以上本地嵌套、循环/重复、多父、缺 chunk、动态未知、受控远程深度截断 |
| 构建产物 | 全 map、无 map、部分 map、冲突 map、源码被删除及相同代码不同归属 |
| 公开仓库 | 未用于规则调参的典型业务仓库；固定 Commit、环境、锁文件和产物哈希 |
| AI | 参数映射、字段含义、拒答及无依据推断；与纯静态结果分开 |

人工先列限定范围内全部请求发送位置及可恢复四项信息，再运行工具；预期不能从本工具输出反推。方法保留作辅助校验，参数按载体和字段路径对照。主表能回查原始 JS、引用路径和证据；未知位置不算定位成功。

分别报告发送点召回/精确率、URL/Host/方法正确率、字段召回/精确率、误归属、重复变体及未支持资产。运行时才可决定的 Host 单列，不能混入“已静态恢复”分子。已知可恢复的最小反例须全部通过；公开样本必须给实际分子/分母及误报清单，不能只展示成功接口。

## 性能与完整性

分阶段记录安装/构建、收集/下载、解析/索引、请求分析、归并/Excel 的墙钟时间、峰值 RSS、输入文件/字节与输出大小。冷/热缓存分别测，同输入重复运行并报告条件。目标语言、引擎或缓存变化都使用同一份资产快照比较。

固定依赖图测 1/10/100 个引用入口，以及不同封装深度和分支数；检查共享调用是否重复展开。maxSteps 只计旧语义求值，不覆盖所有阶段；不能直接比较不同引擎步数，也不能用裁掉文件证明提速。

覆盖分为资产收集、解析/索引、请求发现、定向还原、交付五个阶段；报告每阶段已完成、超限、失败、未知及未尝试数量。整体“任务完成”、分区 finished、模型 complete 和候选正确率分别解释。新核心切默认前，须对同输入验证四项结果、误报、资源及退出/缺口契约。
