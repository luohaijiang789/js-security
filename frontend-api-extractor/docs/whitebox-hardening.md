# 白盒复杂 JS：先核查，再补强

2026-10-27，0.3.0。重点是 JS 资产识别、Host/URL、参数字段与证据，不把候选清单数量当作完整性。

## 复查得到的情况

| 用户关注点 | 0.2 实际边界 | 本轮措施 |
| --- | --- | --- |
| JS 引用 JS | 有模块绑定，但输出缺少实际资产与引用清单 | 输出 assets：原文件 SHA-256、解析状态、模块引用及位置、内部目标/动态/未扫描状态 |
| URL 分多段 | 基础拼接/模板/索引可处理，join/concat 等会丢线索 | 增加受限、确定性的字符串和数组操作，继续通过跨文件参数传播 |
| Host 藏在配置 | baseURL 混在有效 URL 中，没有独立 Host 状态 | 保留 requestUrl/baseURL，拆分 host、origin、path 和 hostState；不从源码路径猜业务域名 |
| 参数分散构造 | 简单属性赋值已有，Object.assign 和 JSON 序列化缺少结构证据 | 补合并与构造字段列表；区分未知值、未知覆盖和序列化阶段 |
| 后续 hook | Axios 注册可能被跳过，缺少明确的请求侧降级 | 检测直接 request interceptor 注册，关联客户端、保留代码位置，标 postHookState=unknown |
| 混淆、编码、加密 | 不能统一保证静态还原 | 标准字面量编码白名单静态处理；未知解码器、eval、运行时密钥保持未知 |

此前核查 GDB 页面入口时已遇到普通类实例工厂和预算耗尽；这轮不把 API 层成功解释为已解决这些问题。

## 当前输出怎么读

- assets 只列本次扫描文件及 ESM/re-export/require/dynamic-import 引用，不等于完整运行时 JS 资源图。破损文件也留下记录，不以没有接口当作没有文件。
- address.hostState 独立于旧 resolution：相对 URL 可明确，但 Host 仍未知；协议相对 URL 可确定 Host，但 origin 不猜页面协议。request hook 存在时，已知 Host 也仅为调用处候选。
- parameterFields 使用载体、字段路径数组、状态和 constructed 阶段。来自 URL 的 Query 名也保留。未知字段值不抹掉已知字段名，但未知 spread 覆盖整个嵌套对象时，不伪造原先子结构仍然有效。
- JSON 序列化可保存构造字段和已知字符串；它不证明最终网络字段。未知 encrypt 的输入字段不能直接列为密文载荷的字段。
- parameterStage=call-site；postHookState=not-observed 仅表示未检测到本模型支持的注册，绝不是没有任何 hook 或网络载荷已验证。

## hook 的保守范围

支持源码中直接的 `client.interceptors.request.use(...)` 注册、ESM 绑定和常见变量别名。仅把这些位置作为可能改写的证据，不执行 hook、不完整求解注册/eject 顺序、条件或响应后触发的新请求。注册可能处于未执行模块或条件内，所以降级可能偏保守；动态注册、改写 fetch、框架专用 hook 和复杂别名仍可能漏识别。

请求头、Host、URL 和 body 都可能被 hook 改变。后续应按客户端实例和执行顺序建立“调用处构造 → hook 改写 → 序列化 → 发送候选”阶段模型；无法理解的改写应在受影响阶段中断精确推导，而非把当前值冒充最终值。

## 混淆处理原则

1. 保存原 JS 与哈希，所有结果回指原文件；目前没有另行改写源文件或通用反混淆器。
2. 标准字符串转义由 parser 处理；静态字符串表索引、join/concat、字面量 atob、URI 编解码和 fromCharCode 用固定白名单模型处理。局部同名函数不冒充标准函数。
3. 编码不是加密。运行时密钥、远程配置、eval、自定义复杂解码或控制流平坦化，不宣称已经还原，也不执行目标代码求值。
4. 标准解码有输入/参数长度保护；失败保留表达式与诊断。后续仍需补字符串/对象总体内存预算和压缩模块适配，不能仅增加调用层数。

## 核查证据与后续顺序

新增 18 项针对性测试，合计 70 项通过，覆盖跨文件配置、分段 Host、动态 baseURL、字面量编码及同名反例、字段覆盖与合并、序列化、跨文件 hook/客户端隔离、资产引用与解析失败。

使用[已固定版本的 Nacos](alibaba-real-world.md)额外扫描 namespace.ts：203 个可解析资产，5 个请求调用点生成 10 个动态前缀候选，全部标记 request hook 后状态未知。此项只验证关联与降级，不是 hook 参数推导或全仓覆盖率验收；外部仓库仍只留链接。

接下来优先：稳定客户端实例/类工厂传播 → 有顺序与分支的 hook 模型 → 参数删除/编码/序列化阶段 → 同版构建压缩 JS 对照。AI 字段解释应读取这些证据与未知状态，不替代 Host、URL、参数的确定性提取。
