# 分析设计

## 1. 分析顺序

以下是构建资产分析内部顺序。白盒完整流程还必须利用业务源码与依赖上下文：明确的接口定义及已知封装先提取，复杂业务封装与第三方 SDK 按请求相关链路深入，再与构建资产核对。不能只统一扫描产物就宣称完成白盒；具体阶段协议按[讨论结论](../../docs/api-discovery-decisions.md)继续评审。

1. 建立全部可取得 JS 的资产图和模块索引。
2. 识别直接发送 API、客户端实例、SDK 和自定义 wrapper。
3. 将候选绑定到真实 AST 位置，区分发送点和普通 URL/路由字符串。
4. 从发送点只反向追踪 URL、Host、方法和参数相关值。
5. 合成实例默认值、调用参数、条件改写和可支持的 hook 阶段。
6. 输出确定值、候选值和未知原因，不执行目标业务代码。

## 2. 发送点发现

首批发送机制：fetch、XMLHttpRequest、Axios、Navigator.sendBeacon。发现方式同时使用：

- 内置 API 的绑定身份，而非只匹配变量名；
- import/require、别名、重导出和 namespace；
- `axios.create` 等实例来源；
- jshound wrapper 模板和模块导出索引；
- 用户或 AI 建议的 client 契约，经绑定验证后加入。

路由、资源加载、WebSocket 等不同机制单独分类。字符串像 URL 不是发送点；同名 `request()` 也不自动视为网络调用。

## 3. URL 与 Host

地址抽象值由有序片段组成，每个片段保存常量、参数、对象属性、环境值或未知表达式及证据。支持：

- 字面量、模板字符串、`+` 拼接；
- `new URL()`、URLSearchParams；
- client baseURL + 请求 path；
- 构建时替换的环境变量和配置常量；
- 条件候选和路径参数。

Host 来源优先级不是“猜测优先级”，而是证据分类：绝对 URL、客户端实例、构建配置、页面部署上下文、运行时未知。脚本 CDN Host、开发代理和页面 Host 不自动当作 API Host。

## 4. 参数

参数按载体分别追踪：Path、Query、Body、Header。抽象对象至少支持字面量、浅/深字段路径、确定展开、Object.assign、别名、条件写入、删除和常见序列化。

每个字段保存：路径、载体、存在状态、值状态、来源位置、条件和阶段。未知 spread 只令可能受影响的字段/载体不完整，不能抹除同对象中已经确定的字段。

Body 第一阶段支持 JSON、FormData、URLSearchParams 和普通表单对象。加密后值可以未知，但加密前已知字段与“最终线上字段名可能改变”必须分别表达。

## 5. 多层封装

wrapper 摘要描述：

- 哪个形参进入 URL、method、headers、query、body；
- client/baseURL/defaults 的来源；
- 返回值和相关对象写集；
- 条件、hook 和未知副作用。

调用方实参与摘要组合，直到到达业务调用位置、值稳定或预算停止。递归使用工作列表和收敛规则，不按每个入口重复从头解释共享函数。

## 6. Hook 与副作用

结果至少区分调用构造阶段、client 默认值合成阶段、请求 hook 后候选。只支持能够静态证明顺序和实例归属的同步 hook；异步、条件注册、动态 eject 和闭包状态保持未知。

无法识别的函数调用按读写影响降级：已知纯函数可保留，未知函数只污染可能被其写入的值，不默认让整个请求对象失效。

## 7. 混淆分级

| 等级 | 示例 | 处理 |
| --- | --- | --- |
| L0 | 压缩、变量重命名、常量折叠 | 必须支持 |
| L1 | 字符串数组、简单解码函数、成员间接访问 | 有界常量求值与模式适配 |
| L2 | 控制流平坦化、复杂闭包状态、动态属性表 | 输出部分结果和具体缺口 |
| L3 | eval/new Function、运行时下载代码、运行时密钥解密 | 静态未知；后续可与受控动态观测关联 |

不把“反混淆成功”作为提取前置条件。先识别发送 API 和相关切片，只对四项相关表达式做局部还原。

## 8. AI

AI 有两个独立用途：

1. **封装识别建议**：输入最小代码切片，返回 client 创建点、发送函数、参数映射和需要继续读取的符号。
2. **字段释义**：对已静态提取字段增加业务含义候选。

建议采用结构化 JSON，并保留模型、提示版本和输入哈希。第一类建议必须经 AST 绑定、实际调用形态和反例核验后才能影响确定结果；第二类只能写 annotations，不能修改提取事实。默认不向模型发送字段值、密钥或完整仓库。

## 9. 结果置信度

每项事实使用 `confirmed`、`partial`、`candidate`、`unknown` 四种状态：

- `confirmed`：有直接语法/绑定/构建证据。
- `partial`：已恢复部分结构并明确缺口。
- `candidate`：启发式或 AI 提议，尚未核验。
- `unknown`：当前输入无法静态确定。

状态按 URL、Host、每个参数载体和 JS 位置分别记录，不能用一个全局 complete 掩盖差异。
