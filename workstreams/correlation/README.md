# 双向关联的共享契约与待办

目标：把实际观察、代码推导和整改建立可复核关系。流程见[核心架构](../../docs/00-总览/核心架构.md)，字段判定见[取证规范](../../docs/01-方法体系/前端数据采集与跨境透传审计体系总方案.md)。

## 最小对象

| 对象 | 必填字段 |
|---|---|
| 案件/资产 | case_id、范围、版本/环境、角色、脚本/配置身份、取得状态 |
| 观察 | observation_id、场景/运行/target、请求引用、方法/端点、字段载体/路径、值表示、脚本/发起线索、状态、证据 |
| 白盒路径 | flow_id、版本/位置、来源、变换、发送/接收、条件、时序、未知边、证据 |
| 关联/主张 | 观察/路径引用、匹配依据、相容性、反证、待证内容及状态 |
| 任务 | 来源 ID、目标、允许材料/动作、依赖/负责人、完成条件、结果引用 |
| 整改 | 根因、关联路径/观察、真实控制点、业务约束、旁路、复验、未结项 |

请求 ID 带运行/会话和 target 范围；重定向、批量事件保留父请求与次序。端点归一化保留原始证据，字段重命名/变换显式记录。优先已有身份，不把个人标识加入新追踪头。

## 关联状态与回路

| 状态 | 输出任务 |
|---|---|
| 候选匹配 | 核版本、脚本、变换、条件，不因名称相同确认 |
| 支持相应主张 | 保留适用场景，扩展同机制其他调用者 |
| 只有黑盒 | 查部署/远程/注入与静态遗漏 |
| 只有白盒 | 查触发/采样/时序与观察能力 |
| 冲突/版本不符 | 查分歧边或拆成不同事件，不能覆盖原观察 |

- [ ] 助手为两侧准备一份填好字段的交接示例和一个冲突反例。
- [ ] 试点至少完成一次往返，记录扩出的接口/场景。
- [ ] 将同根因路径合并整改，保留调用者差异。
- [ ] 修改/配置/权限变化可定位受影响主张和重验任务。

模板见[整改卡](../../docs/05-模板/发现与整改卡.md)；输入字段参考[GitHub schema 核查](../../references/06-开源项目/GitHub方案核查.md)，不直接复制工具默认格式。当前仅概念契约，未生成 schema 或匹配实现。
