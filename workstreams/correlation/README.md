# 双向关联的共享契约与待办

目标：把实际观察、代码推导和整改建立可复核关系。流程见[核心架构](../../docs/00-总览/核心架构.md)，字段判定见[取证规范](../../docs/01-方法体系/前端数据采集与跨境透传审计体系总方案.md)。

## 最小对象

| 对象 | 必填字段 |
|---|---|
| 案件/资产 | case_id、范围、版本/环境、角色、脚本/配置身份、取得状态 |
| 观察 | observation_id、独立/定向来源、快照/父任务、场景/运行/target、请求引用、载体/字段路径、原始与解析引用、完整性、事实阶段、发起线索、证据 |
| 白盒路径 | flow_id、版本/位置、机制/调用者、字段写入/覆盖链、变换类型、发送/接收、条件、时序、未知边、证据 |
| 关联/主张 | 观察/路径/字段引用、具体待证内容、匹配依据、版本/配置/条件相容性、反证、候选/支持/反驳/未决及适用范围 |
| 任务 | 来源/父任务、独立/定向、最小待证主张、竞争解释、允许材料/动作、依赖/负责人、预期/反例、停止条件、结果引用 |
| 整改 | 根因、关联路径/观察、真实控制点、业务约束、旁路、复验、未结项 |

请求 ID 带运行/会话和 target 范围；重定向、批量事件保留父请求与次序。端点归一化保留原始证据，字段重命名/变换显式记录。优先已有身份，不把个人标识加入新追踪头。

## 字段身份与版本约束

| 约束 | 必须保留 |
|---|---|
| 网络身份 | run、target/session、request、redirect hop；不能拿 request ID 当跨系统全局键 |
| 载荷身份 | 原请求、批次/事件位置、载体与字段路径；一个请求多个事件分别映射 |
| 字段血缘 | 最初来源、历次写入/覆盖、变换、最终序列化、发送/转发；与请求发起者分开 |
| 配置身份 | 应用构建、实际脚本/哈希、配置快照/适用时段、角色/租户、SW/缓存状态 |
| 观察质量 | 相关 target/载体能力、附着时间、完整/部分/不透明/缺失/不支持、解析器与干预条件 |
| 证据来源 | 原始来源/派生关系；同一 Hook 的两个报告不能伪装成独立印证 |

缺配置时不强行对齐生产；URL 归一化、字段脱敏和解码不丢原引用。证据匹配有多种解释时保留候选集合，用能区分解释的场景或源码边再收敛。

## 关联状态与回路

| 状态 | 输出任务 |
|---|---|
| 候选匹配 | 核版本、脚本、变换、条件，不因名称相同确认 |
| 支持相应主张 | 保留适用场景，扩展同机制其他调用者 |
| 只有黑盒 | 查部署/远程/注入与静态遗漏 |
| 只有白盒 | 查触发/采样/时序与观察能力 |
| 冲突/版本不符 | 查分歧边或拆成不同事件，不能覆盖原观察 |

## 一次交接示例与冲突反例

以下均为假设，不是已观察的站点事实：

| 项目 | OBS-01 → TASK-01 |
|---|---|
| 输入 | RUN-01/target-T/request-R/第 0 跳，POST /api/order/create，header.bx-ua；实际脚本/配置未知项列明 |
| 待证主张 | 该版本/配置下，哪个写入点向此请求加入该头 |
| 竞争解释 | SDK 注入、业务默认头、其他包装器；不能因字段名就选 SDK |
| 完成条件 | 取得相容版本的写入/匹配/覆盖证据，或返回具体版本/实现断点 |
| 后续 | 定位后枚举导出等其他调用者，由 TASK-02 指定角色/匹配条件补黑盒观察 |

冲突例：两个请求都发往 /collect，但一个是错误事件、另一个是回放批次，page 字段也同名。按批次/事件、脚本、条件与字段变换拆开，不把一个的过滤证据用于另一个。

相同主张/版本/问题不得无新证据循环派发。任务在支持、反驳、有界未见或有负责人的缺口时返回；新配置/场景/来源出现才重新打开相应任务。所有关闭保留状态区别，不将有界未见当通过。
