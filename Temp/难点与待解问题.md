# 白盒 V1 问题台账与落地关卡

**本台账服务一个交付：Host → 前端 JS 请求接口 → 参数 → 含义/敏感性线索 → 代码依据表。** 默认只递归取得三层引用 JS，其他代码不展开。

当前没有接入目标仓和 Host。以下是预计会遇到的工程问题及处理规格，**不是已发生故障，也不表示方案已验证**。原来的机制清单不足以安排实现，本稿补齐未决输出、材料依赖、验收与实施顺序。

## 1. 优先级与责任

| 标记 | 含义 |
|---|---|
| P0 | 第一版必须正确处理；处理不了可返回部分结果/未知，但不能误报完整、无参数或无风险 |
| P1 | 第一版先识别并记录边界，按试点决定深入支持；不能静默漏掉 |
| 实现责任 | JS 获取、解析/数据流、导出与测试负责人，均待指定，可由同一人兼任 |
| 补证责任 | 前端/发布提供代码和配置；业务解释字段；SDK 提供方补封闭实现；合规复核跨境适用事实 |

**区分任务能否运行和结论能否关闭。** 缺远程 JS 不必停掉所有分析，但依赖它的字段不能宣称追清；缺运行配置可以给条件候选，不能给无条件目标命中。

## 2. JS 发现与拉取

| ID / 级别 | 卡在哪里、会造成什么错误 | 第一版处理 | 处理不了时输出 / 所需材料 | 怎样验收 |
|---|---|---|---|---|
| J01 / P0 | 前端入口不明；vendor、压缩包或组件脚本被默认排除，遗漏实际发送代码 | 登记文件/入口和实际支持的 JS 语法；已有 HTML/配置只辅助定位，组件只取支持的脚本部分 | 未支持文件/入口及影响；前端补入口与已有产物，不自动运行构建 | 带请求的 vendor/压缩 JS 不因目录名被跳过；解析失败有文件清单 |
| J02 / P0 | Host 在 A，发送实现在 A 引用的 B.js；只围绕含 Host 的文件拉取会漏 B | 独立发现 JS 引用关系，再按地址和发送点联合定位；获取范围与目标请求 Host 分开 | 未取得引用边、加载位置与深度；前端补脚本定位线索 | 目标 Host 为 api.example.com，JS 来自 cdn.example.net，仍能取得授权引用 JS |
| J03 / P0 | bare import、alias、重导出、external/global 找不到具体 JS；误把包主页或 .d.ts 当实现 | 利用已有解析/锁文件配置定位具体前端 JS；不安装整包、不克隆依赖仓 | `unresolved_module` + 引用表达式/位置；补对应版本的 JS 文件或映射 | 给 JS/只给声明/不给实现三种输入，结果正确区分 |
| J04 / P0 | 三层含义、循环、同 URL 多版本、先深后浅访问处理错误 | 本仓已有 JS 为 0，外部引用每跳 +1；最短深度展开、循环去重，内容身份单独保留 | `depth_limit`、父引用链和未取得位置；不得当分析完成 | 0/1/3 边界；A→B→A 停止；同 D 先深后浅发现仍按合法深度展开 |
| J05 / P0 | 下载失败、登录页、错误 HTML 或截断文件被当 JS；无限重试 | 核响应/最终地址/内容与解析状态，有界重试，保存失败原因；不凭 .js 后缀确认成功 | `fetch_failed` / `invalid_js_content`；所缺文件、授权或可读副本 | 模拟超时、403、200 登录页、截断内容，均不标完整 JS |
| J06 / P0 | JS 中任意 URL 被自动访问、引入凭据泄露或下载失控 | 只跟 JS 引用，限定允许访问范围；重定向每跳复核，凭据不跨目的地复用；限制数量/体积/耗时 | `fetch_scope_blocked` / `resource_limit` 与引用；待确认允许来源或离线 JS | 数据 API/图片不当 JS 拉；越界重定向拒绝；超限停止并出清单，未知代码不执行 |
| J07 / P1 | 动态 script/import、chunk、微前端和标签配置决定实际脚本；地址静态不可解 | 保留构造表达式/有限候选，读取已有配置清单；可用黑盒脚本线索补具体 JS | `dynamic_js_reference`，缺表达式取值/配置快照；不自动拉整站 | 固定地址能展开；动态地址未确定时保留加载点，不能写“无依赖” |
| J08 / P0 | 拉到当前 CDN 内容，却用旧 commit/map 对应调用栈 | 保存根仓 commit、脚本最终 URL/内容哈希、获取时间、配置；无发布对应时分别调查 | `version_unaligned`；前端/发布补对应 JS 与 map | 同 URL 内容变化不覆盖旧证据；错版 map 不生成确定源码行号 |

## 3. Host 与接口定位

| ID / 级别 | 卡在哪里、会造成什么错误 | 第一版处理 | 处理不了时输出 / 所需材料 | 怎样验收 |
|---|---|---|---|---|
| H01 / P0 | 用字符串包含误命中相似域名、注释或 query 中的 URL | 按发送 API 的目的 URL 解析 hostname；大小写等规范化按 URL 规则处理，默认精确匹配 | 解析失败保留原表达式；不从普通字符串生成确认接口 | api.example.com 命中；api.example.com.evil.test、仅 query 值含目标不命中 |
| H02 / P0 | 相对路径、baseURL、绝对地址覆盖、协议相对 URL 被机械拼错 | 按具体请求 API/实例语义组合；保存协议、端口和基址依据；Host 输入默认不按端口筛选 | `host_unknown`；缺页面/请求实例基址或封装模型 | 完整 URL、baseURL+相对路径、绝对 URL 覆盖 baseURL 分别给预期 |
| H03 / P0 | 环境变量、租户/区域开关和远程配置决定 Host，混分支造成假路径 | 有限候选按联合条件拆分，追最终改写；未知配置与目标命中分开记录 | `host_conditional` / `host_unknown`；前端/发布补具体环境配置 | US 与其他区域分支不互拼；候选 Host 命中不升级成当前运行事实 |
| H04 / P0 | 只搜 fetch 漏封装、别名调用、默认实例和 SDK 发送 | 枚举发送原语和封装引用；给公共机制记录地址/方法/参数入口及副作用，再反查调用点 | `unmodeled_sender`，已知调用点及缺失模型/实现 | 三层函数封装、别名、实例调用可定位；不能辨认的方法不伪装普通无关函数 |
| H05 / P0 | 假设所有接口都是 POST 或按 pathname 去重，丢不同方法和调用条件 | 方法按 API 默认/显式值求解；动态路径保留模板；接口与具体调用实例分开标识 | `method_unknown` / `path_partial`；保留调用与条件，不乱替参数段 | 同路径 GET/POST、不同 body、不同调用条件不错误合并 |
| H06 / P1 | Beacon、像素/资源、表单/导航、WebSocket、iframe/Worker 消息与普通 HTTP 混淆 | 登记载体支持清单；能识别的目的地址继续匹配；消息继续追 JS 接收端网络发送，WS 连接和消息分开 | `unsupported_carrier` / `message_boundary`；已知目标/输入照常输出，未知部分留账 | 非 fetch 发送点不会消失；postMessage 本身不当网络出境；WS 消息不冒充 HTTP body |
| H07 / P1 | JS 发起 Host 与重定向/代理后的实际目的地不同，仅搜源码 Host 会漏最终去向 | 主表标“JS 发起地址”；可见 JS/SW 改写继续分析，运行重定向由既有黑盒对账；其他系统转发仅交接 | `runtime_destination_unknown`；需实际重定向或接收部署资料，不能凭初始 Host 确认最终国家 | 初始 A 重定向 B 时不捏造源码直接调用 B，也不把 A 当最终落地证明 |

## 4. 参数提取与代码语义

| ID / 级别 | 卡在哪里、会造成什么错误 | 第一版处理 | 处理不了时输出 / 所需材料 | 怎样验收 |
|---|---|---|---|---|
| P01 / P0 | 对象整体透传、动态键、spread/assign、嵌套数组无法展开，误写无参数 | 逐属性展开已知部分，动态部分记录表达式和来源；数组用 `items[*].id` 等路径表达 | `params_partial` / `params_unknown` + 未展开对象；补 schema 或真实请求结构 | `{...context, user:{email}}` 保留已知字段和未知 context，不以空表通过 |
| P02 / P0 | 跨文件、闭包、回调、this/别名和对象原地修改，错误拼接同名变量 | 跟踪实际绑定、调用点、对象属性及副作用；无法确认的边留候选，不凭函数/参数名连接 | `flow_unresolved` + 断点位置/候选；补实现或专项模型 | 同名不同对象不误连；回调/原地修改有正例，无法支持时明确断点 |
| P03 / P0 | 默认头、公共上下文、拦截器/SDK 自动注入漏掉，安装顺序影响生效 | 参数从业务构造追到发送前改写；机制模型记录安装/匹配条件和写入/覆盖 | `mutation_order_unknown` / `sdk_impl_missing`；需初始化顺序或 SDK JS | 业务参数、追加 pageUrl、风险头分别归因；排除接口和安装前请求不乱加字段 |
| P04 / P0 | 最后覆盖/删除、toJSON/replacer、条件过滤未处理，误报最终发送 | 核序列化和最后有效写入；字段状态区分可能保留、条件保留、已过滤、未知 | `serialization_unknown`；保留对象与最终载荷的缺失关系，不声称原值发送 | 添加后删除、覆盖、条件过滤有反例；已过滤字段不列为确定发送 |
| P05 / P0 | URLSearchParams、FormData、重复键、手工拼 query、文本/二进制被强当 JSON | 按构造方式提取已知字段与表示类型；保留重复键和有序内容；未知格式不强解 | `payload_opaque` / `payload_partial`；补 JS 构造实现或对应格式/schema | 同名多值、数组、multipart 字段保留；二进制未知不伪造键值 |
| P06 / P1 | 定时器、队列引用/副本、账号切换、重试导致采集值与发送时值不同 | 标入队/存储/消费与发送阶段，核 JS 侧身份绑定和重试再注入 | `temporal_flow_unknown`；需队列实现、动作顺序或黑盒定向观察 | A 入队→退出→B 登录→flush 的字段归属不靠当前账号猜；旧副本有记录 |
| P07 / P1 | Cookie/Referer 等浏览器自动带出，JS 没读取却被漏报或虚构读取链 | 区分 JS 构造字段与浏览器可能附带字段；核 JS 凭证/策略配置和黑盒结果 | `browser_added_unverified`；缺运行 Cookie/策略时仅说明候选，不捞真实凭据 | 自动字段与业务参数分开；无源码读取动作时不生成假的来源位置 |
| P08 / P1 | 混淆、eval/Function、Proxy、WASM 调用等无法可靠还原 | 对可见 JS 记录输入、输出和发送边界；格式化辅助阅读，不把生成文本当恢复语义 | `opaque_implementation`；需可读 JS/厂商说明/运行观察；不拉非 JS 实现 | 可见接口仍可输出，隐藏字段关系明确未知；不承诺全反混淆或解密 |

## 5. 含义、敏感性与结果可信度

| ID / 级别 | 卡在哪里、会造成什么错误 | 第一版处理 | 处理不了时输出 / 所需材料 | 怎样验收 |
|---|---|---|---|---|
| S01 / P0 | id/data/payload 等名称歧义，AI 编造业务含义 | 结合写入来源、业务类型/注释/资料给含义，每项附引用；名称推测单独标记 | `meaning_unknown` / `meaning_inferred`；业务解释或字段字典 | 名称相同但来源不同不强行同义；能正确返回未知 |
| S02 / P0 | 敏感名单漏自由文本/标识组合，或把所有 token 判定敏感原值 | 按来源/用途标敏感性线索；原值、派生和只影响分支的控制信息分开 | `sensitivity_unknown`；需用途、关联能力与字段语义，不以未知填“不敏感” | 敏感值藏在普通 data 中仍有线索；哈希/token 不被自动判匿名或可恢复 |
| S03 / P0 | 参数不完整却显示“未发现敏感参数”，造成假阴性 | 完整性、语义状态、敏感性分别维护；部分提取只对已知字段给结论 | 未知字段/实现对结论的影响；不得给整接口安全通过 | body 缺失或不透明时，报告同时显示已知字段和未完成状态 |
| S04 / P0 | 源码、黑盒不同版本；仅发送栈被当全部字段写入栈 | 组合脚本身份、接口/方法、字段变换和条件匹配；发送者与写入者分开 | `observation_unmatched`；需对应 JS/版本或原始请求引用 | 同 /collect 不同事件不混；旧栈不覆盖新代码事实，黑盒缺栈仍保留参数线索 |
| S05 / P0 | 一接口一行挤掉差异；脱敏后不同值被误归并；CSV 泄露原值 | 一参数一行，保留调用实例和参数分支；只输出安全表达式/脱敏值，保护 URL 中的秘密与公式字符 | 主表可筛接口、参数、状态并回查引用；未知与“确认无参数”分开 | 一接口两调用参数不同均保留；凭据原值不入普通报告/Git；导出不触发公式 |
| S06 / P0 | 用接收 Host/IP 或一条参数直接认定国家、违法或保证合规 | 技术表只提供代码/参数/目的地址事实；国家、主体、交易等事实标交接 | `destination_context_needed`；组织/合规补部署、接收方及适用条件，扫描器不扩扫其他代码 | 测试报告不出现仅凭域名推国家、仅凭 token 宣称 EO 违规的结论 |

## 6. 大仓执行与第一版做不到的部分

| ID / 级别 | 卡点 | 第一版出口与验收 |
|---|---|---|
| E01 / P0 | 分析路径爆炸、巨大 bundle、循环展开、远程获取失控 | 获取与分析各设预算；公共机制复用模型；资源/时间耗尽保存已得结果与断点。验收：大文件/循环/限额任务可结束，报告有未完成范围，不能算完整零命中 |
| E02 / P0 | Agent 幻觉、无限搜索、引用过期、同一推断反复自证 | 固定文件身份、问题和预算；摘要需正反例；无证据返回未知。验收：引用不存在/错版本被拒；模型异常不丢已提取字段，人工基线独立给预期 |
| E03 / P0 | “不限制函数层数”被实现成无限计算 | 不用外部 JS 深度截断本仓调用，但可按资源预算停止；停止位置和影响路径必须显示。验收：四层本仓封装不会因 max_js_fetch_depth=3 被截断 |

第一版不承诺解决：任意混淆/动态程序完整语义、缺失 JS 内部实现、不透明密文还原、任意运行配置的实际取值、其他系统转发与完整 EO 适用。不是只写一句“不支持”：上述情况必须关联具体接口/参数，列缺什么、谁提供、补齐后重做哪一步。

## 7. 一个未决项到底怎样落表

### 7.1 必填字段

`issue_id / 类型 / 根仓commit与JS身份 / 触发位置 / 引用链或调用点 / 关联接口与参数 / 已知事实 / 缺失边或材料 / 影响结论 / 下一动作与接手角色 / 状态 / 重试或重验条件`。

状态：待验证、已定位、待材料、待实现能力、待复核、已关闭。当前台账均为设计项，尚无真实业务项可关闭。新证据、配置或 JS 版本改变时重开对应项，不能只改总结文字。

### 7.2 假设案例：主接口已找到，字段仍未追全

| 项目 | 假设记录，不是实测 |
|---|---|
| 已知 | 本仓 main.js 引用 a.js；a.js 引用 b.js；b.js 引用 c.js；c.js 调用未取得的 d.js 创建风险对象，再与 orderId 一起发送；目标 Host 在 c.js 可确定 |
| 限制 | c.js 是第 3 层，d.js 超深度；另有业务字段 body.orderId 能追到 |
| 主表 | 保留接口与 orderId；风险对象若字段名可见照常列，否则加“字段未展开”记录；参数完整性为 partial |
| 未决 | ISSUE-01，关联 J04/P01，列 d.js 引用位置与完整引用链，影响为风险字段及含义未知 |
| 下一步 | 范围获准后提高 JS 深度或提供对应 JS 副本；只有文件取得还不够，须重跑依赖它的参数追踪 |
| 不允许的结果 | 因缺 d.js 得出“接口只传 orderId”“没有敏感参数”或“审计通过” |

若 Host 本身也在 d.js 中未知，主表不能把它写成目标 Host 已命中；放入待核实发送候选，仍通过 issue_id 关联。零命中必须附这些未决发送点和资产缺口。

## 8. 落地顺序与关卡

| 阶段 | 要完成什么 | 进入下一阶段的凭据 |
|---|---|---|
| G0：材料与定义 | 选试点 Host/仓/commit；确认 JS 可取得范围、来源授权、解析支持、参数分类和脱敏口径 | 一条可人工说明的目标请求及其 JS；材料缺失单独登记，不假设已齐 |
| G1：取得与 Host 定位 | 实现 J/H 的最小路径，输出发送点、Host 判断与资产/未决清单 | 直接 URL、封装/配置及误命中反例通过；3 层和失败状态可核对 |
| G2：字段与含义 | query/header/body/path、公共封装/注入、含义/敏感性依据；主表贯通 | 对象合并、覆盖/过滤与未知字段测试；能解释一条黑盒请求，不足项明确 |
| G3：可交付性 | 候选/未决导出、预算停止、去重/版本、引用复核和增量重验 | 主表及未决可回查；无敏感原值泄露；实测报告列支持/缺口，而非只有命中数 |

**没有试点材料也能继续定义接口与样例；不能据纸面设计宣称已具备扫描效果。** 暂不承诺工期或准确率，G0/G1 结果决定工具、模型成本和范围取舍。
