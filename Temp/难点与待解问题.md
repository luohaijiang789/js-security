# 白盒技术问题：按分析过程记录

**适用范围：早期 M1～M5 技术探索，不做敏感性判断。** 当前开发边界以[提取器需求](../frontend-api-extractor/docs/requirements.md)和[开发计划](../frontend-api-extractor/docs/roadmap.md)为准，下文不代表当前实现。

**先列漏点，再比较解决办法。** 表内方法均为候选，未验证可达到的准确性；它们是开发需要研究的问题，不是已有扫描结果。

## 1. 请求地址还原：不能只找 URL 字面量

| 来源/形式 | 为什么会漏或误判 | 可以尝试的方法 | 仍待解决 |
|---|---|---|---|
| 配置文件、环境变量、构建替换 | JS 中没有完整 Host；不同环境取值不同 | 联查已有配置与变量引用；AST/CodeQL 追到 URL 使用点；AI 辅助理解配置约定 | 哪份配置对应美国部署？缺发布值时只能给条件候选 |
| 字符串拼接、模板、协议/子域拆分 | 完整域名根本没有连续出现 | 常量/表达式分析，或 AI 还原候选后用代码验证 | 非常量片段与自定义转换能支持到什么程度？ |
| baseURL、请求实例、公共封装 | Host、路径和最终调用分散在文件/对象中 | 模块/调用与属性关系，CodeQL 数据流或 AST 定向追踪，实例模型 | 如何防止把 A 实例的 Host 配给 B 的参数？ |
| Host 从函数参数传入 | 搜发送函数只有 url 变量，搜调用者又看不到发送 | 从发送点反查调用者，并从地址来源正向追用途 | 工厂、闭包、回调和动态方法调用怎么接？ |
| 当前页面域名、相对 URL | 源码只有 `/api/...`，页面运行地址不在仓内 | 解析已知基址/请求实例，结合已有页面配置或黑盒请求 | 缺少页面基址时保留相对路径 |
| 远程配置、接口响应决定地址 | 再完整的静态源码也可能没有实际值 | 保留配置读取链；接入已有配置快照/黑盒实例辅助 | 快照仅覆盖该时间/场景；无法凭源码穷尽未来值 |
| 区域/租户/角色/开关分支 | 全部 Host 混在一起，或只查某分支 | 路径条件、有限候选及配置约束；人工/AI 审查分歧 | 避免把分支 A 的 Host 与分支 B 的数据拼接 |
| 发送前改写、拦截器、SDK 注入 | 初始 URL 不是最后请求 URL | 追最后写入与包装顺序；补请求库/SDK 模型；黑盒对账 | 动态安装与全局包装的生效顺序可能无法静态确定 |
| 外部 JS、懒加载、构建后模块 | 本仓没有发送实现，取到 JS 也未必连得上模块 | 按入口取引用 JS（白盒一层、网站三层），用可取得构建映射/脚本地址补充 | 深度外 JS、未取得实现、混淆和构建运行时适配 |
| 相似域名、注释、参数里嵌 URL | 文本命中很多，但不是真正的发送 Host | 识别发送目标表达式，按 URL 的 hostname 比较 | 解析失败不能强匹配；运行重定向与 JS 发起地址分开 |

**待比较的不是“谁搜域名更快”，而是谁能把地址来源连接到真实发送点，同时少漏、少错连。** 所有路线都要用不含完整 Host 字面量的样例验证。

## 2. 参数提取：动态有不同层次

| 形式 | 能先知道什么 | 难点 | 可以尝试的方法 |
|---|---|---|---|
| `{uid: account.id}` | 字段 uid 和来源表达式 | 实际值、构造来源不一定已知 | 先提结构，进一步按需追来源；不能因值未知而漏字段 |
| `{...context, ...payload}` | 对象来自哪里，部分已知属性 | 完整字段集合、先后覆盖 | 属性/别名分析、schema 或黑盒结构补充；未知 spread 不能当空对象 |
| `[fieldName]: value` | 动态键和值表达式 | 键可能是有限候选，也可能纯运行时 | 常量/条件求值、数据流与运行观察；不猜固定字段名 |
| 跨函数、跨模块传参 | 参数传递点 | 调用目标、实参/形参、返回值、闭包和对象副作用 | CodeQL 路径/库摘要、AST 定向追踪、AI 提模型；需用同名不同对象反例核对 |
| header/default context/SDK 追加 | 业务参数以外还有写入 | 字段写入者不在发送调用栈，或运行时才安装 | 查全局包装/拦截器、实例配置与写入顺序；黑盒反查新增字段 |
| delete/覆盖/条件过滤 | 构造过字段，不代表最终保留 | 最后有效写入、条件、序列化影响 | 对象状态与路径检查；区分确定保留、条件保留和已过滤 |
| 数组/批量事件/循环构造 | 元素结构或部分事件 | 不同事件形状、动态数量和动态键 | 提字段 schema/通配路径，保留事件差异；不强求枚举实际值 |
| JSON/FormData/query/二进制 | 不同载荷构造方式 | 自定义序列化、重复键、toJSON/replacer、格式未知 | 按构造方式建模型；缺模型时保留输入与未解析部分，不强转 JSON |
| 哈希/加密/token | 输入输出调用和可能关联 | 无法直接恢复发送载荷的内部字段 | 查可见 JS 输入/用途，保留不透明变换与运行证据；AI 不猜密文内容 |
| 队列、异步、重试、账号切换 | 多阶段生产与发送 | 保存引用还是副本、发送时身份、重复注入 | 时序/生产消费关系与定向黑盒场景；不能只看当前变量值 |

还要区分：**字段结构是否完整、构造关系是否追清、地址是否确定。** 三者不能合成一个“提取成功”。构造关系追不完，不必丢掉已知参数；结构没展开，不能标记提取完整。

## 3. 每条技术路线都必须回答的问题

- [ ] **检索召回**：若 Host 在配置、发送在外部 JS，候选收集是否仍能把两边找齐？没有命中的代码是否直接被跳过？
- [ ] **关系准确性**：同名变量、实例、分支、调用者是否误连？有什么可复现反例？
- [ ] **动态边界**：是真正缺运行值，还是分析器没处理常量/引用？两类问题能否区分？
- [ ] **扩展成本**：新增一种请求封装，需要规则、查询、库摘要还是 Agent 阅读？能否跨调用者复用？
- [ ] **执行成本**：整仓分析、定向切片、按需 AI 各要多少机器/模型/人工时间？缓存什么，版本变化后重做什么？
- [ ] **验证方法**：用固定代码和黑盒实例分别能证明什么？有没有独立预期，而不是工具给自己评分？

先保留这些问题，按[路线比较](白盒思路.md)和[Checklist](../docs/验证计划.md)逐项验证，不用“采用某工具”替代答案。
