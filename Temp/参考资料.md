# 参考资料：围绕具体白盒难点收集

> 核查：2026-10-21。已读下列官方文档、指定源码片段及论文相关章节；未安装、运行或评测工具。这里不保存大段转载和待执行代码。

当前仅为 M1～M5 请求与参数提取提供选型参考；文中更深的数据流能力不是首版全部实现要求。

## 已读资料与取舍

| 编号 | 一手资料 | 核实到的内容 | 对本项目的用途与限制 |
|---|---|---|---|
| R01 | CodeQL：[概览/建库](https://codeql.github.com/docs/codeql-overview/about-codeql/)、[数据流](https://codeql.github.com/docs/codeql-language-guides/analyzing-data-flow-in-javascript-and-typescript/)、[库模型](https://codeql.github.com/docs/codeql-language-guides/customizing-library-models-for-javascript/) | 抽取源码关系建分析数据库，再执行查询；有局部/全局数据流与库模型；扩展 API 标为 beta | 候选：跨函数字段追踪与 SDK 摘要。需比较建库、查询和适配成本；默认漏洞规则不等于本项目透传提取，仍需自定义模型与输出 |
| R02 | Semgrep：[taint 文档](https://docs.semgrep.dev/writing-rules/data-flow/taint-mode/overview)、[项目 README](https://github.com/semgrep/semgrep/blob/fe209763a4a2ccfcdf6434e6c332edc24a2f586e/README.md) | 文档区分函数内 propagator、Pro 跨函数及跨文件模式 | 候选：入口、封装和局部模式定位；部署/授权与实际启用模式需核对，不能把社区版默认能力写成跨文件追踪 |
| R03 | [Babel parser](https://babeljs.io/docs/babel-parser) | 支持 JSX/TS 等解析选项，errorRecovery 仍可能遇不可恢复错误 | 候选：可重复提取语法与位置。解析成功不等于调用或字段流已解决；必须记录失败文件 |
| R04 | [TypeScript 模块参考](https://www.typescriptlang.org/docs/handbook/modules/reference.html#paths) | `paths` 影响类型侧模块解析，但不改写输出 import 路径 | 分析器需对照构建/运行解析，不能把类型解析结果直接当已运行实现 |
| R05 | webpack：[动态依赖](https://webpack.js.org/guides/dependency-management/)、[externals](https://webpack.js.org/configuration/externals/)、[Module Federation](https://webpack.js.org/concepts/module-federation/) | 动态表达式可形成 context 候选；依赖可不进 bundle；远程模块可在运行时加载 | 资产发现需查构建配置、chunk、全局映射与远程入口；“源码扫描完”不能自动等于运行代码全覆盖。只对实际采用的构建方式应用这些规则 |
| R06 | [ECMA-426 source map 规范](https://tc39.es/ecma426/) | 定义生成位置到源位置映射；sourcesContent 可省略或含 null，ignoreList 可标第三方代码 | 借 map 回查 bundle 栈位置；map 不保证含源码，也不替代产物版本匹配。第三方被调试工具忽略，不代表审计可跳过 |
| R07 | [SemTaint 论文 v1](https://arxiv.org/html/2601.10865v1) | 研究用 LLM 辅助来源/发送相关规范、调用边和函数摘要；有效性限制提到部分回调传播与前置流缺口 | 借鉴“针对未解决边补模型”，不照搬漏洞检测真值和效果。只读了概览、方法、限制及工具接口相关段落，未复现论文结果 |

以上“用途”是本项目的设计判断，不表示作者承诺支持我们的 SDK、浏览器透传或跨境判断。无工具能够凭接收 URL 独自确认全部国家/主体/后端转发事实。
