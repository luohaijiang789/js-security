## 目前最重要的三个判断

1. **先确定运行代码的边界。** 仓库、依赖、构建产物和远程脚本可能不一致；缺失代码必须显式留账。
2. **调用关系不等于字段流。** 找到请求函数后，还要查对象、字段、注入、覆盖、序列化与发送条件。
3. **插件与静态分析可以互补。** 插件仍待开发；后续用实际接口/参数/调用栈反查，静态新路径可供插件定向验证。

第一阶段已冻结为[前端 API 与请求参数提取 M1～M5](../docs/前端代码仓JS请求API采集.md)，不按 Host 筛选，不做敏感性或合规判断：只查前端 JS，白盒只向外获取一层引用 JS，网站 JS 收集另按最多三层；不拉其他代码或整个依赖仓。这里保留研究思路，执行以[项目原则](../AGENTS.md)和正式方案为准。

最终目标与 Excel 列见[总方案](../docs/API资产收集总方案.md)。新增[网站 JS 收集入口](../docs/网站%20JS%20收集与静态分析.md)与待开发的浏览器插件互补；研究必须说明能补哪些 API/参数，不能仅罗列工具名字。
