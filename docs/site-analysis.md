# 网站 JS 收集与静态分析

**输入网站入口及访问范围，取得可发现的部署 JS，分析其中的请求与参数候选。** 当前先用 Burp + 被动 JS 提取和 Yakit 平台做采集试点，再比较 URLFinder 的资源发现及 jshound 等字段恢复；三层父链和证据模型按差距适配。结果标记为“网站 JS 静态”，不表示请求已发生。

## 1. 输入与流程

输入包括入口 URL、允许访问的页面范围、脚本允许获取来源；需要登录时提供可用会话。页面范围、脚本来源和结果中的请求 Host 分开管理：允许获取某 CDN 的引用文件，不代表遍历整个 CDN；发现外部请求 Host 仍需记录。

```mermaid
flowchart LR
    P["网站入口、范围、会话"] --> S["发现页面脚本、chunk 和 SDK"]
    S --> F["获取最多三层引用，记录版本与缺口"]
    F --> C["适配打包模块、页面基址及可用运行配置"]
    C --> A["请求发现、地址还原、参数提取"]
    A --> X["统一模型：网站 JS 静态候选"]
```

页面访问可能自然触发业务请求，但脚本收集流程本身不等于完整请求采集；需要实际请求证据时使用插件并单独标记。

## 2. 脚本收集

| 场景 | 做法 | 主要缺口 |
|---|---|---|
| 内联脚本、script src/module | 保存页面、基址、URL/内容、位置及哈希 | 页面注入配置可能不在脚本文件内 |
| import、动态 import、脚本注入 | 静态解析可确定目标，结合加载记录获取 | 完全动态地址保留表达式 |
| 懒加载 chunk、微前端 | 解析可用清单、构建映射及加载关系 | 未知运行时需适配，不能保证枚举全部 chunk |
| SDK、Worker、iframe | 记录依赖和执行上下文；iframe 作为页面发现其脚本 | 跨上下文与父链可能不可取得 |
| source map | 同版可用时辅助模块恢复和源码定位 | 不保证含源码，不证明代码运行过 |

网站模式 `max_js_fetch_depth = 3`：页面内联代码为第 0 层，直接外链脚本为第 1 层，再取其第 2、3 层引用。页面访问深度独立配置。已知父脚本的子文件不能因出现在浏览器加载列表中就自动算第一层。

同文件按最短已知引用路径计算；父链未知标深度未知；循环、超深度、失败、截断及不同内容版本均保留记录。

网页资源地址按页面实际基址解析；模块相对 import 按模块 URL 解析；相对 fetch 按执行上下文的请求规则处理，不能拼到脚本 CDN 目录。Worker 等上下文需要单独建模。

仅访问收集页面和脚本所需资源，不主动请求提取出的 API，不自动提交表单、爆破参数或扫描漏洞。候选爬虫接入前核对默认行为。

## 3. 部署代码分析

分析阶段对应 M2 请求发现、M3 地址提取、M4 参数提取，但需要网站专用适配，不假设下载后可直接套用源码分析器。

| 步骤 | 开发内容 | 边界 |
|---|---|---|
| 上下文准备 | 识别可支持的打包模块、chunk 关系、页面配置和执行上下文 | 未支持的构建运行时记录缺口 |
| M2 请求发现 | 在压缩/打包代码中识别发送机制、实例、包装函数及 SDK | 名称变化、混淆和缺模块可能阻断关联 |
| M3 地址提取 | 解析常量、拼接、已替换配置、基址和可取得运行配置 | 部署代码仍可能依赖远程配置，不猜动态 Host |
| M4 参数提取 | 提取对象、传参、默认项、改写和序列化后的候选字段 | 压缩代码不一定可还原业务语义或完整字段 |

可复用候选包括请求机制模型、表达式和对象字段分析；源码模块绑定、打包模块适配及配置上下文分别处理。具体共享范围由[源码/产物对照验证](validation.md)决定。

## 4. 输出与互补

每条候选保留脚本 URL/哈希、引用链、页面上下文、调用/发送位置和未知项。已收集但未执行分支中的请求也可提取，仍标静态候选；未登录、未加载或解析失败不能解释为没有请求。

静态发现的路径可供插件定向触发；插件发现的漏项可反查漏收脚本、动态构造或不支持模型。仅 URL 相同不足以匹配仓库 Commit 或定位唯一源码调用。输出遵循[统一交付约定](delivery.md)。

首轮默认 Burp + JS Miner/BurpAPIFinder 被动提取，Yakit 为平台对照；API Sword、URLFinder 单独检查主动访问；jshound/Vespasian 等补结构或作为管线对照。能力、主动行为和固定版本见[传统前端工具链评估](../references/传统前端信息收集工具链评估.md)及[网站 JS 工具评估](../references/网站JS收集工具评估.md)。

对于“打开已登录网站，一边捕获请求、一边分析 JS”的使用方式，直接使用上述代理与响应分析工作流。EASYapi、ExecEndpoints 等保留补充评估；结构分析可采用含正文 HAR → jshound 离线目录。详细步骤和 jshound 导出缺口见[浏览器联合采集评估](../references/网站浏览器挂载与动静态联合采集评估.md)。同一个工具产生的实际请求与静态候选仍分别标来源。
