# 白盒开发与验证 Checklist

**当前未实现扫描器，技术路线和覆盖率均未验证。** 下列任务按准备、选型、开发、验收推进；勾选须有对应材料或验证结果。

## 0. 先准备什么

- [ ] 固定一个试点仓版本及目标 Host，确认精确匹配还是包含子域。
- [ ] 收集美国发布配置、页面基址和构建版本；缺失项注明影响哪些判断。
- [ ] 确认仓内公共请求封装与主要 SDK，取得可用实现或同版 JS 制品。
- [ ] 准备代表性黑盒记录：页面、接口、参数、调用栈及采集状态；版本线索有则附带。
- [ ] 确定外部 JS 可获取来源；深度默认 3，不以此限制函数追踪。
- [ ] 确定 AI 可读取及可向模型服务发送的代码范围。

## 1. 分析过程必须回答什么

- [ ] **JS 范围**：本仓及三层引用 JS 能否取得、关联？动态加载/缺实现在哪里断？
- [ ] **发送点**：直接 API、封装、实例和 SDK 能识别哪些？只搜 fetch 会漏什么？
- [ ] **Host**：配置、拼接、基址、函数传入、分支、运行值、最后改写分别怎么查？
- [ ] **参数**：已知字段、动态键、整体对象、自动注入分别能提到什么程度？
- [ ] **路径校验**：是否核对象身份、调用上下文、覆盖/过滤及条件，避免错误拼链？
- [ ] **含义/敏感性**：哪些有来源/资料支持，哪些只是名称推测，哪些仍未知？
- [ ] **结果**：接口/参数能否回查代码与未解表达式，并用既有黑盒请求核对？

## 2. 三条路线使用同一批比较题

分别记录 A（Grep+AI）、B（AST+定向分析）、C（CodeQL 查询）的结果，必要时再试组合 D。每题的调用、字段和条件由人工独立标注；需要运行值才能确定的题，预期允许正确返回未知。

| 题组 | 要放进的代码形式 | 比较重点 |
|---|---|---|
| T01 Host 基础 | 完整 URL、相似域名、注释/query 中的域名 | 正确识别发送目标而不是文本命中 |
| T02 Host 间接 | 已有配置、环境常量、拼接、baseURL、跨文件传入 | 不含完整 Host 字符串时能否找回接口与依据 |
| T03 Host 动态 | 区域分支、远程配置、相对地址缺基址、发送前改写 | 条件关联是否正确；能否区别未求值与材料不存在 |
| T04 参数结构 | 静态字段动态值、spread/assign、动态键、数组与未知对象 | 提对已知字段，保留未知部分与覆盖顺序 |
| T05 跨函数关系 | 导入别名、重导出、闭包/回调、同名不同对象、请求实例 | 数据传递和来源能否追对，需要多少自定义模型 |
| T06 最终载荷 | 默认头/SDK 注入、删除/覆盖、序列化、token/二进制 | 构造字段与最终发送候选是否区分，是否漏后续写入 |
| T07 JS 与运行边界 | 三层引用、动态 JS、混淆/模块运行时、错版脚本、旧队列 | 取得 JS 后能分析多少；哪些必须结合黑盒或材料 |
| T08 真实请求 | 已有黑盒接口/参数/栈，以及独立白盒新候选 | 能否解释实际请求并补新路径，不能只选简单命中样本 |

## 3. 每条路线记录同样的结果

| 比较项 | 需要记录 |
|---|---|
| Host/接口 | 人工真值中找回/漏掉多少，输出中正确/错误多少，未知哪些 |
| 参数 | 按调用点+载体+字段路径核对：提对、漏字段、虚构字段、来源错连、结构未展开 |
| 语义 | 字段含义/敏感标签的依据、推测/未知，人工复核是否一致 |
| 适配量 | 需要写多少规则/查询/摘要/库模型，是否只对该样例有效 |
| 成本 | 初始化、单次分析、增量重跑、AI 调用和人工复核耗时/资源 |
| 可重复性 | 同输入再次运行是否一致，结果引用是否真实且对应同版 JS |

- [ ] 输出一张逐题对比表：A/B/C 各提到什么、漏什么、代价多少；不只统计是否生成报告。
- [ ] 再决定单路线或分阶段组合；组合必须能说明相较单路线新增覆盖与新增成本。
- [ ] 当前所有效果与覆盖率填“未测”；以后报百分比附真值范围、分母和未解项，不外推全仓。

## 4. 选型后逐项开发

- [ ] **JS 获取/模块解析**：同版文件、引用位置、深度、失败原因可追溯；新取得 JS 重新进入完整分析链。
- [ ] **双入口索引**：独立发现 Host 线索和请求候选；不含域名字符串的发送文件仍参与分析。
- [ ] **地址关联**：连接配置、实例、封装与调用；输出确定命中、条件命中、目的地址待定及证据。
- [ ] **参数追踪**：分载体提取字段、来源与变换；未知对象保留缺口，不按空对象处理。
- [ ] **路径校验**：处理已支持的别名、注入、覆盖、删除和序列化；不支持的机制明确返回待定。
- [ ] **语义解释**：规则/AI 判断可回查依据，名称推测与来源事实区分。
- [ ] **黑盒对照/导出**：保留多个候选调用、字段差异和补测条件；输出 CSV、关联 JSON 与摘要。
- [ ] **Agent 补模型（如采用）**：输入具体缺口，输出有位置/条件的候选；通过正反例后才能进入可复用模型。

模块含义与边界以主方案 3.1～3.7 节为准；这里用于检查完成情况，不另外定义一套架构。

## 5. 首轮必须过的反例

- [ ] Host 在 config、发送在 SDK、参数在页面，能连起来；第二个 client 不会串入。
- [ ] 同接口两个调用者的参数和区域条件分别保留，不合成一个请求。
- [ ] `uid` 后面存在未知 spread 时，指出 uid 来源可能被覆盖；字段名已知不等于最终值已知。
- [ ] 对象别名写入、浅拷贝顶层写入、共享嵌套对象写入的结果有区别。
- [ ] 加密前输入可见时保留来源，但不把明文字段写成线上独立参数。
- [ ] 外部 JS 循环引用不重复扩张；更浅路径出现后能重新检查被截断的引用。
- [ ] 动态 Host、获取失败、解析失败、分析预算耗尽分别输出原因，不归为“未发现请求”。
- [ ] 黑盒缺字段或版本未确认时，不据此认定白盒误报；黑盒新字段能反向定位待查机制。

## 6. 覆盖与遗留怎么交付

| 指标 | 分母与边界 | 当前状态 |
|---|---|---|
| JS 获取/解析 | 已发现的唯一资源或文件；深度截断、未知 URL、失败另列 | 未测，不能代表全部运行脚本 |
| 接口召回 | 人工独立标注样本中的真实接口调用上下文 | 未测 |
| 接口准确性 | 输出的已关联接口调用上下文，人工复核正确数 | 未测；待定单列 |
| 字段与来源 | 标注的调用点、载体、字段路径及来源；分开统计提对、漏提、误提与错来源 | 未测；结构未知另列 |
| 黑盒解释情况 | 已采集且进入本次范围的请求样本 | 未测，不能代表未触发页面 |

- [ ] 每个遗留项挂到脚本/调用/字段，写明原因、影响及下一步所需配置、实现或运行证据。
- [ ] 对新增封装和真实样本复验，避免只在用于写规则的样例上验收。
- [ ] 发布实际支持的机制、未支持形式、资源消耗和已知漏点，再决定下一版范围。
