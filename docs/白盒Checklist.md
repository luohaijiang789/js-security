# 白盒 V1：能力、问题、覆盖与遗留 Checklist

> 更新：2026-10-21。范围：一个仓库的前端 JS，按 Host 提取接口/参数/含义/敏感性线索；引用 JS 默认拉取三层，可配置。其他代码不展开。

**当前完成的是方案和问题设计，还没有可运行白盒扫描器，没有目标仓实测，不能报实际覆盖率。** 已有黑盒方案由用户确认有效，但尚未用于本项目的白盒对账试点。

## 2. 当前方案仍有哪些不足

| 不足 | 对落地的影响 | 下一步 / 完成凭据 | 接手角色（待指定） |

| 含义/敏感分类只有原则 | 字段解释、敏感标签与推测可能混淆 | 确定分类口径、引用要求、未知处理和人工复核规则 | 业务、安全/隐私 |
| 预算阈值未校准 | 大仓能否跑完、费用与耗时均未知 | 用实际规模记录数量/体积/耗时/分析预算及停止行为 | 实现、测试 |
| 验收只有分组，没有样例和真值 | 不能量化漏报、误报或比较工具 | 将 V01～V16 做成样例；人工独立标注接口、字段、条件和未知预期 | 测试、复核 |
| 黑白盒尚未做版本对应和往返 | 无法证明表格解释了真实请求 | 留一条完整“观察→源码→新增候选→补测”的引用链 | 白盒、黑盒/测试 |
| 未决状态尚未形成实际记录 | 错误可能只出日志，最终主表看起来完整 | 演示缺 JS/动态 Host/部分 body 均生成 issue_id 并关联主表 | 实现、导出 |

## 4. 第一版计划覆盖到哪里

这是**计划能力分层，全部尚未实测**。P1 深入支持可以后置，但识别并输出未支持/未知边界必须保留。

| 场景 | V1 计划做到 | 可能仍然留下什么 |
|---|---|---|
| 静态完整 URL、常量拼接、已知 baseURL | 确定 Host、方法、路径、调用位置，提取已知字段 | 依赖配置/封装缺失时降为候选 |
| 取得的三层 JS 与本仓跨文件调用 | 解析引用、追字段与公共封装，不以三层截断函数链 | 三层以外引用、模块不明、预算停止 |
| 对象合并、请求头注入、最终过滤 | 追已知属性及最后改写，给正反例 | 动态键、无法确定的别名/顺序/SDK 内部 |
| 动态配置、远程入口、区域/角色分支 | 输出有限候选、条件与缺失材料 | 不能保证覆盖所有运行配置或实际发生 |
| 队列、浏览器自动字段、特殊载体 | 识别可见 JS 边界与输入输出，按能力给结果 | 完整时序、自动 Cookie 值、未知协议字段 |
| 混淆/加密/动态执行/非 JS 实现 | 提取可见接口和输入输出，保留不透明部分 | 不保证全反混淆、解密或恢复隐藏实现 |
| 国家与 EO 适用 | 提供前端字段/接口事实和待补事项 | 地区、主体/交易等需组织及合规复核 |

## 5. 覆盖度怎样计算、现在能报多少

**现在各项实测覆盖均为 N/A（未测），不是 0% 或预估的 80%/90%。** 当前工程验收 0/32、验证分组执行 0/16 只反映进度，不是检测能力。三层只是获取预算，也不是覆盖百分比。

先固定：根仓 commit、Host、JS 来源/深度、运行配置、语法/载体支持、时间/资源预算、人工或受控样例真值及排除理由。以下分开报，不合成一个总“覆盖率”。

| 指标 | 分子 / 分母 | 当前值 | 必须同时披露的限制 |
|---|---|---|---|
| JS 取得率 | 已成功取得的已定位 JS 资产 / 声明范围内已定位 JS 资产 | N/A | 根仓已有与外部拉取分别报；失败/超深度列账；地址未知的引用另报数量，不能宣称资产全集已知 |
| JS 解析成功率 | 无已知解析缺口的文件 / 已取得、纳入分析的 JS 文件 | N/A | 恢复性错误/部分解析单列；文件解析成功不代表数据流正确 |
| Host 判断完备度 | 有依据确定目标命中或排除的调用实例 / 已发现发送调用实例 | N/A | 条件候选、未知另报；分母是已发现集合，不证明发现了全部发送点 |
| 接口查准率 / 召回率 | 正确确认的目标调用实例 / 全部确定命中输出实例；正确找回的可确定目标真值实例 / 基准中可确定目标真值实例 | N/A | 真值须独立标注；未知/条件候选单列并核对是否合理，不能拿输出集合自己当真值 |
| 参数查准率 / 召回率 | 正确输出字段 / 全部输出字段；正确找回字段 / 基准中真实字段 | N/A | 字段单位为“调用实例+载体+字段路径+必要条件”；未知对象不是已找到其全部字段 |
| 参数含义有据率 / 复核正确率 | 有代码/业务依据的解释 / 已提取参数；经独立复核正确的解释 / 已复核解释 | N/A | 名称推测/未知分开；已复核子集不等于所有参数 |
| 敏感字段召回率 | 正确标出的真值敏感字段 / 固定口径下基准敏感字段 | N/A | 同时记录误标与未知；已标字段的比例不等于召回，更不等于法律风险覆盖 |
| 黑盒解释率 | 版本/条件相容且被代码解释的基准请求实例 / 事前固定的基准请求实例 | N/A | 错版/缺材料保留未解释原因；不得只挑已能解释的请求当分母，不外推未触发页面 |

调用实例按 JS 身份、调用位置及必要条件区分；接口模板用于展示归组。脱敏或归并不能抹去真值需要的差异。分母为空/未知报 N/A，并给数量和原因；小样本率必须附样本量和适用范围。

## 6. 遗留问题必须怎样交接

| 遗留类型 | 主表怎样表示 | 补什么、谁接手 | 关闭凭据 |
|---|---|---|---|
| JS 超深度/缺失/无法授权取得 | 关联 issue_id，接口或参数标部分/未知 | 前端/发布/SDK 方给对应 JS，或负责人调整获取范围 | JS 对齐且受影响路径重验；单纯下载成功不算关闭 |
| 动态 Host/运行配置未知 | 候选或未知 Host，不混入确定命中 | 前端/发布补配置或测试补相容运行证据 | 目的地址与条件有依据，修正关联主表 |
| 动态对象/SDK/序列化无法追清 | 已知字段保留，未展开部分单列 | 解析/模型负责人补能力，前端/SDK 方补实现 | 字段写入/过滤有证据，剩余未知明确 |
| 含义/敏感性待确认 | 标推测/未知，不填“不敏感” | 业务补字段用途，安全/隐私复核分类 | 引用及复核结论可回查 |
| 语法/载体/分析预算不支持 | 支持范围、停止点与影响实例单列 | 实现方补支持或调整预算；负责人确认剩余范围 | 对应验证与受影响调用重跑，或明确作为未解决项交付 |
| 实际接收地区/主体和法律适用 | 技术事实与待核实项分开 | 组织/合规提供相应事实，不扩扫其他代码 | 有责任方的事实与适用复核；不能靠主表自动关闭 |

实际遗留项必填：`issue_id、关联问题ID、JS/版本、接口/参数、缺失事实、影响、接手人、下一动作、复核时间、证据、状态`。状态用待材料/待能力/待验证/待复核/已关闭；人员与时间尚未分配时如实待填写，不能默认有人处理。

- [ ] 主表每个部分/未知状态有未决引用；没有接口也能登记未解析 JS 或未知发送点。
- [ ] 取得/模型/配置变更后，能找到需要重跑的接口与参数。
- [ ] 关闭遗留须有证据；“工程正确返回未知”不自动关闭业务问题。
- [ ] 零命中报告仍包含 JS 缺口、未知 Host/参数、支持范围和停止原因。
- [ ] 未解决项有接手人或明确未分配，不在最终汇总中消失。

## 7. 推进 Checklist：按凭据过关

- [ ] **G0 材料**：试点 Host/仓/commit、JS 来源与配置、至少一条人工可解释请求到位；选型待试点结果决定。

- [ ] **G3 交付**：导出、预算、错引、版本与重验可用；交主表、覆盖统计、验收结果和遗留清单。
- [ ] 将[问题台账 V01～V16](../Temp/难点与待解问题.md)转成可执行样例和独立标注，逐组记录通过/失败/未执行。
- [ ] 基于实测决定是否扩展语法/载体、提高 JS 深度或补模型；对外报效果时附分母、样本量、未测范围及遗留。
