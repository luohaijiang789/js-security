# 白盒技术方案比较 Checklist

**先验证分析能力，再决定开发路线。** 当前未实现扫描器；下列是待执行的比较任务，不是已完成能力或实测覆盖。

## 1. 分析过程必须回答什么

- [ ] **JS 范围**：本仓及三层引用 JS 能否取得、关联？动态加载/缺实现在哪里断？
- [ ] **发送点**：直接 API、封装、实例和 SDK 能识别哪些？只搜 fetch 会漏什么？
- [ ] **Host**：配置、拼接、基址、函数传入、分支、运行值、最后改写分别怎么查？
- [ ] **参数**：已知字段、动态键、整体对象、自动注入分别能提到什么程度？
- [ ] **路径校验**：是否核对象身份、调用上下文、覆盖/过滤及条件，避免错误拼链？
- [ ] **含义/敏感性**：哪些有来源/资料支持，哪些只是名称推测，哪些仍未知？
- [ ] **结果**：接口/参数能否回查代码与未解表达式，并用既有黑盒请求核对？

## 2. 三条路线使用同一批比较题

分别记录 A（Grep+AI）、B（AST+定向分析）、C（CodeQL 查询）的结果，必要时再试组合 D。每题的调用、字段和条件由人工独立标注；需要运行值才能确定的题，预期允许正确返回未知。

| 题组 | 要放进的代码形式 | 比较重点 |
|---|---|---|
| T01 Host 基础 | 完整 URL、相似域名、注释/query 中的域名 | 正确识别发送目标而不是文本命中 |
| T02 Host 间接 | 已有配置、环境常量、拼接、baseURL、跨文件传入 | 不含完整 Host 字符串时能否找回接口与依据 |
| T03 Host 动态 | 区域分支、远程配置、相对地址缺基址、发送前改写 | 条件关联是否正确；能否区别未求值与材料不存在 |
| T04 参数结构 | 静态字段动态值、spread/assign、动态键、数组与未知对象 | 提对已知字段，保留未知部分与覆盖顺序 |
| T05 跨函数关系 | 导入别名、重导出、闭包/回调、同名不同对象、请求实例 | 数据传递和来源能否追对，需要多少自定义模型 |
| T06 最终载荷 | 默认头/SDK 注入、删除/覆盖、序列化、token/二进制 | 构造字段与最终发送候选是否区分，是否漏后续写入 |
| T07 JS 与运行边界 | 三层引用、动态 JS、混淆/模块运行时、错版脚本、旧队列 | 取得 JS 后能分析多少；哪些必须结合黑盒或材料 |
| T08 真实请求 | 已有黑盒接口/参数/栈，以及独立白盒新候选 | 能否解释实际请求并补新路径，不能只选简单命中样本 |

## 3. 每条路线记录同样的结果

| 比较项 | 需要记录 |
|---|---|
| Host/接口 | 人工真值中找回/漏掉多少，输出中正确/错误多少，未知哪些 |
| 参数 | 按调用点+载体+字段路径核对：提对、漏字段、虚构字段、来源错连、结构未展开 |
| 语义 | 字段含义/敏感标签的依据、推测/未知，人工复核是否一致 |
| 适配量 | 需要写多少规则/查询/摘要/库模型，是否只对该样例有效 |
| 成本 | 初始化、单次分析、增量重跑、AI 调用和人工复核耗时/资源 |
| 可重复性 | 同输入再次运行是否一致，结果引用是否真实且对应同版 JS |

- [ ] 输出一张逐题对比表：A/B/C 各提到什么、漏什么、代价多少；不只统计是否生成报告。
- [ ] 再决定单路线或分阶段组合；组合必须能说明相较单路线新增覆盖与新增成本。
- [ ] 当前所有效果与覆盖率填“未测”；以后报百分比附真值范围、分母和未解项，不外推全仓。
