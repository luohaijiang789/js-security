# 插件界面与交互改进

本轮按用户实际试用反馈重做管理界面与查看流程，并将插件工程完整移入 `browser-extension/`。构建、升级与安装步骤见[插件开发与安装](插件开发与安装.md)，工程入口见[插件 README](../browser-extension/README.md)。

## 已复现的问题

| 问题 | 复现或原因 | 本轮处理 |
|---|---|---|
| 点击接口看起来无反应 | 100 条请求时，详情在表格下方约 `7,259px`，而测试视口仅高 `1,000px`，点击没有把详情带入视口 | 使用固定高度列表与常驻详情侧栏；点击行立即显示详情，窄屏使用可见侧栏 |
| 重开后看不到已保存任务 | 后台重启后当前运行任务为空，页面未自动选择 IndexedDB 中的历史任务 | 优先恢复用户选择，缺失时选择当前或最近历史任务；后台暂不可用时仍可查看本地数据 |
| 刷新干扰查看 | 列表轮询和详情记录更新没有作为稳定浏览流程验收，可能覆盖当前选择或把详情分类归位 | 详情身份与内容更新分开管理；轮询保留已打开请求、分类及任务选择，过期响应不能覆盖新操作 |
| 新任务继承旧策略 | 编辑当前任务与创建新任务共用表单，可能携带旧任务 Filter 和有损归并配置 | 新建弹窗使用独立草稿，从明确的模板、归并与授权页面开始；取消不会改动已有任务 |
| 导出可能混入其他任务 | 长时间导出期间仍依赖可变的界面任务选择 | 导出开始时固定任务、配置与选中记录；写入期间锁定任务切换，取消与失败明确反馈 |
| 只有结束请求可见 | 长连接等请求没有终态前，用户无法查看已经取得的字段 | 增加“在途”快照视图，按批次展示受保护的已取得字段；打开的详情在请求完成后自动更新终态 |
| 目录占用了整个项目根部 | 插件的源码、npm 依赖和构建文件直接放在多方案仓库根目录 | 统一放入 `browser-extension/`，其他方案使用各自工程目录，主仓文档与参考仓继续共享 |

## 管理页与数据查看

点击 Chrome 工具栏插件图标直接打开管理标签页，不再经过 Popup。工作台包含原始、在途和聚合三个视图，提供全任务搜索、资源类型过滤、分页、任务切换和右上角导出入口。

详情侧栏分类展示：

| 分类 | 展示内容 |
|---|---|
| 概览 | 完整 URL、方法、状态、页面、Referer、发起脚本、时间、Filter 版本、采集质量及请求身份 |
| 参数 | Query 名称和值，保留重复名称、空字符串和原始顺序 |
| 请求头 | 已取得的头、脱敏观察和完整性原因 |
| 请求体 | 表示类型、Content-Type、解析内容；合法 JSON `null` 与未取得正文分别显示 |
| 调用栈 | 可观测帧与异步父栈，函数、脚本及一基行列；缺失坐标与未展开父链保留说明 |
| 原始数据 | 全部已保存字段与状态，可复制 JSON 或导出单条 JSONL |

原始记录不会被聚合视图替代。点击请求组可查看代表记录、次数和差异，再进入本组全部原始观察。在途视图展示的是可能尚未到齐的受保护快照，不能当作完成请求；完成后保留同一请求 ID，并更新已经打开的详情。

## 状态与并发控制

页面刷新、用户选择、打开详情和导出各自保留操作身份；旧异步结果返回时，先判断是否仍属于当前任务与当前操作。后台任务变更按顺序处理，避免重复开始、停止与恢复互相覆盖。后台周期写盘和转存调度分开，慢转存不会阻断在途快照写入。

导出固定本次任务上下文，选中在途快照时保留 `pending` 状态。正式交接仍应先停止并写盘，再导出完整任务包。界面的自动刷新开关只控制列表刷新，不表示暂停浏览器采集。

## 已有用户的目录升级

将源码放入 `browser-extension/` 不会自动迁移旧扩展的数据。没有固定 manifest `key` 时，Chrome 加载已解压扩展的路径变化可能改变扩展 ID；IndexedDB 按扩展来源隔离，因此从旧根目录 `dist/` 改为 `browser-extension/dist/` 加载后，旧任务不保证在新扩展中可见。

需要保留已有任务时，可选择以下一种方式：

1. **保持原加载路径更新。** 在 `browser-extension/` 构建后，将 `browser-extension/dist/` 的构建内容完整复制到原来已经加载的 `dist/` 目录，再到 `chrome://extensions` 点击该旧扩展的“重新加载”。原安装路径不变，可继续使用旧扩展来源下的数据；更新前建议先导出已有任务。源码、依赖和正式构建配置仍全部在 `browser-extension/`，原路径只用于临时兼容安装。
2. **新路径独立安装。** 先用旧扩展导出已有任务，再加载新的 `browser-extension/dist/`。在确认备份可用前保留旧扩展，不要卸载它，以免删除其本地证据。新扩展不会自动读取旧扩展的 IndexedDB；当前没有承诺跨扩展 ID 自动导入历史任务。

构建前先停止旧任务并完成导出。确认实际加载路径、扩展 ID 与需要保留的数据后再更新，避免把“新来源下没有历史记录”误判为采集数据库损坏。
