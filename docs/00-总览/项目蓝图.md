# 范围与问题地图

**目的：找清前端 JS 跨境透传链路并整改。** EO 14117/DSP 决定本轮需要补哪些数据、主体、交易与访问事实；实施顺序见[团队方案](../../deliverables/团队交流方案.md)，任务状态见[Checklist](../../deliverables/项目Checklist.md)。

| 要排查的问题 | 白盒入口 | 黑盒入口 | 最后要定位到 |
|---|---|---|---|
| 自有埋点发了多余字段 | 事件 schema、公共 track、对象合并 | 事件请求/批量载荷 | 字段构造和调用者 |
| SDK 自动读取或上报 | 初始化、插件、默认开关、读取与发送 | 脚本/配置/实际接口与字段 | SDK 输入、接入配置或替换控制 |
| 风控字段被注入业务 API | 拦截器、fetch/XHR 包装、匹配配置 | 本方请求中的新增头/query/body | 注入点、影响接口与接收后流转 |
| URL/错误/回放暴露内容 | URL、错误对象、breadcrumb、DOM/遮罩 | 异常、动态页面、回放与离开场景 | 源头最小化、公共封装和旁路 |
| 延迟与跨身份透传 | 队列、存储、重试、Worker/SW | 登录/退出/切换、离线/恢复 | 身份绑定、清理与 flush |
| 首跳之后转发或境外可访问 | API、日志、队列、存储、有效权限 | 请求/字段作为下游交接线索 | 后端、云、供应商与组织控制 |

范围：应用/版本、路由/角色/租户、脚本/配置、发送载体和下游。一个仓库、CDN 清单或主流程都不是完整分母。每个未取得资产、未触达状态和未支持机制进入覆盖账本。

试点优先一条错误上报和一条业务 API 注入，其他机制登记后分批深入。Baxia 是样本，不限制排查品牌。一般 CVE、性能优化和通用 Agent 平台仅在解决上述问题有直接作用时纳入。
