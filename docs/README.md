# 文档导航

本目录描述新一版前端 JS API 提取器。当前没有实现代码，也没有可执行命令。

建议按以下顺序阅读：

1. [需求](requirements.md)：明确做什么、输出什么、什么不做。
2. [架构](architecture.md)：明确模块、边界、协议和技术路线。
3. [分析设计](analysis.md)：明确四项信息怎样从复杂 JS 中恢复。
4. [测试与验收](testing.md)：明确用什么输入证明效果和速度。
5. [实施计划](plan.md)：逐项实现、验证和打勾。

## 文档规则

- 只维护当前方案，不保存逐版本报告和失效设计；历史使用 Git 追溯。
- 计划中的 `[x]` 必须同时有实现、自动化测试和约定的真实样本证据。
- 只完成设计或只增加候选数量不能打勾。
- 发现架构假设不成立时，先更新需求或设计，再修改代码。
- 外部仓库、构建产物、依赖和大报告放主仓库 `work/`，不提交到 Git。
