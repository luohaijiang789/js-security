# 黑盒二：网站 JS 收集与请求静态提取

**输入网站入口和允许访问的页面/脚本范围，取得可发现的 JS，复用白盒请求分析能力，输出 API 与参数候选。** 这是对现有插件真实请求采集的补充，当前仅方案、未实现。

## 1. 流程

```mermaid
flowchart LR
    P["入口页面 / 可用登录会话"] --> S["发现内联脚本与外链 JS"]
    S --> D["收集静态引用、已加载脚本、可解析 chunk"]
    D --> F["按引用深度获取，记录版本与缺口"]
    F --> A["复用 M2～M4：请求、地址、参数分析"]
    A --> X["M5 汇总 Excel，标为网站 JS 静态候选"]
```

## 2. 采集什么

先从 HTML 的 script/module 与现有资源记录收集脚本；需要渲染或登录时使用用户提供的会话访问获准页面。浏览器运行只能发现已发生的加载，仍需静态分析 import、动态脚本构造、chunk 映射和远程模块引用。

| 场景 | 处理 | 主要缺口 |
|---|---|---|
| script src、内联脚本 | 记录页面、基址、URL/内容与位置 | 内联脚本可能依赖页面运行配置 |
| import、动态 import、脚本注入 | 解析已知目标，递归获取 | 地址完全动态时记录表达式 |
| 懒加载 chunk、微前端 | 解析已有构建映射/清单，结合加载记录 | 未知构建运行时需要适配，不保证枚举所有 chunk |
| 外部 SDK、Worker、iframe | 记录引用边与执行上下文，取得其 JS | iframe 页面不是 JS；记录页面跳转，不能把它当脚本文件 |
| source map | 可取得同版映射时辅助定位 | map 不一定包含源码，不能当运行覆盖证明 |

网页相对 URL 按实际页面基址解析；ES 模块相对 import 按模块 URL 解析。JS 中的相对 fetch 通常依赖执行上下文，不能直接拼到脚本 CDN 地址。

## 3. 范围与深度

采用[总方案](API资产收集总方案.md)的三层口径。页面遍历与 JS 引用深度分开记录；已知父脚本的子脚本不得重复算成页面直接脚本。

页面访问范围、脚本允许获取来源、接口结果记录范围分开：允许收集 CDN 脚本不代表遍历整个 CDN；发现外部请求 Host 仍应记录，不按业务站域名过滤结果。未知父链、失败、截断、不同内容版本保留记录。

只为收集页面与脚本访问必要资源，不自动对提取出的 API 发请求，不启用参数爆破、自动表单提交或漏洞扫描。使用爬虫前核对默认行为，防止把“发现端点”误变成“请求端点”。

## 4. 如何与插件互补

- 网站 JS 找到未触发的请求：输出静态候选及可能触发条件，供插件定向验证。
- 插件看到请求但网站 JS 没找到：按调用栈找漏收脚本、动态构造或未支持机制。
- 两边字段不同：查脚本版本、页面配置、拦截器、SDK 注入及采集状态。
- 同一 API 不能仅凭 URL 相同认定源码已定位；多个候选和错版线索必须保留。

## 5. 首轮验证

- [ ] 页面直接 JS → SDK → 子 JS 的三层链可取得，第四层留缺口。
- [ ] 外部 CDN 上相对 import 与脚本内部相对 fetch 使用正确基址。
- [ ] 已下载但未执行分支中的请求也能提取，证据仍标静态候选。
- [ ] 未登录、未加载 chunk、解析失败不被当作没有请求。
- [ ] 与插件结果进入同一 Excel，按来源、版本和调用上下文保留差异。

候选获取工具：getJS / Katana / GoSpider；候选轻量提取器：jsluice / LinkFinder。用途与限制见[调研](../Temp/GitHub方案调研.md)，不预先全部接入。
