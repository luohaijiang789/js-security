# 原始CDP日志、原子移交与重放

当前范围为现有监听的12类通知：脚本解析、执行上下文创建/销毁/清空、Network请求/响应/ExtraInfo/终态，以及子目标附加/分离；不是Chrome全部协议方法。原始通知先写临时日志，持久成功后再交给整理器。日志与待传队列在同一IndexedDB中，移交事务同时写待传正文/序号、删除日志条目、更新两边账目；最终只有有效后端ACK才清理待传正文。重启先恢复待传，再移交剩余日志，最后重新附加浏览器。

重放上传已记录的原始通知，不重新执行过期CDP命令。connection、会话、标签、通知序号、接收时间、配置版本及JS代次与原始params一起固定。后端保留原文、独立核对摘要和数量，关联请求/响应/调用栈；整理记录已存在时不重复计数，缺整理记录时输出有来源标记的恢复记录。通知中没有的响应正文、延迟取得的JS正文和未解析异步父栈不能凭空恢复。

新建远端任务默认开启原始日志；旧配置未显式开启时维持旧行为。开启时原始通知完整传输，Filter/字段选择只影响整理视图，不裁剪原始证据，创建任务时明确显示这一点。暂停后不捕获新请求，仅继续已知在途请求的终态；未附加窗口、配额拒绝、写入事务尚未提交前崩溃仍是缺口。

日志临时待移交总量有界，写入中的内存批次也有上限；失败保留内存并暂停，不静默清理。停止先移交日志并等待传输确认，封账额外核对原始日志总数/字节/方法分类。未移交日志拒绝删除任务。不把已观察计数、已持久日志、已入待传和后端ACK混为一谈。

## 协议、状态和容量

wire仍为capture-stream-2，新增raw-cdp-journal-1能力和raw_cdp分类。RawCdpEvent.data保存capture_json原文、capture_sha256和UTF8 capture_bytes；后端独立验证摘要、长度、connection/序号、任务/会话/标签及通知方法，再与事件/传输账目一起提交。Raw通知的唯一ID由connection+通知序号生成，与上传流序号分别记录，重放不改写通知身份。

IndexedDB升级至4：新增capture_journal和journal_ledgers，保留既有待传和分类账。admitted只表示日志已严格持久；handed_off表示日志已原子搬入待传；pending表示尚未移交；ACK在传输账目中表达。封账额外提交capture_journal={count,bytes,by_kind}，后端逐项核对raw_receipts，缺失或不符拒绝封账；客户端也拒绝伪造的原始日志回执。

待移交日志全局最多16384项/64MiB，待写内存批次最多4096项/32MiB，约5毫秒合批。容量按序列化UTF8字节计，存储引擎和序列化瞬时开销另计。达到上限显式报错/暂停；恢复先移交已有持久日志释放容量，再重试尚在内存的批次，避免配额满后无法恢复。旧任务未显式开启原始日志时维持原范围，任务中不能切换该范围；切换需新建任务。

传输队列写盘失败时只在内存预留稳定序号，持久账目不提前计入该项，并暂停接纳后续事件。恢复写盘与其他在途ACK共享串行账目更新；事务提交后才更新持久计数。界面状态中的pending/admitted包含内存预留，volatile_pending单列尚未持久的数量。原始通知已经写入日志的，重启后仍从日志补传；只在内存中且未写入日志的数据仍受崩溃缺口限制。既有损坏账目继续拒绝猜测恢复，不自动删数据或重排序号。

不支持日志能力的旧后端会让原始待传保持未确认并提示升级，不静默降级为不收集。恢复会重新协商能力，可在同地址后端升级后继续补传。旧任务关闭原始日志时仍可使用旧端串行/窗口兼容路径。

## 分析和原始证据查询

同一请求的request/response/initiator/栈组成一个恢复记录，状态为raw-cdp，保留raw_event_ids；整理记录已存在时仅关联原始事件，不重复增加请求次数。字段无法从通知取得时保持missing/partial；晚到的重定向ExtraInfo不能可靠归属时保留歧义。JSON正文结构恢复预算为2MiB、64层、100000节点，超限保留完整原文并标记结构解析缺口，NaN/Infinity和重复键不当作确定的JSON参数。无起始通知的终态不猜请求，暂停后新请求不进入恢复记录。缺少整理后的上下文可从日志投影，已持久JS不会因同一原始解析通知再次出现而被误报缺源。

分析结果增加raw_capture统计、API组raw_recovered_request_count与原始证据ID；没有JS正文也生成真实请求清单。固定批次同时保留raw-notifications.jsonl，使用JSON转义保留不能直接UTF8显示的原始值；无法安全规范化的通知留缺口，不使整批失败，也不编造正常文本。

上下文按创建、销毁、清空的生命周期区分，同一个executionContextId复用时保留独立资产与域名。原始通知按回调顺序绑定脚本，整理后的源JS只有唯一匹配时才挂接该生命周期；无法证明时保留JS正文但Host为未知，记录raw_context_binding_unknown。单个请求的ExtraInfo先暂存再关联，支持早于起始通知或responseReceived；头名称按大小写无关合并，ExtraInfo优先，保留普通通知的独有字段。重定向存在多个跳且归属不明时仍保留歧义，不猜测头所属跳。

GET /events?scan_id=…&event_id=…返回该任务下完整不可变事件及事件摘要，错误任务返回404。列表摘要不带原始正文，原始通知按需查询/下载；插件预览最多200000字符，完整内容可下载，不在浏览器另建已确认正文档案。

## 验证与仍未完成的部分

覆盖：移交前中断、移交后断网、重建客户端补传、错误作用域移交事务回滚、写盘失败、配额恢复、写入内存限额、能力升级重协商、旧库升级、摘要/身份冲突、伪造封账、请求响应栈恢复与去重、重定向歧义、暂停、缺源、异常Unicode及实际background RPC到后端封账。

本轮持久化的是Chrome通知，不是所有后续CDP命令结果。未取得/未持久的响应正文、Debugger源码和异步父栈不能凭通知重建；事务提交之前崩溃、未附加范围和配额拒绝仍保留缺口。命令结果持久化、长期容量治理、会话租约及目标Chrome/服务器压力验收为后续工作；不承诺无条件100%全站采集。

在途追踪索引最多16384项，子会话/标签页断开时释放；索引满时原始通知仍上传，并明确记录暂停期间可能缺少终态的缺口。索引清理不删除待传证据。
