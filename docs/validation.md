# 三路联合验证与现场验收

白盒旧实现已经删除，正在重新设计；浏览器插件仍独立维护。下面列的是三路最终联合验收，不表示白盒相关能力已经实现，也不把局部测试外推为整体通过。

当前先验证[黑盒二](../website-js-extractor/docs/plan.md)，再接入白盒；白盒状态见[实施计划](../frontend-api-extractor/docs/plan.md)，样本分组、评分分母与发布门槛见[测试与验收](../frontend-api-extractor/docs/testing.md)。本文件保留三路整体执行清单，不将计划标为已验收。

## 0. 提取器验证入口

需求、架构、分析设计和单路验收集中在提取器自己的 docs/，本页不重复勾选实现进度。旧版记录只通过 Git 历史追溯。

## 1. 材料准备

- [ ] 一个可重复构建的试点仓及固定 Commit，附目标环境配置、锁文件、私有包凭据、代码生成输入和正式构建命令。
- [ ] 同一项目的源码、本地构建产物、source map、同版线上产物，以及可访问测试页面。
- [ ] 人工标注发送点、调用上下文、预期地址/字段及同名非网络函数等反例。
- [ ] 允许获取的直接外部 SDK 与后续引用样例；明确代码可发送给 AI 的范围。
- [ ] 受控服务端接收记录用于核对实际发送；插件开发后再补插件导出包，不将其作为白盒前提。

## 2. 静态分析核心与白盒接入样例

| 样例 | 必须检查的结果 |
|---|---|
| fetch/Axios/XHR/Beacon 标准用法 | 发送点、实例、机制与参数正确；同名普通函数不误报 |
| 跨文件 report(data) → request.post | 能追到调用方字段，隔离不同调用者 |
| 多 client、不同 baseURL/拦截器 | 地址、字段和改写属于正确实例 |
| 环境变量、别名、条件编译与生成文件 | 构建成功并记录输入；产物值能回指源码配置和位置 |
| 第一层 SDK 自己发送 | 分析发送及可确定的业务调用关联 |
| 第一层 SDK 委托更深模块发送 | 按输入模式和显式获取配置递进；黑盒二超过三层留截断和影响，不假定无请求 |
| 未知 spread、动态键、对象别名/覆盖 | 已知结构保留且风险显式；未展开变量不冒充字段名 |
| 拦截器删除、JSON 过滤、自定义编码 | 区分构造结构与最终候选载荷；未支持行为标部分 |
| WebSocket、Pixel、Form、Worker | 按机制和执行上下文处理，未支持部分有记录 |
| 时间/节点预算耗尽 | 保存部分结果和准确中断原因，不静默标完整 |

## 3. 源码、构建产物与部署代码对照

对同一批请求分别分析三种输入，逐条记录恢复结果及缺口：

| 输入 | 重点观察 |
|---|---|
| 配置齐全源码 | 模块绑定、跨文件传参和业务位置能否恢复 |
| 本次构建产物 | 已替换常量、生成代码、完整 chunk 与 source map 是否可恢复 |
| 同版线上产物 | 与本地制品哈希/模块差异、部署注入配置和额外脚本 |

- [ ] 分别评估 M2、M3、M4，列出可共享基础、专用适配和仍未解决的场景。
- [ ] 对新的独立联合样本运行原生 jshound 与增强核心，核对四项结果、方法、位置和缺口；既有 worker 开发测试不代替此项。
- [ ] 对本地预览运行 Vespasian 的被动 crawl/JS 静态模式，核对动态观测与未触发候选，并确保关闭主动 probe。
- [ ] 再用 CodeQL/Joern 与源码 AST 对照跨文件封装、拦截器和源码位置，决定哪些差距需要自研。
- [ ] 模型和 AI 提议用未参与建模的新样例及反例复验；保留依据位置，不凭解释提升完整性。

## 4. 网站 JS 收集验证

本路优先独立实施，阶段及必测矩阵见[黑盒二计划](../website-js-extractor/docs/plan.md)，不等待白盒。以下三层规则限制主动补取，已取得深层资产仍分析。

- [ ] 内联、外链、动态 import、懒加载、SDK、Worker 与 iframe 有来源和上下文记录。
- [ ] 直接脚本 → 子脚本 → 第三层可获取，第四层留缺口；未知父链不伪装第一层。
- [ ] 相对 import、页面资源与不同上下文的相对 fetch 使用各自正确基址。
- [ ] 未执行分支可输出静态候选；未登录、缺 chunk、压缩/解析失败不当作无请求。
- [ ] 可取得运行配置与脚本哈希关联；多版本不覆盖、不强并。
- [ ] 收集工具不主动请求提取出的 API 或自动提交业务表单。

## 5. 插件验证

先验证 CDP 采集原型，再完成 Filter、存储、归并、转存等功能；完整清单见[插件验收规格](../browser-extension/docs/requirements.md#10-验收-checklist)。

- [ ] 与受控服务端记录核对地址、头、Query、Body；调用栈可取得性和缺失原因明确。
- [ ] 多标签、iframe/子目标、Worker、重定向按目标 Chrome 版本测试可观测边界。
- [ ] 验证刷新/导航、debugger 断开、后台生命周期及恢复；中断窗口留账。
- [ ] 实测高请求量、队列上限、写盘/转存失败及停止时在途请求处理。
- [ ] 插件包可导入统一模型；缺失、脱敏和请求组关联不丢失。

## 6. 统一交付验收

- [ ] 三路可独立输出，同一 API 不同证据/版本/调用/观察分别保留。
- [ ] 总表、参数明细、分析缺口与 JSON 底稿可通过 ID 回查。
- [ ] 无字段、未知、未采集、不适用及脱敏有明确区别。
- [ ] 同 URL 不强认同版；参数并集不伪装单次载荷；单次实测不提升全部路径完整性。
- [ ] 超长内容及大数据量不静默截断，Excel 外部字符串不作为公式执行。

| 指标 | 统计口径 |
|---|---|
| 静态请求召回/误报 | 人工标注的调用上下文；未确认候选另计 |
| 参数准确性 | 请求上下文 + 载体 + 字段路径；计漏字段、误字段和错误合并 |
| 获取/解析情况 | 已发现资产中的成功、失败、截断；不冒充全部网站脚本覆盖率 |
| 实测采集质量 | 受控发送与已观测/持久化记录对照，附中断和未知窗口 |
| 完整性与成本 | 误标完整数量、未知项、耗时、适配与人工复核成本 |

每项结论附输入版本、配置、模型/工具版本、分母和遗留问题。不把三路数量相加当覆盖率，不外推全仓或全站百分比。
