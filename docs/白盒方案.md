# 单仓 JS 白盒方案：讨论起点

**当前任务：设计一种方法，从一个代码仓找出数据传输路径，解释黑盒观察，并定位整改点。**

业务背景见 [README](../README.md)，已确定且已验证有效的[黑盒方案](黑盒方案.md)作为既有输入。本文件只保留白盒讨论与决定，不预设扫描工具或实现架构。

## 已确认

- 先覆盖一个仓库，再考虑多仓扩展。
- 黑盒提供页面、接口、参数信息与调用栈，白盒据此反查。
- 白盒还要独立排查，发现黑盒尚未触发的路径。
- 输出必须能落到字段、接口、代码/配置位置，无法确认的明确留账。

## 接下来讨论的四个问题

| 问题 | 要决定什么 |
|---|---|
| 怎么找全发送入口 | 业务请求、上报 SDK、公共封装、隐式注入和动态配置如何纳入 |
| 怎么查清字段来源 | 跨函数/模块、对象合并、覆盖/过滤和异步传递追到什么程度 |
| 怎么使用黑盒结果 | 接口/参数/调用栈如何匹配源码；版本不符或栈不完整怎样处理 |
| 怎样验收 | 用哪些正反例证明能找到真实路径、排除错误连接并给出修改点 |

具体工具、AI/Agent 分工和自动化程度，待上述问题明确后选择。
