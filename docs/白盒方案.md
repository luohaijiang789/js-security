# 白盒 V1 方案框架

**目标：输入 Host 和一个代码仓，找出前端 JS 使用该 Host 的接口，提取参数、含义和敏感性线索，汇总成表。** 服务于美国业务前端 JS 跨境传输排查。

当前处于方案阶段，尚未开发。下表“能解决什么”指设计目标，不代表已有能力。

## 1. 输入与范围

| 输入 | 约定 |
|---|---|
| 代码仓 | 一个仓库，分析其中前端 JS |
| 目标 Host | 默认精确匹配；不是搜索文本中所有同名字符串 |
| JS 拉取深度 | 可配置，默认 3；只控制引用 JS 的取得，不限制仓内函数嵌套 |
| 辅助材料 | 已有配置、依赖映射、黑盒接口/参数/调用栈，按需使用 |

只递归取得引用 JS，不拉其他代码或整个依赖仓，不执行被分析代码。

## 2. 整体流程

```text
收集/解析 JS ←→ 递归拉取引用 JS
       ↓
定位请求与 Host ←→ 追踪封装和参数
       ↓
解释参数含义与敏感性 → 汇总表格 → 与黑盒核对
```

## 3. 模块与开发内容

| 模块 | 要开发什么 | 能解决什么 | 难点 / 尚未解决 |
|---|---|---|---|
| ① JS 识别 | 枚举前端 JS；读取已有 HTML/配置定位入口和脚本引用 | 确定哪些 JS 需要分析 | 前后端混放、组件脚本、vendor/压缩产物；实际支持的语法和文件类型待明确 |
| ② 引用 JS 拉取 | 解析引用、递归获取、深度控制、循环和重复处理 | 把外部 JS 纳入分析，默认最多三层 | 动态地址、包名到具体文件的映射、权限/下载失败；三层外仍可能有关键代码 |
| ③ JS 解析与关联 | AST、作用域、导入/导出、变量与函数引用索引 | 将跨文件调用连到正确实现，避免同名误连 | 别名/重导出、构建后的模块系统、动态调用；解析器及适配范围待验证 |
| ④ 请求与 Host 定位 | 识别发送 API/公共封装；解析 URL、baseURL、拼接及配置 | 找出目标 Host 对应的接口、方法和路径 | Host 分散在配置/封装中；相对地址、运行配置和最后改写可能无法确定 |
| ⑤ 参数追踪 | 沿调用参数、对象构造和请求改写，提取 query/header/body/path | 找到业务参数、公共上下文和 SDK 自动注入字段 | 对象引用/覆盖、动态键、回调、拦截器顺序、序列化；跨函数追踪方式需用样例验证 |
| ⑥ 含义与敏感性 | 结合字段名、来源、上下文和注释，用规则/AI 给解释与标签 | 将参数变成可阅读、可筛选的信息 | 普通名称歧义、自由文本、token/密文；无法确定的含义保留未知 |
| ⑦ 结果汇总 | 统一请求/参数结构，生成一参数一行的表，附代码位置 | 汇总一个仓库中目标 Host 的接口和字段 | 同接口不同调用的差异、部分字段未展开、去重丢信息；不能把未知写成无参数 |
| ⑧ 验证与补齐 | 固定代码样例测试，再用已有黑盒请求核对 | 检查接口/参数是否提对，定位需要补的模型 | 黑白盒版本不一致、运行时生成字段；真实覆盖度须实测，当前不能估百分比 |

参数的运行时值未知，仍可提取已知字段及来源表达式；不要求第一版先还原全程序数据流。下载到 JS 也不等于已理解其动态行为。

## 4. 最终结果

主表字段：**仓库/JS文件、Host、方法、接口路径、参数位置/名称、来源表达式、参数含义、敏感性线索、代码位置、未解析部分。**

同一接口可有多行参数；不同调用条件保留差异。国家和法律适用不由 Host 名直接推断。

## 5. 开发顺序

- [ ] **先跑通最小链路**：本地 JS、直接请求、固定 Host、普通参数 → 表格。
- [ ] **再解决核心难点**：跨文件封装、地址拼接、对象合并/覆盖、默认头与注入 → 用正反例验证。
- [ ] **再扩展引用与请求模型**：三层 JS 拉取、项目实际使用的请求库/SDK → 明确支持与缺失部分。
- [ ] **最后完善语义和验证**：参数含义/敏感标签、结果归并、黑盒核对 → 根据实测补模型。
