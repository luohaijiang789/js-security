# 代码架构、目录与实施顺序

本轮在根目录后端和唯一生产插件上重构，不新建第二套服务。真实请求、响应、发起位置、调用栈及上下文组成一条逻辑请求记录；JS内容与独立观察另存。先固定种子，递归收集（默认5层），结算引用，再冻结资产集，最后统一分析。

## 后端目录与依赖

```text
src/website_js_extractor/
  domain/                 # 协议、配置、资产与快照语义
    protocol.py
    settings.py
    assets.py
  storage/                # 原始证据、分类账、固定输入导出
    capture_store.py
  api/                    # HTTP校验、路由和接收入口
    server.py
  application/            # 作业与分阶段编排
    jobs.py
  ingestion/              # 浏览器证据转统一分析输入
    stream.py
    capture.py
  collection/             # 只发现/获取静态资源，不输出API结论
    graph.py
    fetcher.py
    pipeline.py
    references.js
  analysis/               # 锁定引擎、位置与结果适配
    engine.py
    worker.py
    engine-lock.json
    results.py
  cli.py / __main__.py
```

依赖方向：API→应用/存储；应用→输入适配→收集→分析；存储→领域；领域不依赖HTTP/浏览器。收集图和分析器不得操作接收数据库或临时浏览器队列。第三方引擎仍固定于references/repos/jshound，不批量修改子模块。

| 模块 | 输入/输出 | 必须守住的边界 |
| --- | --- | --- |
| domain | 版本化事件、AnalysisSettings、资产身份 | 深度/预算分别配置，5层指种子D1至D5，运行时加载深度另存 |
| storage | 不可变原始事件/对象、回执/分类账、固定水位种子导出 | 持久后ACK；只导出选中任务/水位所引用对象，不复制整库阻塞接收 |
| API | 上传/封账/作业/查询HTTP | 校验和错误映射；不在ACK路径下载JS或分析 |
| application | 固定批次、配置与状态 | 收集→结算→冻结→分析；新增事件进入下一轮 |
| ingestion | 一条真实请求记录、JS观察、上下文→统一快照 | 原始响应/调用栈保留；URL不是版本，不把加载栈冒充发送栈 |
| collection | 确定引用→正文/引用图/缺口/收集清单 | 配置允许来源、逐跳重定向检查，循环/多父/最短路径，未知不猜 |
| analysis | 固定完整/部分资产集→静态API候选和证据 | 全文件集统一分析，缺依赖传播缺口，不伪造调用位置 |

## 插件目录与依赖

```text
browser-extension/src/
  background/index.ts     # 扩展生命周期、会话拥有权、RPC调度
  capture/                # 真实请求、JS/加载、栈的采集
  transport/              # 中转协议、持久待传、重试/回执/封账
  storage/                # 任务库、资产索引、采集账和旧任务清理
  domain/                 # 类型和配置校验
  requests/               # 原请求过滤、分组、展示/字段语义
  integrations/           # 兼容原有SLS等出口
  export/                 # 原请求导出
  ui/                     # 工作台、组件、main入口和样式
```

background→capture/transport/storage，UI只走RPC或查询/只读任务数据。采集器不单独attach第二个连接；transport不调用浏览器业务API；类型不能依赖Vue。保持manifest的background.js和管理页安装入口不变。

## 完整性和大流量不变量

1. 浏览器事件分种类批量持久计数（非完整原始事件日志），分清“已观察”“正文取得”“已入待传”“已确认”；超限/取源失败也必须有记录。
2. 真实请求各部分可迟到，保持同一请求身份和明确字段状态；不能因响应未结束就只留内存无限等待。
3. 重启只恢复固定接收端/项目/任务/流身份，不生成新上传ID绕过旧回执。
4. 入队/ACK清理严格事务；发送端摘要与接收端校验组成端到端内容校验。旧仅服务端哈希不能当端到端一致证据。
5. 持久存储承载积压，内存只持有当前工作集；元数据/小请求不能永远排在大JS后。并行/乱序协议需先定义连续水位和缺失集合再上线，当前串行不能宣称已解决吞吐问题。
6. 存储失败必须保留可重试状态并暂停，禁止静默覆盖；磁盘/配额耗尽和未取得正文不算捕获成功。
7. 封账核对序号、分类、字节、对象和采集缺口；“传输全部确认”与“浏览器提供全部证据”分开。

## 配置和阶段清单

AnalysisSettings采用统一校验：默认max_js_depth=5，种子已有JS作为本批次D1（这是补抓预算，非真实网站层级）；函数/内部模块追踪另行预算。后端支持资源补取，允许来源取浏览器已观察脚本/页面来源并合并显式配置的CDN来源；不将API结果里的URL当下载任务，不默认复制Cookie到后端。服务端取不到登录资源时记缺口；插件委托补取作为后续工作包，不能假称已支持。

收集阶段结束输出analysis-manifest.json：种子身份、最终资产哈希、引用状态分布、层级、配置、缺口和complete/partial状态。分析只读该清单对应的固定正文集。即使部分收集也能分析，但必须保留影响范围。
