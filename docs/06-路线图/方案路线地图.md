# 建设顺序：按跨境透传问题验收

| 顺序 | 先解决的具体问题 | 产物与退出条件 |
|---|---|---|
| 1 人工闭环 | 代码与请求无法对应 | 一条字段路径、一次双侧往返、可定位整改和缺口 |
| 2 黑盒结构化 | 抓到了流量但字段/上下文不可检索 | 资源/场景/请求/字段引用；保留本方请求 |
| 3 白盒机制 | 封装/SDK 注入藏在调用处之外 | 版本/条件明确的机制，关联具体调用者与变换 |
| 4 双侧关联 | 只有一边发现或两边冲突 | 解释/验证任务与版本相容性，不强行合并 |
| 5 接收后事实 | 浏览器首跳后断链 | API/日志/队列/区域/访问负责人及取证 |
| 6 增量控制 | SDK/配置/字段/权限变化复发 | 变化影响的主张与重验任务 |

后端取证和必要临时处置可从第一轮开始，不等工具建完。工程待办见[workstreams](../../workstreams/README.md)，研究问题见[研究队列](../../references/研究队列.md)。

暂不提前决定图数据库、完整 AST 引擎、定制浏览器或多 Agent 平台。使用真实重复工作、漏报机制、运行兼容与维护成本作选择，阶段计划和人员由[交流方案](../../deliverables/团队交流方案.md)落实。
