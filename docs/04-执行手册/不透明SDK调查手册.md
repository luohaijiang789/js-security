# 不透明 SDK：围绕可整改问题分级调查

**目标：查清 SDK 输入、直传/注入、可关联性和下游；不以完整反混淆作为交付前提。** 项目方法见[白盒](../../deliverables/白盒怎么做.md)与[黑盒](../../deliverables/黑盒怎么做.md)。

| 顺序 | 查什么 | 完成证据/后续分支 |
|---|---|---|
| 1 固定样本 | 实际脚本哈希、加载者、初始化/远程配置 | 版本与配置对应；拿不到列资产缺口 |
| 2 切分边界 | 读取、token 输入/输出、业务注入、SDK 直传 | 代码/调试/请求引用，未知实现不补猜 |
| 3 核具体字段 | 与用途/整改有关的输入和载体 | 六项路径检查；不将读取等同发送 |
| 4 受控对照 | 合成输入、身份/状态，控制时间/缓存/随机噪声 | 基线、干预与观察；变化只能先支持依赖假设 |
| 5 查关联 | token 稳定范围、账号共现、实际 join 键和持有方 | 映射/密钥/持有能力证据；字段同名不能代替 |
| 6 查下游 | API/日志/队列/存储、主体/地区/访问 | 接收方证据或带负责人的交接 |
| 7 选动作 | 冗余字段删除、必要风控限用/保留/替换 | 真实控制点、业务约束、双侧/下游复验 |

## 向供应商要什么

- [ ] 数据与派生特征分类、用途、默认开关和字段控制。
- [ ] 实际端点、处理/子处理主体、区域、备份和支持访问。
- [ ] token 生命周期、稳定性、关联方式和密钥/映射控制。
- [ ] 可用过滤、接口/区域限定、删除和审计证据；要求对应版本。
- [ ] SDK/远程配置变更通知与接入侧可验证方式。

## 缺证据时如何继续

| 已知 | 可以推进 | 保留未知 |
|---|---|---|
| 冗余原始字段进入请求 | 评估源头删除并验证 | 接收与历史副本另追 |
| 只知道读取 | 查必要性和变换 | 不声称原值发送 |
| 必要 opaque 风控 | 查匹配范围、输入/输出、供应商事实 | 不靠猜解 token 决定全部替换 |
| 配置或下游拿不到 | 有目标的材料/实验任务 | 当前启用、区域/主体、访问状态 |

EO 事实与处置进入[Checklist E/R/V](../../deliverables/项目Checklist.md)，供应商说明与技术观察分别留据。
