# JS 请求采集插件 v0.1.0

按《[JS 请求采集浏览器插件](JS%20请求采集浏览器插件.md)》实现的独立 Manifest V3 扩展。EASYapi 与 maksimu/openapi-devtools 用于参考；未将其发现结果计数或主动过滤逻辑作为采集入口。

## 构建与安装

构建环境使用 Node.js `20.19+` 或 `22.12+`（Vite 7 要求）。项目的公开依赖使用 npm 官方源；根目录 `.npmrc` 仅对本项目生效，并保留锁文件中的下载地址，不修改全局 npm 配置。

```bash
npm ci
npm run build
```

如果先前安装报内部镜像 `rollup-*.tgz` 的 E404，拉取最新功能分支后重新执行 `npm ci && npm run build`。`vue-tsc: command not found` 是依赖安装中断的后续错误，不需全局安装 `vue-tsc` 或删除锁文件。单次明确指定源也可使用 `npm ci --registry=https://registry.npmjs.org/ --replace-registry-host=never`。如果环境要求所有依赖必须走企业镜像，应由镜像维护方补齐锁定版本，再按组织约定调整项目配置。

Chrome 125+ 打开 `chrome://extensions`，开启开发者模式，选择“加载已解压的扩展程序”，选择构建后的 **dist 目录**。交付 ZIP 解压后，选择包含 `manifest.json` 的目录。企业策略必须允许加载该扩展。

点击工具栏插件图标打开 Popup：选择授权标签页、任务名称、Filter 模板、归并和归档策略后开始。点击“查看 / 导出”进入完整管理页面。完整页面也能新建任务；关闭 Popup 或管理页面不会主动停止后台任务。Chrome 会显示 debugger 调试提示。

暂停不接收新请求，在途关联继续；恢复登记中断窗口。停止先进入“处理中”，默认等待 5 秒，在途超时登记不完整，再完成写盘。调试断开、标签页关闭、后台重启均保留中断记录，手动恢复后不补写中断时段的请求。

## Filter 与归并配置

规则可以在可视化编辑器中配置，也可导入以下结构；`values` 是多值数组。非法字段、匹配方式、正则、嵌套或配置范围会报错。

```json
{
  "scope": {"field":"page_host","operator":"domain","values":["alibabacloud.com"]},
  "include": {"op":"or","rules":[
    {"field":"resource_type","operator":"in","values":["XHR","Fetch","Ping"]},
    {"field":"query","key":"tag","operator":"contains_any","values":["alpha","beta"]}
  ]},
  "exclude": {"field":"extension","operator":"in","values":["png","css"]}
}
```

`dynamic_query`、`dynamic_json` 默认空数组，`uuid_path` 默认 false，不擅自忽略 UID、CNA、Token、租户或资源 ID。普通 Query 按名称稳定排序，重复名称的值不排序；JSON 对象字段可规范化，数组顺序不变。每条请求固定接收时的配置版本。

默认保护 Cookie、Authorization、Token、Secret、Password、Credential、API Key、Session、CNA、UID、AccountID、TenantID 等名称对应值；URL 用户信息和 fragment 不保存。保留字段名称及 `[REDACTED]` 标记，不提供明文保留开关。JSON 深度超过 32 层、正文超限、不可解析、文本 / 二进制 / 文件均明确记录状态。非敏感字段和 URL 路径仍可能是业务数据，请在授权环境使用。

## 服务协议

在任务策略中设置 `service.enabled` 和 `service.url`，通过界面授权接收服务 origin。只接受 HTTPS，不允许 URL 内嵌凭据、Query 或 fragment，不跟随重定向。可选 Bearer Token 仅存 `chrome.storage.session`，不进入任务配置或导出包。

```http
POST /ingest
Content-Type: application/json
Idempotency-Key: <稳定批次ID>
Authorization: Bearer <可选会话令牌>
```

```json
{"schema_version":"0.1.0","batch_id":"...","scan_id":"...","records":[]}
```

服务必须按 Batch ID 幂等持久化；**持久化成功后**返回：

```json
{"batch_id":"相同批次ID","persisted":true}
```

HTTP 2xx、请求已经发出均不等于转存成功；缺少上述回执仍失败。自动最多 3 次尝试，指数退避下限，调度可晚于下限；耗尽后等待人工“重试失败批次”，原始本地数据保留。`service.interval_ms` 默认 5 秒（调度周期约 15 秒），`service.compress` 默认 false；开启后发送 gzip 和 `Content-Encoding: gzip`。每批固定接收地址及压缩选项。令牌失效后先重新授权。任务配置变更不会把已完成记录自动再发到新服务。

## 导出和一致性

```text
EO_SCAN_<任务ID>/
├── scan_manifest.json
├── requests_0001.jsonl
├── request_groups.jsonl
└── capture_errors.jsonl
```

任务目录通过用户选择目录写入；最后成功写入 manifest 才显示成功。ZIP 的请求分片另有 SHA-256；CSV 嵌套字段为 JSON，公式前缀按文本保护。取消目录写入可能留下部分文件，界面明确报错，请勿将无成功 manifest 的目录作为完整包。导出到新目录可避免与此前同名包混淆。

分组记录有代表 ID，每条原始请求有 `group_id`；在原始视图搜索组 ID 可查全部成员。仅代表模式导出不可恢复逐次证据。Schema 为初版 `0.1.0`；Excel / `analysis.json` 下游导入和静态关联仍属于后续汇总模块，此版不生成虚构静态依据。

## 验证命令与结果

```bash
npm run build          # TypeScript / Vue 检查及 MV3 分目录构建
npm test               # 核心、转存、真实 Chromium CDP 和页面测试
npm run test:browser   # CDP 与页面测试（页面中替代扩展 API）
npm run test:extension # 真正加载 MV3，须允许安装扩展的 Chrome
```

Linux 浏览器默认 `/usr/bin/chromium`；可用 `CHROMIUM_PATH` 指定已安装浏览器。测试只访问本地受控服务；服务收到的记录与采集结果核对，不请求用户业务系统。

当前环境 Chromium `154.0.8037.57` 的真实 CDP 场景保存 13 条预期请求、12 个请求组：POST、HEAD、OPTIONS、GraphQL、静态 JSON、Beacon、像素、重复 Query、动态归并、重定向、超大正文、暂停和停止在途；未选标签页及暂停后请求没有进入保存结果。测试敏感原值不进入持久化记录。另验证 100 次重复观察、写盘失败保护、下载完成 / 取消、服务持久化回执、同 ID 三次重试、可视化页面和 Popup 操作。

当前环境有企业 `ExtensionInstallBlocklist: ["*"]`，**真正 MV3 加载测试未通过安装前置条件**。没有修改企业策略；CDP 测试使用真实浏览器和 fake-indexeddb，页面测试替代了扩展 API，不作为完整插件现场验收。Worker / 跨进程 iframe、真实 IndexedDB 配额故障、后台强制重启、多文件下载 / 目录权限和长时间压力测试须在目标企业 Chrome 继续验收。原规格 T01～T35 不整体勾为已通过。
