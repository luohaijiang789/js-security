# 黑盒二执行计划与验收

本文件是 site-js-analyzer 独立 CLI 原型的唯一进度清单。主干的[插件/本地服务产品计划](../website-js-extractor/docs/plan.md)单独维护产品协议、UI、MV3 与发布验收；本文件的 S0–S6 是原型任务 ID，不与产品阶段同名项等同。按任务 ID 及前置关系实现、测试、记录证据后更新；不另存逐版本报告。用户已授权先写规划，再按规划开始实施，不需逐项重新确认。

设计依据：[总体设计](site-analysis-design.md)、[讨论结论](api-discovery-decisions.md)、[开源实测](../references/blackbox2-experiment/README.md)。运行方式见[独立工程](../site-js-analyzer/README.md)，结果协议见[协议](../site-js-analyzer/docs/protocol.md)。

## 目标与实施顺序

目标：取得页面部署 JS，沿引用继续收集，提取 URL、Host、Method、参数与 JS 来源，输出可追溯 API 统计。优先复用固定 jshound，不区分业务和三方，不主动调用发现的 API。第一条可运行链路先处理已有资产，随后增加受控递归获取、精确位置和浏览器输入。

```mermaid
flowchart LR
    S0[工程与协议] --> S1[离线导入与字段保留]
    S1 --> S2[引用图与递归获取]
    S2 --> S3[精确位置与调用上下文]
    S3 --> S4[正式统计与 Excel]
    S4 --> S5[独立样本验收]
    S5 --> S6[浏览器直接接入]
```

| 阶段 | 可交付结果 | 前置条件 | 阶段门槛 |
| --- | --- | --- | --- |
| S0 | 独立工程、固定依赖、输入输出协议、样本清单 | 已有开源实测 | 协议明确已知/未知、来源、候选、退出状态 |
| S1 | HAR/目录 → 快照 → 内部记录 → JSON/预览表 | S0 工程与协议 | Query 不丢、版本不覆盖、候选不冒充精确调用 |
| S2 | 引用边、三层补取、预算与恢复 | S1 | 递归/循环/多父/缺口和额外请求核对通过 |
| S3 | 原始位置、调用方、字段阶段与置信度 | S1/S2 | 位置有直接证据；多接口共享发送点不错误合并 |
| S4 | 接口汇总、调用明细、正式 Excel | S3 | 已确认/候选/未解析分开，各计数可回查 |
| S5 | 冻结独立样本、精度/召回/资源成本报告 | S2–S4 | 正常/反例矩阵通过，公开样本有明确分母 |
| S6 | 浏览器资产交付、交互界面与现场验收 | S5 | 登录/导航/Worker/CDP 现场验证；离线入口独立可用 |

S0.4 的独立样本准备可与 S1/S2 的通用输入实现交错推进，但必须在针对样本增加提取规则之前冻结，未完成不得通过 S5。

不把浏览器 UI、AI、全站爬虫或白盒接入放在首个可运行里程碑；这些不会阻止验证核心能力。S1 可以先提供预览统计与表格，但必须标明尚非 S4 的完整接口统计。

## S0：工程、协议与样本

- [x] **S0.1 工程**：建立 `site-js-analyzer/`，Python CLI 调用固定 jshound；工程依赖独立，错误版本必须停止，不混入插件依赖。产出 pyproject、引擎锁定信息、使用说明。验证安装、CLI 帮助、缺依赖/错版本错误及冻结样本运行。
- [x] **S0.2 协议**：定义 Task、Context、Asset、EngineRecord、RequestCandidate、ApiGroupPreview、Gap；标明文件证据与精确发送点的区别，冻结 schema 0.1。产出协议文档与实际 JSON；验证未知、缺失、失败及版本关联反例。
- [x] **S0.3 现有基线清单**：引用已冻结 13 请求样例、压缩样例及 Swagger UI Commit/哈希，说明公开 bundle 无召回真值。验证主流程可读这些输入且不丢原始字段；不将其称独立盲测集。
- [ ] **S0.4 独立验证集**：另选公开部署样本，冻结版本、获取方法、人工发送点/参数和标注范围，分开发集与独立验证集。无真值的样本只做兼容性验证。

## S1：首个可运行里程碑——已有资产的离线分析

- [x] **S1.1 导入快照**：目录保存相对文件身份；HAR 只导入 HTML/JS，不将流量 API 响应当静态接口；处理 UTF-8/Base64、缺正文、状态/类型和同 URL 多版本。正文按哈希保存，原始输入不改写。验证正常 HAR、缺正文/无效 Base64/登录 HTML、同名/同 URL 不同正文、空目录与路径穿越。
- [x] **S1.2 引擎适配**：在有超时的独立子进程运行 `analyze_with_paths`，保留内部完整记录和读取文件清单；不同上下文/互斥版本不放同一目录混析。读 Query、Body、Header 与表达式，不只转换有损 JSONL。验证 13 请求、4 Query、8 Body 叶字段和非请求类型隔离。
- [x] **S1.3 来源与候选**：把引擎文件名映射回资产 URL/哈希、页面上下文。原生已归并记录只能叫引擎候选，缺行列/调用链就记缺口；不输出虚构的发送点数或调用次数。未知 Host、动态 Method 和异常 URL 不能强归并。
- [x] **S1.4 可检查输出**：产出 `analysis.json`、内部底稿、快照清单与候选/参数/资产/缺口 CSV 预览；文本表格防公式执行，长数据可回查 JSON，不静默截断。预览分组与正式 S4 统计明确区别。输出目录默认不得覆盖已有文件。
- [x] **S1.5 首轮验收**：自动化正常/反例通过；已有冻结样例回归、公开 bundle 兼容性运行；记录准确命令、结果与剩余限制。此门槛通过才称离线原型可用，不称全站/完整黑盒二已完成。

## S2：引用图与受控递归获取

- [x] **S2.1 引用发现**：复用 chunk_map/module specifier，覆盖 import、字面量动态 import、Webpack/Vite 表、内联脚本和 import map；确定引用与推测分开。产出 AssetEdge，保留父位置/类型/解析基址。
- [x] **S2.2 深度与队列**：内联 0、直接外链 1，默认补取至 3；已取得更深资产仍分析。循环/多父复用，短路径晚到重新评估，未知父链不记第一层。验证层数与队列停止原因。
- [x] **S2.3 网络范围与会话**：只请求确定静态资产，资源来源与 API Host 分离；逐跳检查重定向，认证信息不自动跨域；401/403/登录 HTML 留缺口。受控服务器核对无主动 API 请求。
已落地的边界：S2.1 复用固定引擎，Webpack 4 旧式 builder 未暴露的引用位置保留 null；Vite 没有可靠模块基址的表项只做候选。S2.3 的会话仅接受本地显式 origin 请求头，不从 HAR 复制认证。S2.4 已完成并发预算、原子 checkpoint、哈希恢复和受控较大输入验证；不代表生产大站性能或完整 S2 验收。

- [x] **S2.4 预算与恢复**：配置文件数/字节/超时/重试/并发/总时长；超限、解析失败保存部分数据，支持快照恢复。禁止截断当完整；不可访问目标不绕过网络策略。
- [ ] **S2.5 扩展上下文**：Worker/importScripts、脚本插入、source map 分别适配；原始脚本、map 和源码层数不混用。不主动注册 Service Worker。
- [ ] **S2.6 递归验收**：同一引擎对比补取前后，新增 API 可关联具体新增脚本；受控多层矩阵和独立冻结样本同时验证。

## S3：精确位置与调用上下文

- [ ] **S3.1 增强入口**：核查固定引擎归并点，必要时建立可访问增强 fork，再接主仓库可拉取版本。不修改第三方子模块后留本地孤立提交。
- [ ] **S3.2 原始位置**：底层发送 API、原始行列/偏移、wrapper 与调用方；压缩文件为主位置，map 为附加位置。未定位的继续候选，不能凭 URL 字符串匹配捏造精确绑定。
- [ ] **S3.3 请求还原**：别名、跨文件 wrapper、client/baseURL、条件 URL、参数载体、未知 spread/覆盖、同步 hook。按实例/调用上下文隔离，不将字段并集伪装一次载荷。
- [ ] **S3.4 定位验收**：共享 send 对应多接口、同接口多调用、同名非网络函数、CDN 相对 fetch、多个页面/Worker、缺模块/混淆等用例，附实际边界。

## S4：正式统计与交付

- [ ] **S4.1 分组协议**：冻结可回查的 Host/Method/路径模板规则及版本，保留 Query/条件/参数变体；未知地址、不同版本和候选不强并。
- [ ] **S4.2 三种计数**：接口组数、调用上下文数、唯一发送位置数分开；实测次数不进入静态统计。没有精确证据时不提供假计数。
- [ ] **S4.3 Excel**：统计概览、API 总表、参数、JS 资产、引用关系、分析缺口，加 JSON 底稿/快照；公式文本安全、超长数据、超行拆分与恢复可验证。
- [ ] **S4.4 交付验收**：每个统计数字可回查底层记录；候选/未知与缺口单列，来源/版本不覆盖；同 URL 不假定同版。

## S5：效果、性能与发布

- [ ] **S5.1 效果**：独立验证集报告发送点精确率/召回、参数恢复/误归属、位置正确率，附分子分母、范围和未知；不开全站百分比空头承诺。
- [ ] **S5.2 性能**：小/中/大包与多入口测时间/内存/缓存、预算停止、恢复；重复共享代码不按入口重新全量分析。
- [ ] **S5.3 可靠性**：构建与包安装、依赖/许可证、CLI 退出码、引擎失败/中断和报告一致性。冻结可复现命令后发布离线版。

## S6：浏览器接入

- [ ] **S6.1 公共 URL 输入**：仅取页面和必要静态文件，不以 URL 假定登录态；复用同一获取与分析链。
- [ ] **S6.2 浏览器资产交付**：保留页面/Worker、URL/正文/哈希，协调黑盒一 CDP 所有权，不恢复旧白盒服务。
- [ ] **S6.3 界面与现场**：进度、候选/接口、JS 引用和缺口可查看；目标 Chrome 验证登录、导航、懒加载、正文清理与权限限制；替代 API 测试不称 MV3 验收。

## 必测矩阵

| 样例 / 反例 | 验收预期 |
| --- | --- |
| 页面 → a.js → b.js → c.js → d.js，各子层有 API | 默认补到 c，d 留深度缺口；HAR 已有 d 时也分析 d |
| 多父、循环、短路径晚到 | 复用获取/解析，保留边，重新调度此前超深度引用 |
| import、Webpack/Vite 映射、脚本插入、Worker | 分项验证支持范围，动态未知不冒充已枚举 |
| CDN JS 发相对请求、同 JS 用于不同页面/Worker | 基址正确，按上下文隔离，不误拼到 CDN |
| 缺正文、403/404、200 登录 HTML、超时/超限 | 原因分别记录，不当无 API 或扫描完整成功 |
| 同名文件、同 URL 不同正文、同正文多页面 | 不覆盖版本，不丢上下文 |
| 未执行 fetch、路由字符串、普通同名 request | 前者可发现；后两者不计作已定位发送行为 |
| 共享 send 被两个 URL 调用；同接口十个调用 | 保留两个接口上下文；后者一组但十处明细 |
| baseURL、条件 URL、未知 spread、嵌套 Body/Header | 已知部分保留，改写/未知标明，不拼造完整载荷 |
| 原生导出丢字段/位置，扫描中断/恢复 | 检出适配缺口，保留部分结果与准确停止原因 |
