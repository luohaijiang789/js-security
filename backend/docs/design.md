# 产品处理链路

1. 插件以统一任务和同一CDP会话收集API、JS、页面/执行上下文、加载证据及任务状态。
2. 分类事件采用当前capture-stream-2；大正文分块，服务端完整校验并持久确认。
3. 接收端只负责保存/查询，耗时分析不进入ACK事务；当前显式ingest将已保存数据归一化并离线提取。
4. 下一工作包由已持久水位生成不可变manifest，触发分析，新增事件留给下一批。
5. 固定jshound核心处理跨文件资产与引用，静态候选和浏览器观察保守关联，保留歧义。
6. Agent对有价值缺口规划受限工具调用、提出结构建议，再由确定性核验器校验。
7. 结果保存输入/引擎/模型版本，通过查询回传插件，主表和右侧证据分别表达实测、静态、模型建议与缺口。

当前第1–3及离线第5有实现；第4/6/完整第7待实现。精确调用点与字段加工仍按独立矩阵增强，不从“已有API清单”推断已完成。

技术/进程见[架构](architecture.md)，实现交付见[模块](modules.md)，Agent见[设计](agent.md)，wire字段以[实际协议](protocol.md)为准。旧独立插件移入legacy，不参与当前产品操作流程。
