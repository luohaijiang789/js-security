# 传统前端信息收集工具链评估

核查日期：2026-10-22。重新按安全行业已有的工作流检索：浏览器经代理访问网站，代理记录真实流量，响应分析插件同步从 HTML/JS 提取接口和后续脚本，再按需补抓资源、查看来源和导出。

**本项目的默认试点入口调整为 Burp 代理 + 被动 JS 提取；BurpAPIFinder 作为专门接口收集候选，Yakit 作为平台型对照。** EASYapi、ExecEndpoints 和 jshound 保留特定用途，不再作为传统资产收集需求的默认首选。成熟的是代理与插件工作流；具体插件的提取准确率、版本兼容和外部域名覆盖仍需试点，不将历史长短等同于质量。

## 1. 最直接对应需求的既有工具

| 工具/路线 | 已实现的工作 | 使用形态 | 对本项目的判断 |
|---|---|---|---|
| Burp + [JS Miner](https://github.com/PortSwigger/js-miner) + GAP | 浏览器实际流量保存在 Proxy/Site Map；JS Miner 被动找 JS/JSON 中的 API 端点并提供静态文件导出；GAP 提取潜在链接/参数 | 浏览器正常登录操作，Burp 扩展处理响应 | **先用的采集基线**。JS Miner 的 BApp manifest 标注 Pro；只开被动分析，不开猜 source map/端点探测。静态字段是候选，非完整 Schema |
| [BurpAPIFinder](https://github.com/shuanx/BurpAPIFinder) | 监听代理响应、分析 HTML/JS 链接、保存原始请求响应与路径至 SQLite、来源关联、可选自动访问提取路径 | 加载 JAR 后，浏览器经 Burp 正常访问，插件自动处理 | **接口收集主候选**。源码有停止主动请求而继续解析已捕获响应的分支；同 Host 过滤和其他筛选需处理，不能独占资产来源 |
| [API Sword / API剑](https://github.com/PortSwigger/api-sword) | 从响应递归提取 API/JS，主动 GET/POST，关联来源 JS，写入 Burp Target sitemap | Burp 插件，设置 Scope 后边浏览边挖掘 | **功能形态非常贴合**，但属于带主动验证的收集器；当前只采集模式不能照默认设置运行。BApp manifest 为 Pro |
| [URLFinder](https://github.com/pingc0y/URLFinder) | 从页面/JS 收集 URL、继续获取 JS、支持 Cookie/Header/代理，导出 CSV/JSON/HTML | 独立命令行/可执行程序 | **离线批次/资源补抓候选**。内置 URL 一层、JS 三层及自定义层数，但会访问发现链接验证状态，不能视作纯 JS 下载器 |
| [JSFinder](https://github.com/Threezh1/JSFinder) | 页面 JS URL/子域名提取；Cookie、指定 JS 列表、结果文件；作者另有浏览器油猴脚本 | Python CLI 或 [DevTools_JSFinder](https://github.com/Threezh1/Deconstruct/tree/main/DevTools_JSFinder) 油猴脚本 | **传统轻量工具与浏览器入口参考**；主要为正则 URL 提取，不是请求方法/字段全量还原器；旧实现同源/同根域限制明显 |
| [Yakit / Yaklang](https://yaklang.com/) | MITM/History 记录流量、批量响应分析、插件处理、爬虫 JS Parse，以及 JS SSA/调用链分析能力 | 中文桌面安全工作台 + 浏览器代理 + 插件/规则 | **平台型首轮对照**。现成抓包/分析入口明确；SSA 请求字段分析不应冒充已验收的一键全站报表功能 |

补充：SpiderSuite 的官方 Interactive Crawler 文档支持 Manual Mode：用户登录、手工浏览，软件记录 API 请求/响应和 JS 资源。可作桌面交互采集候选；公开 GitHub 是发布/文档仓，本次没有扫描器源码可核实，未证明完整静态字段分析，不标为开源引擎依赖。

## 2. BurpAPIFinder：确实是边浏览边收集

固定提交 `1f298590fa03` 的关键路径：

1. `processProxyMessage()` 接收代理响应，保存待处理流量；
2. `startDatabaseMonitor()` 调度 `runAPIFinder()`；
3. HTML 用 `extractUrlsFromHtml()`，JS 等文本用 `findUrl()`；
4. 新路径写入数据模型，并记录 `isJsFindUrl`、来源 `jsFindUrl` 和原始请求/响应；
5. 可选 `HTTPUtils.makeGetRequest()` 继续访问发现路径。

**关闭主动请求不是关闭整个提取器。** 该固定源码先处理已有原始响应，再检查 `ConfigPanel.toggleButton.isSelected()`；选中后返回，跳过后续路径 GET。UI 提示是“是否开启对提取URL进行发起请求”，且选中/未选中图标和逻辑容易误读，试点必须按实际网络增量确认，不能只看按钮图案。

首轮使用：

1. 从项目 Releases 获取 JAR，Burp 的 Extensions → Installed → Add → Java 加载。
2. 用 Burp 自带浏览器打开目标站，或给现有测试浏览器配置 Burp 代理；将 Intercept 设为 off，正常登录操作。
3. 在插件中停用“对提取 URL 发起请求”，保留响应解析。
4. 同时保留 Proxy HTTP history/Site Map 与插件 SQLite/路径数据；分别查看真实调用和从 JS 发现的路径。
5. 核对自己的 CDN、跨域业务 API 和第三方 SDK。插件 `findUrl()` 明确过滤为 `subdomain.equalsIgnoreCase(host)`；发现的路径默认填写 GET，属于待访问模板，**不能当成源码已证实的 Method**。

还确认存在静态扩展名/域名过滤、3xx/404 跳过、短路径过滤和响应长度截断；这些是插件分析层行为，不代表 Burp 原始历史也丢失。保留底层历史作为对照，避免把单个插件结果误当全量资产。

## 3. API Sword：采集、递归和验证是一条链

固定提交 `119df8158eb5` 已包含 BApp manifest、源代码、英文说明及 UI：

- BApp manifest 标注 `SupportedProducts: Pro`。
- 默认 `isReqAPI=true`，携带原 Header；提取后主动 GET，非 200 时可改为 POST。
- 将结果连同来源 JS 展示，写入 Burp sitemap。
- 支持 Scope、速率、Header、自定义前缀、响应码筛选和去重。

该工具正是传统“从前端递归挖接口”的现成实现，应该列入，而不能因其不输出本项目 Excel 就忽略。但其收集 UI 主要在主动请求取得响应后填充；关闭 `isReqAPI` 会退出候选循环，**不能承诺关掉主动开关后仍能得到完整被动候选清单**。

因此，本项目默认被动流程先用 JS Miner/BurpAPIFinder；API Sword 留作另行启用主动验证时的候选，或提取其候选处理逻辑做适配。工具主动请求产生的记录不能标记成测试人员业务操作的实测。

## 4. URLFinder 与 JSFinder：独立收集器已有长期实现

URLFinder 的 `-m 2` 文档明确 URL 深入一层、JS 深入三层；`config.yaml` 支持分别设置 `urlSteps`、`jsSteps`、Header、过滤和匹配规则。结果有 Source、Status、Title 等，支持 CSV/JSON/HTML。它与本项目“三层 JS”有直接可比性，但其层计数规则仍需源码/样例核对，并需拆开“获取 JS”和“验证 API 地址”。

JSFinder 的原项目可批量读取已收集 JS 链接；作者 2020 年另提供 `DevTools_JSFinder`，通过油猴在浏览器访问时自动获取域名和接口。因此“打开网站挂一个脚本进行前端信息收集”已有多年实现。其脚本采用 DOM + 同源 JS 同步 XHR + 正则，不覆盖现代应用全部 chunk、跨域资源和动态地址，作为轻量方案而非默认完整引擎。

Packer-Fuzzer 也不能漏列：它针对 Webpack 站点提取 API/参数并有报告输出；同时集成未授权、SQL 注入等主动检测，基础模式也不能直接假定为纯采集。固定仓库最新提交为 2024-05-24，本项目只评估采集组件，不启用漏洞扫描流程。

## 5. Yakit：平台能力可复用，SSA 与一键插件需分清

官方材料提供三类直接依据：

1. History 模块保存 HTTP(S)/WebSocket 流量，支持请求参数查看、批量处理和分析器；
2. 基础爬虫有 JS Parse 开关，插件可通过 `mirrorHTTPFlow` 处理包含 JS 等静态资源在内的流量；
3. 2024 年 JS SSA 文章演示提取网络调用参数、引用关系和调用链；2026 年文档说明 JS/TS 前端、import/export、部分跨过程分析继续扩展。

这些足以将其加入现成安全平台对照，尤其适合有中文 GUI 和后续源码分析需求的团队。但本轮未取得一个已安装、已验证、能无配置生成完整前端 API 字段表的具体插件包，不把平台可编程能力等同于现成的一键功能。

## 6. 现在怎么选

| 使用目标 | 首选动作 |
|---|---|
| 浏览网页同时记录真实请求、找 JS 内未触发接口 | Burp + 被动 JS 分析；先比较 JS Miner 与 BurpAPIFinder |
| 深入递归访问发现接口并查看响应 | API Sword；其主动行为是另一个运行模式，不混入默认被动任务 |
| 无需持续人工操作，输入 URL 批量收集 JS/URL | URLFinder 与 Katana；检查范围、状态探测和层数；JSFinder 作轻量对照 |
| 中文一体化工作台，后续要写字段/调用链规则 | Yakit + MITM/History 分析，按实际插件能力验证 SSA 接入成本 |
| 想先装很轻的浏览器脚本 | FindSomething、JSFinder 油猴；EASYapi 保留为新项目候选 |
| 对已收集 JS 恢复更复杂字段 | jshound/Yak SSA 等作分析补充，依据已发现差距选择 |

本项目近期工作应是**接入既有采集结果并验证覆盖**。只有解析、来源关联和 Excel 映射的已确认差距才补开发。更深入的字段来源追踪不应阻塞先拿到可审阅的 API 资产清单。
