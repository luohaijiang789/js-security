# 模块职责与交付边界

本文列工作包，不再复制整条产品计划或算法正文。状态只在[计划](plan.md)，当前路径/依赖与未来集成接口见[架构](architecture.md)，当前实际格式见[协议](protocol.md)。下表是完成条件，不代表模块已经实现或验收。

| ID | 职责 / 输入 → 输出 | 完成条件与边界 |
| --- | --- | --- |
| C01 协议与身份 | 领域语义 → 当前格式校验、未来共享schema/例子 | 版本/身份/错误语义明确；未来TS/Python同一例子校验，不维护两套冲突定义 |
| E01 任务与目标 | 用户控制、浏览器事件 → 目标/上下文/代次与中断 | 所有网页范围、故障隔离、正常与意外分离、真实MV3；后续接Broker租约，不自行detach他人连接 |
| E02 正文与加载证据 | Network/Debugger/DOM → 内容、加载请求/initiator栈与独立观察 | 逐入口追溯、版本不覆盖、驱逐/缺正文/超限明确；原型仅Debugger，不算三入口完成 |
| E03 引用补抓 | DOM/核心线索 → 范围内获取、引用边与缺口 | 最短D0–D3、循环/多父/晚到短链，完整正文与逐跳来源校验；不探测API |
| E04 待传与版本 | 去重正文/独立观察/确认水位 → 有界待传、固定引用清单 | 保留版本/观察，排空、配额和恢复一致；未来分块/内容去重不假定已实现 |
| E05 客户端与视图 | 任务/服务结果 → 控制、资产/API/缺口与详情 | 配对失败可见、版本不兼容拒绝、候选不提升；离线可保存，历史结果不串任务 |
| S01 服务接入（当前仅本机） | HTTP → 校验命令和结果 | 当前loopback与Origin/Host/密钥校验；目标远端TLS/项目授权、大小/哈希/幂等、错误无副作用；原型/v0与未来/v1明确区分 |
| S02 对象与证据存储 | 正文分块/加载观察/栈/边 → 项目内去重、校验持久确认和待关联索引 | 路径安全、完整性、版本/重复提交；未来续传/数据库迁移需要单独验证 |
| S03 分析作业 | 固定输入+版本/配置 → 原始输出、结果和缺口 | 同一核心、不联网/不执行JS、可取消/超时、子进程回收、输入不变；失败不当空成功 |
| A01 模块索引 | AST与引用 → 资产/模块/绑定索引 | 跨文件和runtime隔离，不依赖文件名或批次顺序猜绑定 |
| A02 发送绑定 | 模块/调用 → 发送点或候选 | 同名普通函数不确认；库调用和底层传输关联，不重复计数 |
| A03 调用摘要 | 绑定/实例/条件 → 有界变体 | 两client、同wrapper两调用、跨模块和递归预算不串线 |
| A04 字段合成 | 变体/相关写入 → URL/Host/参数和影响范围 | 覆盖/删除/spread/hook有序，动态值与字段结构分开，未知不冒充完整 |
| S04 导出 | 同一结果层 → JSON/未来Excel与证据包 | 与UI同源、不丢变体/字段，不导出凭证，文本公式/超长/超行处理可验证 |

A01–A04 的具体算法和反例只见[分析设计](analysis-design.md#5-请求分析基线与目标增强)，不在此另写一套。

## 目标数据模型（尚非当前原型字段承诺）

当前 capture-0.1/result 0.5 沿用[协议](protocol.md)。正式模型在实际容量、引用闭环和绑定需求确定后冻结，不要求先把所有目标对象建成空框架。

| 对象 | 必须保留的语义 |
| --- | --- |
| Task / Context | 任务、采集代次、目标/执行上下文与导航身份；不是一个服务进程或一个URL |
| AssetContent / AssetObservation | 表示的精确哈希与字节；来源、方式、时间、上下文和script/request身份独立；同正文保留多观察 |
| AssetEdge / Snapshot | 全部父边、引用依据/基址/状态；固定清单、截止点、父快照，不只记录首次层数 |
| AnalysisRun | 固定快照+配置+核心/parser/模型版本；未来重试产生新run，不覆盖旧事实 |
| SendSite / RequestVariant | 资产表示与parser位置、绑定、调用链、实例和条件；URL不是发送点身份 |
| Evidence / Gap | 可回查资产/字段/变体；缺脚本可仅有资产级缺口，不凭空制造请求 |

未来字段还需表达 expression、valueState、presence、certainty、conditions、stage、evidence/gap 引用；事实确定度与载体结构完整性不能共用一个“成功”布尔值。实际名称与兼容策略冻结前不作为原型已支持字段。

## 后续实施任务格式

每个任务写清模块、限定用例、真实修改路径、输入/输出、依赖、正常/反例、完成标准、演示和剩余缺口。集成工作包 I1–I4 的路径、接口与验收只在[架构集成方案](architecture.md#5-黑盒一集成方案仅设计)维护；本轮不实施这些工作包。

正式 /v1 的配对、Task/Asset/Chunk/Snapshot/Run/分页/导入/导出对象是后续目标，不预先锁定一整套路由或框架。实施时应先提交机器可校验的协议例子、版本兼容和拒绝反例，再联调；不能从现有 `/v0/jobs` 推断已具备这些能力。

持续采集的下一版目标将Content与加载观察、JS请求/重定向、原始initiator和可得异步栈分别提交；远端对象存在不等于新观察已提交。协议和输入校验、按字节背压/ACK、连续小批次与依赖增量是P1工作，不是现有/v0能力，详细语义只在[架构](architecture.md#6-持续采集与远端处理目标未实现)维护。
