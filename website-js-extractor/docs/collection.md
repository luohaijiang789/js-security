# K2 引用发现与递归补取执行约定

依据[执行计划 K2](plan.md)，当前实现 K2.1–K2.4 的引用图、会话范围、并发预算及正文恢复。Worker/source map 等扩展按实际验收更新，不因一条链路可运行就勾选整个 K2。

## 引用与深度

- 复用固定 jshound 的 `imports.specifiers`、`chunkmap.analyse`，使用同一 Babel AST 补充引用位置。不执行目标脚本，也不执行其业务函数。
- HTML 的 script/modulepreload、内联模块、import map，JS 的 import/export、字面量动态 import，以及可确定 publicPath 的 Webpack、可确定模块基址的 Vite 依赖表进入确定引用。推测文件名、任意 JS 字符串、动态表达式单列，不自动下载。
- HTML 为第 0 层，其直接外链/内联模块导入为第 1 层，再依次深入。全部导入资产均分析，包括超过补取上限的已有正文；无父链的 JS 深度为 null。必要时用户可明确指定初始 JS 种子，不自动把所有已加载 JS 当第一层。
- 同上下文按最短已知引用链计算；循环、多父保留所有边，复用相同资产。新出现的短路径会重新评估此前超深度的引用；同 URL 多版本不任选一个。
- 引用行号从 1 开始、列号与 JS start/end 从 0 开始，使用 UTF-16 code units（与 Babel/浏览器一致），保留 BOM 的位移；内联 JS 同时保留局部偏移并还原 HTML 行列。旧 builder 未暴露的位置为 null，不是 API 发送点位置。API 精确位置仍属 K3。

## 补取与保存

- 默认只构图。显式启用补取并提供允许的精确 origin 后，仅取确定脚本引用；允许资源来源和 API Host 是两类信息。
- 每个重定向跳次重新检查 origin；只使用该目标 origin 显式配置的请求头，不从 HAR 自动复制 Cookie/Authorization，不把起点认证头跨域继承。保留系统代理与 TLS 校验。
- 文件数、单文件/总字节、HTTP 超时、补取总时长和有限重试均受预算约束。响应正文必须完整取得且类型符合 JS；HTML 登录页、403、错误 MIME、超限和失败分别记账。
- 每轮保存正文哈希与可恢复 collection checkpoint；恢复前验证正文哈希与路径，不联网时也可重放已有输入。恢复不会把上次未解决错误永久当作已解决。
- 补取属于运行时的新观察，不自动证明与 HAR 原快照同版；来源与获取时间保留。

## 验证顺序

先检查引用提取/import map/打包器，再检查纯图的层数、循环、多父、晚到短路径与版本歧义，最后用本地 HTTP 服务核对实际访问路径、重定向、深度截断、预算和恢复。请求日志中不得出现从 fetch/XHR 等提取的业务 API 探测。公开冻结 JS 用于兼容性检查，不把数量增长解释为全站召回提升。

原 13 请求回归的 HTML 正文固定为 `/main.js`，HAR 生成器现在使用与该 HTML 一致的同源脚本 URL；正文哈希、预期 API 和字段数量不变。CDN 模块基址和 API 请求基址分离仍由独立正常/反例测试覆盖，不用错误的 HAR 来源关系绕过引用缺口检查。

## K2.4 并发与预算实施顺序

1. 将文件尝试数、在途读取额度与累计字节计费放入同一个线程安全预算对象；读取前预留，读取后返还未用额度。失败读取无法确定消耗时保守计费，不把截断内容当脚本。
2. 按最短已知层数分批调度，每批不超过配置的并发数，同上下文/URL 只派发一次。HTTP 线程只获取资源，主线程接收完整结果、更新图并原子保存 checkpoint。
3. 同上下文的直接引用、重定向与共享子资源合并在途请求和完成结果；不同上下文不共用响应。不会因为多个父引用而重复消耗脚本配额。
4. 达到发现/获取截止时间或发生取消时不再派发新任务，停止并回收在途任务，保存已完成正文后返回部分结果；已进入连接/头部读取的任务受剩余 socket 超时约束，不能宣称能强制中断任意系统 DNS 阻塞。
5. 验证配额竞争、重试、慢响应、失败与恢复；再以更宽的引用图、较大正文及冻结公开 JS 验证串行/并发的语义结果与成本。公开样例不作为全站召回或生产压力保证。

预算指应用读取的正文与保守计费，不等于网卡流量（HTTP 头和 socket 已缓冲数据不计入）。未知长度正文恰好耗尽额度、无法证明 EOF 时宁可记缺口；只有完整正文进入快照。断点恢复重用已校验正文，不承诺恢复部分 HTTP 字节。


实现入口：`ReferenceGraph` 按层选择不超过 `--fetch-concurrency` 个不同上下文/URL，`StaticFetcher` 在锁内预留文件尝试与读取额度。每线程使用独立 urllib opener，保留系统代理/TLS；相同上下文的重定向最终正文由 Future 共享。主线程接收完成结果并原子写 checkpoint；停止后回收线程，保留完成正文，不保存半截脚本。

本轮统计由[协议 0.4](protocol.md)定义，恢复只复用正文，不累加上轮网络计数。自动化反例见[并发测试](../tests/test_concurrency.py)，冻结公开正文与较宽引用图的验证入口见[较大输入检查](../tests/check_collection_load.py)。这些验证不代替不同正文的大型网站、登录态或 Chrome 插件现场验收。

## K2.5 扩展上下文实施顺序

1. 先适配 Worker/SharedWorker 的明确构造引用（字面量或 `new URL(..., import.meta.url)`），保留类型、构造位置和基址依据。绑定遮蔽、动态路径/类型、blob/data 均不作为可补取目标；不注册 Service Worker。
2. 为每个创建位置建立独立静态推断上下文，保留创建者与原页面；Worker 主脚本最终 URL 作为请求基址。`importScripts` 仅在 classic Worker 中补取，使用 Worker 主脚本基址；模块 import 使用当前模块 URL，不继承页面 import map。嵌套 Worker、循环、深度与获取预算继续约束。
3. 已导入正文可在版本无歧义时显式关联到 Worker 上下文，保留原始观察及关联证据，不将 HAR pageref 当真实执行证明；多个版本不任选。网络获取仍按上下文隔离，checkpoint 恢复必须保留上下文身份。
4. 动态脚本只提升经过 AST 绑定验证的常见直线创建/设 src/插入模式；普通 `.src`、别名逃逸、重复写入、动态表达式保留候选。页面 DOM 引用不在 Worker 中冒充有效调用。
5. source map 另建源码证据，不把 map/sourcesContent 直接作为执行脚本分析，也不沿任意 sources URL 下载；压缩 JS 保留主身份，源码位置由后续精确定位验收。本阶段分步交付，未完成 source map 与对应冻结样本前 K2.5 保持未勾选。
6. 正常/反例核对页面/CDN/Worker 三种基址、经典/模块 Worker、同正文多上下文、重定向、循环、恢复与无业务 API 探测；冻结公开 Worker 样本用于兼容性运行，不声称全站召回。
