# 实施计划与当前状态

更新：2026-11-02。本文件是唯一进度入口；目标是增强黑盒一作为唯一采集/展示插件，黑盒二提供远端接收/存储/关联/持续解析，CLI 是核心调试/重放入口；本机服务保留为可选部署。直接复用黑盒一建设统一链路，不再先发布独立黑盒二插件。用户已授权改造黑盒一，本轮开始运行代码增强；不部署远端。

## 2. 唯一实施顺序

### P1：统一采集端与远端协议（当前实施优先级）

- [ ] 按I1先抽黑盒一共享会话并回归原请求能力，再按I2接入JS消费者、按I3接入静态仓/远端客户端/现有工作台；保留旧任务和字段选择，不新增生产插件工程。
- [ ] 把ObservedRequest与JS内容/加载观察/栈分别建模，冻结重传去重、上下文关联和实测/静态来源隔离的正反例。

- [ ] 冻结下一版正文/观察/JS加载请求/initiator栈/边/确认水位协议，补完整输入与乱序/歧义反例；现有capture-0.1只作旧输入兼容，不冒充增量协议。
- [ ] 插件采集Network加载证据并与Debugger源码关联，趁会话有效解析可得异步父栈；保留目标/导航/重定向代次、表示差异和缺失，不能只凭URL绑定。
- [ ] 建正文按哈希存储、观察独立引用的本地有界待传缓存；快照改为引用清单，上传确认前不得清理正文，写盘/上传同样有字节背压。
- [ ] 增加授权HTTPS远端服务配置、项目级隔离、对象存在性协商、分块哈希校验/持久确认、幂等事件提交与断线恢复；不把当前loopback开发服务直接对外开放。
- [ ] 远端收到完整正文即解析、持续返回版本化候选和缺口；先验证有界分批适配，再建跨文件索引和受影响重分析，缺依赖保持待补全，不为每个新文件全量重跑。
- [ ] 用多MiB单文件、重复正文跨页面及更大唯一正文总量验证浏览器内存、待传/服务积压、丢确认/断线、恢复、源版本与上下文隔离；停止前无需等待全站采集完才能看到结果。

- [ ] 在允许自定义扩展的目标 Chrome 按[使用说明](plugin.md)加载构建，记录实际 Chrome/OS、版本、任务、日志与失败。
- [ ] 核对现有网页/新网页、导航、登录资源、暂停恢复、后台重启、关闭管理页、快照和服务配对；连接被占用时不抢占。
- [ ] 对 iframe/Worker/SharedWorker/Service Worker 逐类记录已取得/缺正文/基址未知；修正实际可复现缺陷，不把未知升级为已覆盖。
- [ ] 真实插件→授权分析服务→同一核心→持续候选/缺口/JSON 整链通过；普通 CDP 或 UI 检查不代替此项。

退出条件：持续采集/去重上传/确认/持续解析的限定矩阵和真实 MV3 证据齐全；未支持项在界面和导出可见。Windows 11/Chrome 125+ 仍是目标运行组合，最低 API 版本不是现场支持证明。

### P2：引用补抓闭环

- [ ] 对照 DOM、Network 正文与 Debugger 源码，保存表示来源、文档/导航代次及关联缺口，不混同正文。
- [ ] 远端对固定事件水位的发现批次返回确定引用；插件核对来源、重定向、最短 D0–D3 和预算后补取，形成新快照，不修改旧输入。
- [ ] 验证离线等待、鉴权/登录 HTML、循环/多父、短链晚到、未知父链、已观察深层资产、跨来源头部隔离和停止/恢复。
- [ ] 以同一引擎对比补抓前后，新增候选能关联新增脚本；冻结独立样本和人工预期后验收，不能只比较候选数量。

退出条件：受控图允许预算内的确定脚本取得完整正文，禁止 API 探测和动态路径猜测下载。CLI 的 HTTP 补取只作参考，不直接搬进本机服务。

### P3：统一链路回归与原型退役（本轮不实施）

I1–I3 是P1/P2增强黑盒一时的工作包，不再另建独立插件后才迁入；此阶段重点是统一链路验收与旧原型退役，当前仍未实施。具体设计见[架构](architecture.md#5-黑盒一集成方案仅设计)：

- [ ] 对P1/P2形成的I1–I3统一链路执行单独/同时运行、分别暂停/停止、导航、背压、服务故障与来源隔离矩阵，回归黑盒一原采集/保存/导出。
- [ ] I4 在允许加载扩展的目标Chrome记录真实权限/后台/配对/上传/查询全链证据，通过前不默认启用新功能。
- [ ] 统一功能与数据兼容验收后退役旧独立采集原型，保留回归材料和用户主动导入路径，不先删除源码或数据库。

退出条件：单插件同时支持真实请求和 JS 静态分析；旧任务不丢、不自动扩范围，两类证据不混算。首段本地采集实现不等于完整集成完成。

### P4：精确提取与正式交付

- [ ] 建立可访问增强 fork 并锁定补丁；先核查上游归并和信息丢失点，不用外围拼接伪造位置。
- [ ] 按模块/词法绑定定位发送点，隔离两 client、共享 wrapper 的多次调用及条件，追踪 URL/Host/四载体的覆盖、删除和 hook。
- [ ] source map 作为附加位置证据，执行 JS、map 和源码不共用获取层数，不重复计数。
- [ ] 冻结分组规则，分别统计接口组、调用上下文、唯一发送位置；保留候选/未知和版本变体。
- [ ] 正式 Excel、JSON 和证据包同源，长内容、文本公式、超行拆分和记录回查通过。

退出条件：受支持矩阵的确定结果具有绑定、位置和逐字段依据；准确率/召回附范围与分子分母。

### P5：稳定发布与共享核心

- [ ] 先冻结公开开发集、独立盲测与指标门槛，再运行盲测；不为通过改变样本或预期。
- [ ] 按目标机器核验时间/内存、1/10/100 入口共享代码、配额/断线/取消/重启与升级恢复。
- [ ] 如确有需要，再落地正式 v1、类型生成、分块续传和存储迁移；不以更换框架代替正确性验证。
- [ ] 干净 Windows 目标机器验证安装、启动/配对、自检、版本不兼容、离线重放及许可，记录支持范围。
- [ ] 白盒接入同版构建资产并单独验收构建、环境追溯和源码关联。

## 本轮实施清单：统一插件的首个采集闭环

- [x] 为新任务增加默认关闭的持续JS采集选项，旧任务行为不变。
- [x] 在Recorder现有CDP会话接入scriptParsed、执行上下文与Script网络加载证据，不另行attach；JS不受请求Filter筛除。
- [x] 独立IndexedDB存哈希正文与独立观察，顺序读取、单文件/总正文/元数据预算；不截断源码、不自动清理未确认内容，满额暂停JS并登记缺口。
- [x] 在原工作台查看待传观察与按需源码，暂停/停止等待已接受的JS读取及写入；任务删除同时清理其JS引用。
- [x] 验证去重、多MiB、加载证据、失败/预算和原请求回归；记录实际MV3限制。

本轮不会宣称已接通远端：分块上传、ACK、服务端持续分析、精确Network↔script关联和独立功能租约另行实施。正文是Debugger解析后的文本，不能冒充HTTP原始响应字节。

实现说明：`browser-extension/src/js-capture.ts`是现有Recorder的消费者，没有第二次attach；JS单独的顺序异步队列最多64事件/4 MiB，避免等待读源阻塞请求事件处理。`js-store.ts`使用独立`js-security-js-outbox`数据库v1，旧请求库v2不变；正文对象与引用元数据分开，重复正文不从IndexedDB整份读回再改引用。正文跨任务按SHA-256去重，只有用户显式删除任务才回收其独占对象。源码与Network事件目前保持独立，`network_match=unknown`；没有创建精确关联。子目标记录可取得的target_id，根目标未知保持null。

当前边界：JS与请求共用同一任务的暂停/恢复/停止，不具备独立租约。JS背压/写盘失败后本任务不自动重试，任务缺口与JS面板显示原因；停止、导出并清理后重新建任务。缺正文保留source_unavailable/source_over_budget/source_session_changed；正文按需读取，预览截断不影响下载全文。事件按目标代次和递增序号稳定分页，不保证跨目标全局时间顺序，time保留供后端处理。未实现ACK、远端发送、静态解析或引用补抓，不承诺全站全量覆盖。

自动化记录（2026-11-02）：`npm test`含构建与18个测试文件、166项测试全部通过；新增9项逻辑/存储测试、1项真实Chromium CDP测试、1项工作台UI测试。CDP样本含两个URL加载同一3 MiB正文，验证两次源码观察/两次加载请求、一份正文、导航/帧信息及原请求持久化；单元样本另含3 MiB中文、Filter独立、跨会话、重定向、失败、队列预算、事务预算和分页。UI替代了扩展API，不能证明MV3。`npm run test:extension`被当前企业策略ExtensionInstallBlocklist=["*"]拒绝，未绕过，真实MV3现场仍未验收。较大唯一正文总量、真实RSS峰值、长时间浏览和浏览器重启恢复仍待性能/现场验证。
