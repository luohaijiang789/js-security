更新：2026-10-30。本文件是黑盒二 Website JS Extractor 的唯一进度清单，覆盖分析核心、命令行、插件和 HTTP 服务。现有核心和命令行可运行，插件与 HTTP 服务尚未实现。产品阶段 S0–S5 与核心任务 K0–K6 在本文件统一维护；按实际代码、测试和冻结样本证据勾选。工程见[架构](architecture.md)，模块输入输出和完成条件见[模块规格](modules.md)。

## 模块落地顺序

原型完成不表示整个模块完成。每项实现按模块规格拆成可独立复核任务，记录用例、路径、依赖、输入输出、测试及演示；不以文件夹或接口空返回作为交付。

## 打勾规则

实现项必须同时有代码进入主干、正常及反例自动化测试、该项要求的冻结样本验证、实际边界文档。浏览器能力还需目标 Chrome 现场证据。设计项可以在评审冻结后单独完成，不能因此勾选实现项。部分完成保持未勾选；不以候选数、缩小范围或降低预期冒充效果提升。

## 统一工程迁移顺序

用户已明确要求黑盒二只有一个工程目录。本轮先把已有分析代码、测试和依赖定义迁入 `website-js-extractor/`，统一 Python 包与命令为 `website_js_extractor` / `website-js-extractor`；合并两份进度清单，已有核心任务使用 K0–K6 编号，产品阶段继续 S0–S5。随后整理文档入口与架构路径，删除旧工程及重复计划；运行全部测试、冻结样本回归和新环境安装验证后提交主干。插件、HTTP 服务、精确绑定及正式统计的未完成状态保留，不因目录合并升级。

迁移验证：统一包在新虚拟环境安装后 70 项测试通过；冻结 API/公开 bundle、Webpack/Vite、Worker 和递归恢复回归通过。统一名称的 wheel 在另一新环境安装，命令行恢复旧 0.4 Worker checkpoint 成功，13 请求基线保持；208 个主仓自有 Markdown 本地链接检查通过。日志为 `work/blackbox2-tools/logs/unify-*`，复现命令按[使用说明](usage.md)执行。旧工程目录与根目录中的独立分析设计/计划已移除，入口统一到本工程。

## 分析核心实施任务与验证记录

以下 K0–K6 任务与上面的产品 S0–S5 属于同一工程：已实现的命令行入口调用本工程分析核心，后续 HTTP 服务继续调用该核心。K 任务用于保留已有验证证据，不因命令行可运行而勾选浏览器、HTTP、精确绑定或正式统计门槛。旧任务编号 S0–S6 在这里统一改为 K0–K6；旧工程和独立计划已移除。当前 70 项自动化测试通过；下一项为 K2.5 的 source map。

### K0：工程、协议与样本

- [x] **K0.1 工程**：建立 `website-js-extractor/`，Python CLI 调用固定 jshound；工程依赖独立，错误版本必须停止，不混入插件依赖。产出 pyproject、引擎锁定信息、使用说明。验证安装、CLI 帮助、缺依赖/错版本错误及冻结样本运行。
- [x] **K0.2 协议**：定义 Task、Context、Asset、EngineRecord、RequestCandidate、ApiGroupPreview、Gap；标明文件证据与精确发送点的区别，冻结 schema 0.1。产出协议文档与实际 JSON；验证未知、缺失、失败及版本关联反例。
- [x] **K0.3 现有基线清单**：引用已冻结 13 请求样例、压缩样例及 Swagger UI Commit/哈希，说明公开 bundle 无召回真值。验证主流程可读这些输入且不丢原始字段；不将其称独立盲测集。
- [ ] **K0.4 独立验证集**：另选公开部署样本，冻结版本、获取方法、人工发送点/参数和标注范围，分开发集与独立验证集。无真值的样本只做兼容性验证。

### K1：首个可运行里程碑——已有资产的离线分析

- [x] **K1.1 导入快照**：目录保存相对文件身份；HAR 只导入 HTML/JS，不将流量 API 响应当静态接口；处理 UTF-8/Base64、缺正文、状态/类型和同 URL 多版本。正文按哈希保存，原始输入不改写。验证正常 HAR、缺正文/无效 Base64/登录 HTML、同名/同 URL 不同正文、空目录与路径穿越。
- [x] **K1.2 引擎适配**：在有超时的独立子进程运行 `analyze_with_paths`，保留内部完整记录和读取文件清单；不同上下文/互斥版本不放同一目录混析。读 Query、Body、Header 与表达式，不只转换有损 JSONL。验证 13 请求、4 Query、8 Body 叶字段和非请求类型隔离。
- [x] **K1.3 来源与候选**：把引擎文件名映射回资产 URL/哈希、页面上下文。原生已归并记录只能叫引擎候选，缺行列/调用链就记缺口；不输出虚构的发送点数或调用次数。未知 Host、动态 Method 和异常 URL 不能强归并。
- [x] **K1.4 可检查输出**：产出 `analysis.json`、内部底稿、快照清单与候选/参数/资产/缺口 CSV 预览；文本表格防公式执行，长数据可回查 JSON，不静默截断。预览分组与正式 K4 统计明确区别。输出目录默认不得覆盖已有文件。
- [x] **K1.5 首轮验收**：自动化正常/反例通过；已有冻结样例回归、公开 bundle 兼容性运行；记录准确命令、结果与剩余限制。此门槛通过才称离线原型可用，不称全站/完整黑盒二已完成。

### K2：引用图与受控递归获取

- [x] **K2.1 引用发现**：复用 chunk_map/module specifier，覆盖 import、字面量动态 import、Webpack/Vite 表、内联脚本和 import map；确定引用与推测分开。产出 AssetEdge，保留父位置/类型/解析基址。
- [x] **K2.2 深度与队列**：内联 0、直接外链 1，默认补取至 3；已取得更深资产仍分析。循环/多父复用，短路径晚到重新评估，未知父链不记第一层。验证层数与队列停止原因。
- [x] **K2.3 网络范围与会话**：只请求确定静态资产，资源来源与 API Host 分离；逐跳检查重定向，认证信息不自动跨域；401/403/登录 HTML 留缺口。受控服务器核对无主动 API 请求。
已落地的边界：K2.1 复用固定引擎，Webpack 4 旧式 builder 未暴露的引用位置保留 null；Vite 没有可靠模块基址的表项只做候选。K2.3 的会话仅接受本地显式 origin 请求头，不从 HAR 复制认证。K2.4 已完成并发预算、原子 checkpoint、哈希恢复和受控较大输入验证；不代表生产大站性能或完整 K2 验收。

- [x] **K2.4 预算与恢复**：配置文件数/字节/超时/重试/并发/总时长；超限、解析失败保存部分数据，支持快照恢复。禁止截断当完整；不可访问目标不绕过网络策略。
- [ ] **K2.5 扩展上下文**：Worker/importScripts、脚本插入、source map 分别适配；原始脚本、map 和源码层数不混用。不主动注册 Service Worker。
- [ ] **K2.6 递归验收**：同一引擎对比补取前后，新增 API 可关联具体新增脚本；受控多层矩阵和独立冻结样本同时验证。

### K3：精确位置与调用上下文

- [ ] **K3.1 增强入口**：核查固定引擎归并点，必要时建立可访问增强 fork，再接主仓库可拉取版本。不修改第三方子模块后留本地孤立提交。

- [ ] **K3.4 定位验收**：共享 send 对应多接口、同接口多调用、同名非网络函数、CDN 相对 fetch、多个页面/Worker、缺模块/混淆等用例，附实际边界。

### 必测矩阵

| 样例 / 反例 | 验收预期 |
| --- | --- |
| 页面 → a.js → b.js → c.js → d.js，各子层有 API | 默认补到 c，d 留深度缺口；HAR 已有 d 时也分析 d |
| 多父、循环、短路径晚到 | 复用获取/解析，保留边，重新调度此前超深度引用 |
| import、Webpack/Vite 映射、脚本插入、Worker | 分项验证支持范围，动态未知不冒充已枚举 |
| CDN JS 发相对请求、同 JS 用于不同页面/Worker | 基址正确，按上下文隔离，不误拼到 CDN |
| 缺正文、403/404、200 登录 HTML、超时/超限 | 原因分别记录，不当无 API 或扫描完整成功 |
| 同名文件、同 URL 不同正文、同正文多页面 | 不覆盖版本，不丢上下文 |
| 未执行 fetch、路由字符串、普通同名 request | 前者可发现；后两者不计作已定位发送行为 |
| 共享 send 被两个 URL 调用；同接口十个调用 | 保留两个接口上下文；后者一组但十处明细 |
| baseURL、条件 URL、未知 spread、嵌套 Body/Header | 已知部分保留，改写/未知标明，不拼造完整载荷 |
| 原生导出丢字段/位置，扫描中断/恢复 | 检出适配缺口，保留部分结果与准确停止原因 |

每项同时具备代码、正常/反例自动化验证、所需冻结样本验证和实际限制记录后才勾选。设计完成不等于实现完成。

受控矩阵可静态恢复的预期必须全部满足。误归属、候选混算、静默丢字段或错误归并明细阻止阶段验收。公开样本报告人工标注范围内发送点召回/精确率、参数恢复/错误率、位置正确率、耗时/内存，附分子分母；无真值范围单列未知，不虚设全站覆盖率，不通过缩小输入或放宽预期改善结果。
