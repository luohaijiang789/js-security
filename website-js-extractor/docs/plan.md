# 实施计划

更新：2026-10-29。本文件是黑盒二唯一实现进度清单。当前只有方案文档，无可运行插件/服务；以下均未验收。工程及语言见[工程架构](architecture.md)，每个模块的输入输出、实现动作和完成条件见[模块规格](modules.md)。先验证浏览器采集和 jshound，再实现完整产品，不先搭空框架。

## 阶段效果

| 阶段 | 必须交付 | 能向用户演示的效果 | 过关后再做什么 |
| --- | --- | --- | --- |
| S0 工程与原型输入 | 技术栈、模块边界、最小协议、人工预期和固定版本 | 明确每个模块交付什么、如何连接及怎样判正确 | 做真实采集原型 |
| S1 浏览器采集原型 | 最小 MV3 收集器、上下文/资产快照与故障清单 | 在登录页面取得 JS，展示来源、哈希、引用与漏项 | 冻结同一输入跑分析基线 |
| S2 jshound 基线与改造验证 | 原始结果、逐发送点差距、关键增强验证和正式 v1 协议 | 证明核心复用范围，验证变体隔离与绑定改造可行 | 按验证结果实现最小链路 |
| S3 最小产品 | 正确性最小矩阵、工作台、本机服务、冻结分析、JSON/Excel | 正常操作页面后，一次生成能回查且调用不串线的四项主表 | 增强复杂调用与加工 |
| S4 复杂请求恢复 | 五层/循环 wrapper、复杂 SDK、hook/序列化和缺口 | 深层代码与复杂追加/修改字段可还原且不串线 | 独立样本与发布验收 |
| S5 稳定发布 | 盲测、性能、故障恢复、目标 MV3 验收材料 | 可重复分析真实限定范围，效果与成本有实际分母 | 让白盒接入已验证核心 |

## 模块落地顺序

| 阶段 | 模块工作包 | 可复核产物 | 进入下一阶段的条件 |
| --- | --- | --- | --- |
| S0 | C01 最小协议、工程决策、样本预期 | schema/例子、版本清单、人工预期、试点机配置 | 采集与核心原型有明确输入输出，不要求提前实现产品 |
| S1 | E01/E02/E04 原型、E03 基础补抓 | 可加载原型、固定资产包、真实 MV3 记录 | 取得可校验输入并如实记录漏项 |
| S2 | A01–A04 原始基线、关键改造试验、S03 命令入口、C01 正式 v1 | 可复跑命令、逐案例差距、fork补丁、协议与性能门槛 | 绑定确认、调用隔离及字段追踪有通过/失败证据，可确定改造范围 |
| S3 | E01–E05、S01–S04、A01–A04 最小能力 | 可安装/启动工程、端到端样本、三种导出 | 最小正确性矩阵通过，输入/结果/证据可复核 |
| S4 | A01–A04 复杂能力、E03 bundler补抓 | 冻结复杂样本、字段加工证据及缺口 | 五层、条件、实例、hook等限定矩阵达标 |
| S5 | 全模块恢复/发布、共享核心输入验证 | 发行包、安装说明、盲测/性能/MV3材料 | 预先冻结门槛通过，另一台目标机器可复现 |

原型完成不表示整个模块完成。每项实现按模块规格拆成可独立复核任务，记录用例、路径、依赖、输入输出、测试及演示；不以文件夹或接口空返回作为交付。

## S0：冻结工程与原型输入

- [ ] 评审[需求](requirements.md)、[整体设计](design.md)、[工程架构](architecture.md)、[模块规格](modules.md)、[共享范围](../../docs/js-analysis-scope.md)和[验收规则](testing.md)，冻结原型范围。
- [ ] 确认 TypeScript/Vue 插件、Python 服务、Node/Babel 核心及独立工程目录；核对 Windows 试点机、Python/Node安装和目标Chrome。
- [ ] C01 建立最小 Task/Context/AssetContent/AssetObservation/AssetEdge/Snapshot/AnalysisRun/SendSite/RequestVariant/Evidence/Gap schema与正反例；明确状态、身份和本机路由，S2后冻结正式v1。
- [ ] 冻结受控站点、公开开发集和独立盲测集的范围、版本、哈希与人工预期。
- [ ] 固定 jshound 上游 Commit、浏览器最低版本与试点机器；明确补抓范围和预算。
- [ ] 将最小矩阵逐项写成人工预期：直接请求、SDK自发、同名非网络函数、两实例、同封装两调用、跨文件封装、字段覆盖删除及动态未知。

## S1：浏览器采集原型

- [ ] 建立只覆盖基础脚本/字面量引用的最小独立 MV3 原型（复杂 bundler 补抓后续按基线差距增强），自动接入所有窗口 HTTP/HTTPS 网页及新建/导航，跳过内部页。
- [ ] 对照 DOM、Network 正文、Debugger 源码三种入口，验证当前快照与后续加载；记录表示差异。
- [ ] 建立 frame/target/context 与导航代次；逐类核验 iframe、Worker/SharedWorker/Service Worker 的覆盖和缺口。
- [ ] 建 D0–D3 引用与补抓队列，验证循环、多父、未知父链、已观察深层资产及超层停止。
- [ ] 验证登录资源、权限/策略、缓存/正文丢失、版本变化和超限状态。
- [ ] 真实加载扩展，测试黑盒一/DevTools 干扰与连接分离；不抢占已有连接。
- [ ] 交付原型构建/加载步骤、冻结包生成命令或操作入口、自动化正反例和目标Chrome记录；实测采集预算。

## S2：验证 jshound 基线

- [ ] 在同一冻结脚本快照运行原生完整目录模式，保存命令、版本、原始结果、耗时和内存。
- [ ] 核对直接请求、SDK 自发、多层引用/封装和字段增删覆盖的逐发送点差距。
- [ ] 验证 Webpack/Vite、module index、wrapper、source map 及页面配置实际边界。
- [ ] 检查结果归并/导出是否丢失调用者或字段差异，确定原始证据层与适配边界。
- [ ] 建立可访问增强 fork，固定补丁/许可证；据实冻结性能、公开样本数值验收门槛。
- [ ] A01/A02 验证模块身份与发送绑定；不明URL调用保留候选，同名非网络函数不得进入确定结果。
- [ ] A03/A04 用两client、同wrapper两调用和字段覆盖删除验证增强路径，检查上游索引/归并有无不可逆信息丢失；记录需修改的具体函数与预期。
- [ ] C01 冻结正式v1及TS/Python类型生成/校验流程；S03提供同一快照的discover/analyze可复跑入口，保存上游原始结果与项目事实差异。
- [ ] 明确各模块剩余工作包、依赖和估算依据；核心试验失败时先修订方案，不用UI集成掩盖分析缺口。

## S3：最小可用产品

- [ ] 实现独立工作台：任务、资产引用、API 主表、右侧详情和缺口视图。
- [ ] 实现本机服务配对/能力协商、持久任务、分块幂等续传及不可变 snapshot。
- [ ] 接入引用发现、范围内补抓与离线完整目录分析，输出四项及逐字段状态。
- [ ] E03/E04/S03实现发现快照→引用队列→补抓→新快照闭环；每轮输入不可变，离线时明确等待服务的复杂发现项。
- [ ] A01–A04通过最小正确性矩阵：fetch/XHR/Axios/beacon、依赖自发、已支持ESM/打包模块、基本跨文件wrapper、两client隔离、同封装两调用、URL/baseURL、四载体与简单字段覆盖/删除；未知影响定向降级。
- [ ] 实现开始/暂停/恢复/停止、排空/超时、服务不可用时离线任务包；进度持续可见。
- [ ] 实现 JSON、Excel 和证据包；最小矩阵可确定正例及反例均通过，结果全部可回查。
- [ ] 验证无主动调用提取 API、无业务脚本执行；缺块/空结果/未完成状态不混淆。
- [ ] 交付端到端启动、自检、任务包导入与固定快照重跑入口；主表/详情/导出同源，故障和候选不能提升为完整成功。

## S4：嵌套与请求加工

- [ ] 增强打包模块、动态 import、Worker 及缺 map/部分 map 的归属与已知字段恢复。
- [ ] 在S3基本跨文件wrapper和实例隔离之上，增强5层、工厂/闭包与循环wrapper的有界摘要追踪，预算耗尽不伪装精确结果。
- [ ] 在S3四载体基础上，增强条件Host、对象别名/分支写入、嵌套字段与重复键序列化。
- [ ] 增强库版本相关默认值与可证明顺序的hook；未知spread/副作用/异步注册定向降级。
- [ ] 验证 L0/L1 与 L2/L3 降级，严重调用/实例/位置误归属为 0。

## S5：稳定性、独立验收与白盒接入

- [ ] 完成浏览器/服务重启、配额耗尽、断传、取消、单页失败及预算中断恢复验证。
- [ ] 验证增量缓存与上下文失效；完成 1/10/100 入口共享依赖、深度和分支性能测试。
- [ ] 独立盲测达到事先冻结门槛，报告真实分子/分母、失败资产、时间和内存。
- [ ] 在目标 Chrome 真正加载 MV3 扩展完成现场验收；替代 API 测试不算此项。
- [ ] 默认版本交付插件、服务、安装/使用说明、许可、已验证边界和遗留缺口。
- [ ] 在干净Windows目标环境验证显式依赖安装、启动/配对/自检、断线/重启、离线包导入、版本不兼容与数据库升级恢复；记录实际Chrome版本。
- [ ] 将同版仓库正式构建资产接入共享协议，比较四项结果；白盒单独验收构建、环境追溯和源码关联。

AI 封装建议、字段释义与远端服务不阻塞首版，核心通过后另列增量任务；不默认上传脚本到模型。

## 打勾规则

实现项必须同时有代码进入主干、正常及反例自动化测试、该项要求的冻结样本验证、实际边界文档。浏览器能力还需目标 Chrome 现场证据。设计项可以在评审冻结后单独完成，不能因此勾选实现项。部分完成保持未勾选；不以候选数、缩小范围或降低预期冒充效果提升。
