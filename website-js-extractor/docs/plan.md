# 实施计划

本文件维护黑盒二的进度。当前先做设计与基线验证，白盒分析核心不另起实现。

## S0：冻结设计与输入

- [ ] 评审[共享提取范围](../../docs/js-analysis-scope.md)，冻结分层、起点、路由与发送位置的记录语义。
- [ ] 冻结网站输入、页面/脚本范围、会话和预算配置。
- [ ] 冻结资产、引用边、页面上下文、发送点、请求变体和缺口协议，与白盒协议对齐。
- [ ] 冻结受控站点与公开部署样本快照、哈希、人工发送点及四项预期。

## S1：验证分析基线

- [ ] 对相同冻结脚本目录运行原生 jshound，保存版本、命令、原始输出、耗时和内存。
- [ ] 核对直接请求、SDK 自发请求、多层引用/封装和发送前增删覆盖，记录逐发送点差距。
- [ ] 验证 Webpack/Vite 模块、懒加载、Worker、无 map/部分 map、页面配置和相对地址。
- [ ] 根据实测确定增强 fork、收集适配器及分析核心边界，不先建空框架。

## S2：最小网站链路

- [ ] 实现页面与脚本快照、三层引用工作队列、哈希和失败/超限记录。
- [ ] 接入发送点识别与定向反向追踪，输出四项 JSON 和用户主表。
- [ ] 区分调用构造、默认值合成和 hook 后候选；不合并不同调用者、实例或互斥参数。
- [ ] 用反例验证同名非网络函数、未知 spread、动态 Host、缺脚本及上下文误归属。
- [ ] 验证收集流程不主动调用提取出的 API；空结果与未完成分析分别返回状态。

## S3：独立验收与白盒接入

- [ ] 在未参与规则开发的冻结样本上核对发送点和参数字段，报告真实分子/分母及缺口。
- [ ] 验证循环、多父、三层以上引用截断、缓存和资源预算；候选数不作为召回率。
- [ ] 将同版仓库构建资产接入已验证核心，比较 URL、Host、参数和 JS 归属。
- [ ] 白盒独立完成正式构建、构建环境与源码关联验证后，再标记其对应计划完成。

实现项只有在代码、正常及反例自动化测试、冻结样本验证均完成后才能勾选。只完成设计或部分场景保持未勾选；第三方工具能力不能当作本工程已实现。
