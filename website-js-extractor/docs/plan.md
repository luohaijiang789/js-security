# 实施计划

更新：2026-10-29。本文件是黑盒二唯一实现进度清单。当前只有方案文档，无可运行插件/服务；以下均未验收。先验证浏览器采集和 jshound，再实现完整产品，不先搭空框架。

## 阶段效果

| 阶段 | 必须交付 | 能向用户演示的效果 | 过关后再做什么 |
| --- | --- | --- | --- |
| S0 设计与样本冻结 | 范围、协议、人工预期和固定版本 | 明确收什么、从哪找、怎么计层及怎样判正确 | 做真实采集原型 |
| S1 浏览器采集原型 | 最小 MV3 收集器、上下文/资产快照与故障清单 | 在登录页面取得 JS，展示来源、哈希、引用与漏项 | 冻结同一输入跑分析基线 |
| S2 jshound 基线 | 可复跑命令、原始结果、逐发送点差距、增强位置 | 证明哪些四项已能恢复、哪些场景会漏或串线 | 按差距实现最小链路 |
| S3 最小产品 | 插件工作台、本机服务、冻结分析、JSON/Excel | 正常操作页面后，一次生成能回查 JS 的 API 主表 | 增强复杂调用与加工 |
| S4 复杂请求恢复 | 多层 wrapper、SDK、实例、hook/序列化和缺口 | 深层代码与追加/修改字段可还原且不串线 | 独立样本与发布验收 |
| S5 稳定发布 | 盲测、性能、故障恢复、目标 MV3 验收材料 | 可重复分析真实限定范围，效果与成本有实际分母 | 让白盒接入已验证核心 |

## S0：冻结设计与输入

- [ ] 评审并冻结[需求](requirements.md)、[整体设计](design.md)、[共享范围](../../docs/js-analysis-scope.md)和[验收规则](testing.md)。
- [ ] 冻结 Task/Context/Asset/AssetEdge/Snapshot/SendSite/Request/Gap schema、状态及本机协议。
- [ ] 冻结受控站点、公开开发集和独立盲测集的范围、版本、哈希与人工预期。
- [ ] 固定 jshound 上游 Commit、浏览器最低版本与试点机器；明确补抓范围和预算。

## S1：浏览器采集原型

- [ ] 建立只覆盖基础脚本/字面量引用的最小独立 MV3 原型（复杂 bundler 补抓后续按基线差距增强），自动接入所有窗口 HTTP/HTTPS 网页及新建/导航，跳过内部页。
- [ ] 对照 DOM、Network 正文、Debugger 源码三种入口，验证当前快照与后续加载；记录表示差异。
- [ ] 建立 frame/target/context 与导航代次；逐类核验 iframe、Worker/SharedWorker/Service Worker 的覆盖和缺口。
- [ ] 建 D0–D3 引用与补抓队列，验证循环、多父、未知父链、已观察深层资产及超层停止。
- [ ] 验证登录资源、权限/策略、缓存/正文丢失、版本变化和超限状态。
- [ ] 真实加载扩展，测试黑盒一/DevTools 干扰与连接分离；不抢占已有连接。

## S2：验证 jshound 基线

- [ ] 在同一冻结脚本快照运行原生完整目录模式，保存命令、版本、原始结果、耗时和内存。
- [ ] 核对直接请求、SDK 自发、多层引用/封装和字段增删覆盖的逐发送点差距。
- [ ] 验证 Webpack/Vite、module index、wrapper、source map 及页面配置实际边界。
- [ ] 检查结果归并/导出是否丢失调用者或字段差异，确定原始证据层与适配边界。
- [ ] 建立可访问增强 fork，固定补丁/许可证；据实冻结性能、公开样本数值验收门槛。

## S3：最小可用产品

- [ ] 实现独立工作台：任务、资产引用、API 主表、右侧详情和缺口视图。
- [ ] 实现本机服务配对/能力协商、持久任务、分块幂等续传及不可变 snapshot。
- [ ] 接入引用发现、范围内补抓与离线完整目录分析，输出四项及逐字段状态。
- [ ] 实现开始/暂停/恢复/停止、排空/超时、服务不可用时离线任务包；进度持续可见。
- [ ] 实现 JSON、Excel 和证据包；最小矩阵可确定正例及反例均通过，结果全部可回查。
- [ ] 验证无主动调用提取 API、无业务脚本执行；缺块/空结果/未完成状态不混淆。

## S4：嵌套与请求加工

- [ ] 增强打包模块、动态 import、Worker 及缺 map/部分 map 的归属与已知字段恢复。
- [ ] 实现跨文件、2/5 层和循环 wrapper 的有界摘要追踪，区分调用方与请求变体。
- [ ] 实现 URL/baseURL/条件 Host 与 Query/Path/Body/Header 的字段路径、覆盖、删除和序列化。
- [ ] 实现实例默认值、可证明顺序的同步 hook；未知 spread/副作用/异步注册定向降级。
- [ ] 验证 L0/L1 与 L2/L3 降级，严重调用/实例/位置误归属为 0。

## S5：稳定性、独立验收与白盒接入

- [ ] 完成浏览器/服务重启、配额耗尽、断传、取消、单页失败及预算中断恢复验证。
- [ ] 验证增量缓存与上下文失效；完成 1/10/100 入口共享依赖、深度和分支性能测试。
- [ ] 独立盲测达到事先冻结门槛，报告真实分子/分母、失败资产、时间和内存。
- [ ] 在目标 Chrome 真正加载 MV3 扩展完成现场验收；替代 API 测试不算此项。
- [ ] 默认版本交付插件、服务、安装/使用说明、许可、已验证边界和遗留缺口。
- [ ] 将同版仓库正式构建资产接入共享协议，比较四项结果；白盒单独验收构建、环境追溯和源码关联。

AI 封装建议、字段释义与远端服务不阻塞首版，核心通过后另列增量任务；不默认上传脚本到模型。

## 打勾规则

实现项必须同时有代码进入主干、正常及反例自动化测试、该项要求的冻结样本验证、实际边界文档。浏览器能力还需目标 Chrome 现场证据。设计项可以在评审冻结后单独完成，不能因此勾选实现项。部分完成保持未勾选；不以候选数、缩小范围或降低预期冒充效果提升。
