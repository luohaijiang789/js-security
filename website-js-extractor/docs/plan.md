## 最新调整：远端直传接收闭环（覆盖上一轮本地待传设计）

用户要求JS不落浏览器本地盘，尽可能所有采集内容直接发送远端。本轮步骤：

- [x] 黑盒二增加独立v1增量接收API：分块正文、SHA-256校验、提交、幂等事件、持久ACK、分页查询/正文回读。
- [x] 黑盒一改为共享会话→有界内存→接收API，移除新JS本地写入；远端任务的实测请求也直接发送，不写请求/活动快照/分组数据库。保留旧本地请求模式兼容。
- [x] 任务只需远端地址，内置固定code/default项目，按地址申请权限；工作台从远端查询。
- [x] 核对JS正文、Unicode/大文件、页面/导航/重定向/上下文/加载栈、实测请求原字段，模拟重复/丢确认/损坏/失败/重启读取。
- [x] 实际Chromium CDP→插件采集逻辑→真实Python HTTP接收→逐字段回读比对，回归原请求/UI功能，记录真实MV3限制。

无磁盘待传情况下不承诺离线/崩溃零丢失；成功只定义为远端哈希/字段校验及数据库事务提交后的持久ACK。现有本地JS数据不静默删除，停止新写入并提供显式清理。未获实际远端地址时只在本机联调，不擅自部署。

当前实现：生产插件`remote-capture.ts`→黑盒二`receiver.py`，SHA-256正文去重、256 KiB分块、完整对象校验、SQLite WAL/FULL事务后ACK；小事件逐字段保留，大事件作为UTF-8 JSON对象分块，不靠截断通过限制。请求保留原字段选择/完整或截断模式，传输不再次删减。JS raw CDP字段与规范化证据共同上传，ObservedRequest与静态候选分开。Network↔script精确关联仍unknown，没有静态分析成功计数。

浏览器JS元数据队列复用任务的CDP事件队列上限（默认2000事件/16 MiB），脚本源码4并发读取并保序发送观察，在途/失败内存有界；同一接收端/项目的相同正文只上传一次，重复加载仍保留独立观察；JS单文件64 MiB、单个传输对象128 MiB。队列溢出时丢弃本次JS事件并按缺口计数，请求采集继续；上传失败才暂停任务，保留首个未确认内容供同会话“恢复”重试；其后未处理的窗口和排队事件以缺口计数，停止不能把未确认标为完成。内存队列/正文不写IndexedDB或storage；仅任务配置、计数、缺口/UI设置留本地，接收code已内置，不需要手动令牌。页面/请求URL仍在少量任务/错误元数据中，不宣称浏览器完全零磁盘。既有本地请求模式保持兼容，远端模式禁止切回本地或换接收端。

验证：Python接收器6项包含大文件/Unicode/空正文、分块损坏、完整哈希、缺块、事件冲突、项目/认证/Origin、分页和库重新打开。插件新增真实HTTP传输测试覆盖丢ACK、伪造ACK、冲突、大请求事件、服务进程重启、错误令牌及失败暂停/内存重试；实际Chromium CDP通过同一Recorder连接采集两份3 MiB JS和含中文/emoji/重复查询参数/嵌套JSON的POST，逐事件JSON摘要、正文和具体参数回读一致；断言无本地JS库、无请求/活动快照落盘。本轮`npm test`含构建与20个文件、173项通过；后端89项按模块运行通过（含接收器6项、离线ingest6项）。合并单进程discover在当前环境被SIGKILL，未记为通过。真实MV3仍被企业策略阻止，未绕过。未开展长期唯一正文总量/RSS压力、远端TLS/公网部署或接收端持续分析验收。
