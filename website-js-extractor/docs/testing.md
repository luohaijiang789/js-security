# 测试与验收

当前所有门槛都是待实施的验收要求，没有实测通过结论。先冻结输入与人工预期，再运行基线和增强版本。

## 1. 三类验证分别记录

| 验证层 | 能证明什么 | 不能替代什么 |
| --- | --- | --- |
| 单元/组合 | 深度、协议、状态机、绑定、字段与失败处理符合预期 | 浏览器真实权限与生命周期 |
| 真实 CDP | 真实正文、脚本事件、导航和目标关系 | 实际安装 MV3 扩展后的行为 |
| 目标 Chrome MV3 | 真正加载插件、后台恢复、权限、目标和并发干扰 | 全站请求完整性或其他版本浏览器表现 |

每次记录插件/服务/jshound Commit、Chrome/操作系统版本、配置、快照哈希、范围、分母和失败清单。企业策略禁止安装/调试时标“未验收”，不使用替代 API 测试声称通过。

## 2. 冻结测试输入

1. 受控站点：事先标注页面、脚本引用图、发送点、调用变体、四项字段和加工前后结构；服务端记录资源读取及意外 API 调用。
2. 公开开发集：固定代码版本、构建配置、部署和哈希，用于适配 jshound；不得从其输出反推预期。
3. 独立盲测集：至少一个未用于规则开发、包含懒加载/封装的冻结部署；标注限定范围后首次运行，不临时删掉失败输入。

登录、动态脚本等用受控站点；公开站点不具备授权/稳定版本条件时不假称冻结。外部源码、部署与完整结果放 `work/`，Git 只存配置、预期和哈希。

## 3. 必测矩阵

| 范围 | 正例 | 反例/缺口 |
| --- | --- | --- |
| 直接请求 | fetch/XHR/Axios/beacon；URL、方法、四类载体 | 同名非网络函数、普通路由/URL 字符串不误确认为 API |
| 依赖上报 | SDK 初始化/定时/页面行为上报 | 无业务调用者时仍分析；未知触发条件不伪造 |
| 多层调用 | 2/5 层 wrapper、跨模块、共享封装多个调用方 | 递归、缺模块、别名遮蔽；参数不得串线 |
| 请求加工 | 默认 baseURL、Header、字段增删覆盖、同步 hook、JSON/FormData/URLSearchParams | 两个 client 隔离；异步/动态注册 hook 降级；未知 spread 不丢已知字段 |
| 资产获取 | D0–D3、动态 import、Webpack/Vite chunk、循环/多父 | D4 只记引用；已观察 D4 与主动补抓区分；未知深度不自动 D1 |
| 上下文 | 登录页面、同进程 frame、OOPIF、Worker | SharedWorker/SW 等逐类报告覆盖；未知父目标不继承顶页 Host |
| 版本/正文 | 同 URL 不同内容、同内容不同 URL、完整/无/部分 map | Network 正文与 Debugger 源码不强认同版；缺块/超限不当完整正文 |
| 地址基址 | 页面 base、模块相对 import、相对 fetch、Worker | 脚本 CDN 不当 API Host；动态 Host 保持未知 |
| 生命周期 | 所有窗口、新页/导航、关闭管理页、暂停恢复、浏览器/服务重启 | 动态附加开头缺失、被分离、单页失败、存储满/断传均保留缺口 |
| 调试干扰 | 单独运行、黑盒一采集、DevTools 开关分别验证 | 不抢占连接，不隐瞒另一任务中断；失败页面不终止全局 |
| 无主动调用 | 深层 JS 补抓与离线分析 | 受控服务端确认工具没有额外调用提取 API、提交表单或执行下载脚本 |

## 4. 指标和发布判定

| 指标 | 分母/通过要求 |
| --- | --- |
| 资产状态覆盖 | 冻结范围内已发现资产，每项均有完整、失败、超限、未取得或重复引用状态；不得丢项 |
| 获取正确性 | 受控图中允许预算内、可取得的脚本全部获取且哈希一致；范围外/超深度行为与预期一致 |
| 发送点召回/精确率 | 人工标注发送点 / 工具确认发送点；受控可确定矩阵须精确通过，候选另计 |
| 调用变体正确性 | 逐调用/实例/条件核对；严重串线或误归属为 0 |
| 四项恢复 | 按人工可静态恢复的 URL、Host、JS 归属和参数字段分别计算正确率；动态未知不计可恢复分母 |
| 缺口正确性 | 每个故障注入均有对应缺口，分析未完成不能显示完整成功 |
| 可复核 | 确定结果全部可回查固定正文、位置和字段来源；定位未知不能算定位通过 |
| 恢复/续传 | 中断后确认块不丢、可幂等续传；不能丢记录或把新内容混入旧快照 |

独立盲测先报告真实分子/分母与剩余差距，不预先承诺任意站点的百分比。默认发布前，必须根据开发集基线冻结可达到的数值门槛，再运行盲测；盲测后不能为过关下调门槛或缩小样本。受控矩阵、缺口如实表达、严重误归属为零是独立硬门槛。

## 5. 性能与资源

先实测基线：S1冻结采集文件数/字节、插件存储和获取并发，S2冻结分析墙钟时间、峰值RSS、报告大小与公开样本门槛；均注明目标机器，未冻结前不宣称大站可用。

用 1/10/100 页面入口共享依赖，及引用深度/分支可控的图分别测试。相同资产不重复完整解析；同代码不同上下文的配置分析需正确失效。压力项包含大单文件、多小文件、延迟/失败资源、存储满、上传断连和分析超时。达到预算要可终止并导出已完成结果及未完成清单。

## 6. 阶段验收演示

- S1：在真实安装的插件里看到页面/目标、脚本正文哈希、引用链及有意制造的缺口。
- S2：对同一冻结快照重复运行 jshound，展示原始结果、人工预期和逐项差距。
- S3：用户启动插件并操作页面，生成快照，得到能点开 JS 证据的四项主表与导出；基本跨文件wrapper、两client/两调用隔离、简单字段覆盖删除及非网络反例通过；重启服务后仍可重跑。
- S4：五层封装、SDK 增参、两实例与 hook 修改的结果逐条正确，无法确定的部分可见。
- S5：独立样本、故障注入、性能和目标 Chrome MV3 验收同时达标，再发布默认版本。

S1 的采集原型不等于整条分析链已通过；每个阶段只声明它实际证明的范围。

## 7. 工程与模块交付验证

模块号与实现细节见[模块规格](modules.md)，运行组合见[工程架构](architecture.md)。

| 对象 | 必须验证 |
| --- | --- |
| C01 | 相同JSON例子由TS/Python一致校验；类型生成可复现；身份/状态/兼容反例覆盖 |
| E01–E04 | 导航/目标代次、正文与观察分离、深度多父更新、冻结截止序号、发现多轮快照、离线包与重启恢复 |
| E05/S01 | 真实扩展权限与配对、CORS/Origin、凭证过期、分页/断线、协议不兼容拒绝，UI不提升候选 |
| S02/S03 | 同块冲突、损坏包/路径越界、缺对象、只读输入、离线重跑、取消/超时进程树、核心版本及资产处理账目 |
| A01/A02 | 不同runtime同模块号、同名文件/函数、参数遮蔽、批次/输入顺序变化、库级调用与底层传输重复关联 |
| A03/A04 | 同wrapper不同实参、client工厂、闭包、别名写入、条件删除、hook真实顺序、未知副作用、摘要预算降级 |
| S04 | 主表/详情/导出同源、参数/缺口关联、长内容与行数分片、外部字符串按文本写入、凭证不出包 |
| 发行与升级 | 干净Windows安装Python/Node和应用依赖、启动自检、实际Chrome版本、离线导入、schema不兼容、数据库升级失败可恢复 |

首版不要求先开发全套自动安装器，但必须提供可复制的安装、启动和自检步骤，并在另一台目标机器验证。仅在开发容器运行成功不能标默认版本已交付。
