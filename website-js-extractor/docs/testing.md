# 测试与验收规则

本文只定义验证方法、矩阵和通过标准，结果和待办只在[计划](plan.md)维护。准确运行命令统一在[使用说明](plugin.md#验证入口)。测试某层通过不能提升另一层的完成状态。

## 1. 证据分层

| 方法 | 能证明 | 不能证明 |
| --- | --- | --- |
| Python 单元/HTTP/真实核心检查 | 输入校验、预算、字段与版本、作业/进程、固定正文结果 | Chrome扩展权限、浏览器登录态和实际后台存活 |
| 插件逻辑/IndexedDB/消息检查 | 状态、持久化、截止、任务隔离与错误分支 | 实际chrome API行为 |
| 真实 Chromium CDP→核心 | 协议读源、初始/延迟加载、基址、冻结正文与真实核心衔接 | MV3权限、扩展生命周期与跨插件冲突 |
| Chromium UI检查 | 视图、按钮、来源/源码/详情和密钥不落普通配置 | 被替代的扩展API与服务响应真实可用 |
| 真实 MV3→本机服务 | 实际安装/权限、后台、目标、配对和全链行为 | 未运行场景、其他Chrome/OS或全站覆盖 |

企业策略禁止扩展时检查非零退出，记录当时环境/日期和原因，不绕过策略，不计为通过。公开 bundle 无人工真值时仅作兼容性；自动化检查数量不是准确率/召回。

## 2. 当前与补抓矩阵

| 用例 | 验收预期 | 适用阶段 |
| --- | --- | --- |
| 已加载/延迟JS、新页/导航、关闭管理页 | 正文/观察可回查；遗漏区间明确，不擅自刷新或操作业务 | P1 |
| iframe与各类Worker、匿名/inline/sourceURL/blob | 逐类报告已取得/未知；无法确认基址时Host不猜 | P1/P2 |
| 登录资源、DevTools或另一扩展占用 | 自然浏览器上下文可取则保存；失败不抢占、不改成文件不存在 | P1/P2 |
| 暂停/恢复/停止/后台重启 | 有界排空，完整正文保留，中断可见；历史控制不影响当前任务 | P1 |
| 服务离线、Origin/Host/令牌、预算、损坏/重复快照 | 拒绝反例不创建成功作业；冲突不幂等成功；原文和旧输入不变 | P1 |
| 冻结前后继续收集、取消分析 | 快照不变；取消只针对作业，不删除输入或停止其他采集 | P1 |
| 页面→a→b→c→d | 默认只补到D3；D4明确缺口，已有深层正文仍分析 | P2 |
| 多父/循环/短链晚到、版本歧义/import map阻断 | 保留边、重新计算最短路径；不重复获取、任选版本或绕过阻断 | P2 |
| 403/重定向/登录HTML/短响应/未知长度极限 | 分原因记缺口，不截断当完整；逐跳来源校验、不跨域带认证 | P2 |
| 补抓前后同一引擎对比 | 新候选可回查新增脚本；访问日志无业务API探测 | P2 |

已解析源码、DOM和Network正文按表示分别冻结预期；不以URL相同推断正文相同。精确声明覆盖范围后才进入现场门槛。

## 3. 后续集成验收

本节是以后 I1–I4 的验收设计，**本轮不集成、不创建这些实现**。路径、接口和工作包以[架构](architecture.md#5-黑盒一集成方案仅设计)为准。

| 组合/故障 | 必须观测到的结果 |
| --- | --- |
| 只开真实请求 / 只开静态采集 / 两者同开 | 每tab一次attach；各有独立任务/结果和正确的能力配置 |
| 先开任一功能再开另一功能 | 复用会话，不重置请求/异步栈身份，不丢已取得源码 |
| 分别暂停/停止，顺序反转 | 只关闭对应订阅并有界排空；有其他租约时不detach |
| 两者停止/重复release/旧租约延迟命令 | 仅最终释放分离；重复幂等，旧代次不能操作新会话 |
| 导航、子目标、旧request/script终态晚到 | 原观察关联不被新页面配置覆盖；无法关联明确未知 |
| 单消费者队列满/存储失败 | 有界退化并记缺口；另一消费者不被静默停掉或丢事件 |
| DevTools/外部占用、意外分离、标签关闭 | 不抢占；所有实际受影响任务记准确中断 |
| 服务断线/重启/取消作业/loopback授权拒绝 | 请求采集继续；静态正文可保存/导出，作业状态不伪造 |
| 原有任务/模式/Filter/字段选项/导出 | 数据可读、行为不变，不自动扩大旧范围或开启新功能 |
| 独立插件包导入、损坏包、版本冲突 | 用户主动迁移、校验后导入；原库和原输入不删除 |
| 功能关闭与代码回退 | 请求功能仍可用，静态快照保留；不靠卸载/删库回退 |

每项需正常/反例自动化、实际Chrome/OS/扩展版本、日志/快照/导出及剩余限制。I1 先证明黑盒一行为不变，I4 通过之前新功能不得默认启用。

## 4. 精确分析、统计与发布

在增加规则前冻结受控站点、公开开发集和独立盲测集的版本、SHA、人工标注范围与预期；同一输入既对照原生基线，也保留项目适配后的证据。盲测后不为过关下调门槛或缩小范围。

| 矩阵 | 要求 |
| --- | --- |
| fetch/XHR/beacon/Axios、直接/SDK自发 | 绑定正确；同名普通函数、路由字符串和无证据封装不确认为请求 |
| 同wrapper两调用、两个client、跨文件/递归 | 地址、Header与Body不串实例；预算耗尽降级并保留影响 |
| spread/覆盖/删除、重复键、序列化/hook | 遵循顺序与库模型；动态值不使已知字段名丢失 |
| CDN相对fetch、页面/Worker、变版与缺模块 | 用正确执行基址，缺证据不补造；原始位置与map附加位置分开 |
| 共享发送点/多个接口、同接口多调用 | 接口组/上下文/唯一位置分别计，按规则版本可回查 |
| JSON/UI/Excel、长内容和超行 | 同源；凭证不导出，文本公式安全，不丢记录或变体 |

分别报告发送点精确率/召回、四项与参数字段恢复、误归属/变体串线、位置正确率、缺口状态，附分子分母与未知范围。受控可确定正反例逐项通过，严重误归属不能靠增加候选掩盖。未有精确证据时不输出确认计数；未触发API仍可静态发现，不将实测次数混入。

性能需在目标机器冻结预算后验证：小/中/大包、1/10/100入口共享依赖、时间/进程RSS/报告大小、缓存失效、配额/中断/恢复；重复正文命中缓存的负载检查不能外推不同大包成本。Windows安装/启动/权限/重启/升级与真实MV3独立验收，Linux开发通过不能当作Windows发行通过。
