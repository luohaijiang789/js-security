# EO 14117 前端 JS 采集与透传排查整改 Checklist

> 目的：围绕 EO 14117 及其 DOJ Data Security Program，排查前端 JavaScript 引入的数据采集、发送、隐式注入和后续转发/访问路径，完成适用性判断所需取证、整改及复验。
>
> 这是执行清单，不代表已经实施。所有业务项初始未勾选；创建文档、完成一次扫描或没有观察到请求，都不能自动勾选对应业务项。当前仅已有资料与设计，真实业务试点尚未开始。

## 使用方式与完成口径

每条任务按编号跟踪：`状态 / 负责人 / 目标时间 / 证据引用 / 阻塞或不适用理由 / 复核人`。状态使用：未开始、进行中、阻塞、待复核、完成、不适用。不适用必须有依据，不作为已完成发现计数。

完成勾选须有对应证据和责任人确认；缺材料、版本不符、观察失败和未知载荷保留未完成或阻塞。使用[团队交流方案第 9 节](团队交流方案.md)落实负责人。具体步骤查[白盒怎么做](白盒怎么做.md)、[黑盒怎么做](黑盒怎么做.md)。

| 推进阶段 | 任务编号 | 交付凭据 |
|---|---|---|
| 对齐与准备 | G、P | 范围/人员、材料、账号、规则口径和证据保管约定 |
| 两侧发现 | A、B、W | 资源/版本、实际请求/字段、代码机制/路径与覆盖缺口 |
| 关联与适用事实 | C、E | 往返任务、差异解释、下游/主体/交易等事实与复核 |
| 整改与复验 | R、V | 修改记录、双侧/下游与业务证据、未结项 |
| 扩展与持续 | F | 剩余范围、变更触发与复查负责人 |

## 0. 项目目的与 EO 判断边界

- [ ] G01 明确本项目为 EO 14117/DSP 前端相关风险排查与整改；黑盒、白盒、Agent 和资料研究均服务该目标。
- [ ] G02 定义纳入范围的应用、域名、仓库、SDK、远程脚本与共享组件；识别是否涉及美国相关数据，不只依靠站点部署地或用户访问 IP 划界。
- [ ] G03 覆盖浏览器直传、业务 API 透传、日志/队列/存储/复制，以及接收后远程可访问关系；首跳在美国不能直接结案。
- [ ] G04 由隐私/法务指定 EO/DSP 复核人和所依据的规则版本，确认数据类别、规模/时间窗口、交易关系、主体、例外和相关义务的核查口径。
- [ ] G05 明确判定结果包含：待补事实、待法务复核、认定不适用及依据、需整改的适用问题、适用条件下允许及持续控制要求；不能把“未知”归成合规。
- [ ] G06 为其他隐私/安全发现设置关联议题，说明与 EO 目标的关系；不把“已发现一般隐私问题”等同“已证明违反 EO”。

**阶段出口：** 团队知道查什么、为什么查、谁确认 EO 适用性。法律细节未齐全可以开始范围明确的技术调查，但不能先宣称问题已经解决。

## 1. 开始前先准备什么

### 1.1 牵头、范围和协作

- [ ] P01 指定牵头人及前端、测试/黑盒、白盒、后端、云/IAM、业务、隐私/法务、供应商接口人，可兼任但职责明确。
- [ ] P02 选定首个试点，固定版本、环境、主要旅程、角色、租户/区域差异与排除项；指定后续扩展到其他应用的登记方式。
- [ ] P03 确认可执行动作、测试窗口、禁止操作、异常触发方式和生产/测试环境界限。
- [ ] P04 约定共享任务与证据格式，建立阻塞台账、对账时间及需要升级协调的条件。

### 1.2 前端与运行材料

- [ ] P05 取得仓库、commit、锁文件、构建参数、发布记录；建立源码、bundle、部署环境和可取得脚本哈希的对应关系。
- [ ] P06 取得路由/旅程、账号角色、测试账号、合成数据与异常场景；列出无法访问的页面和状态。
- [ ] P07 取得 SDK/标签清单、初始化配置、采样、请求匹配规则、功能开关及远程配置；缺失项指定提供人。
- [ ] P08 取得可用 HTML、bundle、source map、动态加载、iframe/微前端、Worker/Service Worker 材料；标记无法取得或无法解析项。
- [ ] P09 准备网络观察与证据留存环境，按 target/执行上下文、载体、附加时机与解析完整性登记能力，用相关受控正例校准；记录浏览器、工具和配置版本。

### 1.3 接收、合规与数据保管材料

- [ ] P10 确认本方 API、网关/BFF、日志、队列、存储和云配置资料的只读入口与负责人。
- [ ] P11 取得已有字段/事件字典、业务用途、供应商/子处理者和合同资料；没有则登记为待补，不自行假设。
- [ ] P12 确认证据存储位置、访问控制、脱敏、保留与删除；原始凭据、用户原值和完整 Cookie 不进入普通 Git 或未经批准的模型上下文。
- [ ] P13 确认可用模型/Agent 环境、允许提供的源码和流量、外部处理边界、工具权限及执行留痕。

**最小启动条件：** 有明确范围、合法可用的仓库或网站入口、对应负责人和证据保管方式。黑盒执行还需要账号/场景与观察能力；白盒先查可用源码。缺少下游材料不阻断所有调查，但会阻断相关 EO 主张的关闭。

## 2. 前端 JS 与配置是否盘全

- [ ] A01 登记约定范围内所有应用、路由、角色和部署版本；共享 SDK/封装记录使用方，避免试点结果误外推。
- [ ] A02 对照源码导入、HTML、依赖、构建清单与实际加载资源，识别仓库外脚本、标签管理、远程配置和动态代码。
- [ ] A03 按实际版本/哈希登记分析、监控、回放、风控、客服、广告、实验、标签和业务自行上报组件，Baxia 只是其中一个样本。
- [ ] A04 区分浏览器、iframe、Worker/SW、SSR、Edge/BFF 等执行上下文，记录实际运行与部署差异。
- [ ] A05 明确采集配置和脚本发布的负责人、可修改者及变更入口。
- [ ] A06 形成已取得、未取得、未解析、版本不符、机制暂不支持清单，说明影响哪些分析结论。

## 3. 黑盒需要完成什么

- [ ] B01 在不依赖白盒候选的情况下，独立观察约定场景内资源、接口和字段，包含本方业务域名；保存发现快照，后续定向结果保留父任务。
- [ ] B02 记录场景/角色/身份与同意状态、动作顺序、时间、执行成败和观察窗口。
- [ ] B03 记录请求方法、端点、重定向、头/query/body、事件与批量结构、发起线索；分别记录调用/入队、网络事件、响应或接收方证据、失败阶段，不把 Beacon 返回 true 当送达。
- [ ] B04 检查 fetch/XHR、Beacon、WebSocket、资源像素、表单/导航、iframe 消息和后台发送等与目标应用相关载体；不支持项明示。
- [ ] B05 形成字段路径、类型、脱敏/合成样本、语义依据和解析状态；缺失、截断、multipart 文件省略、不透明或未解码内容不能按空内容处理。
- [ ] B06 观察加载、登录/退出、角色变化、关键业务、异常、离开页面、等待、离线与重试等相关状态；未执行项留账。
- [ ] B07 将未知字段/接口/脚本转成白盒反查任务，包含场景、请求、脚本、时间与版本线索。
- [ ] B08 将未干预观察与 Hook/测试配置等受控灰盒实验分开记录，保留必要对照。

## 4. 白盒需要完成什么

- [ ] W01 独立枚举来源、变换、发送点、SDK 初始化、公共包装器、拦截器、加载器与队列；保存发现快照，为公共机制列入参/隐式状态、对象副作用、条件和正反例。
- [ ] W02 从来源向外追踪，同时从实际/候选接口向内反查字段构造，不只按关键字命中出报告。
- [ ] W03 检查 URL/query/hash、身份/设备/会话、表单/DOM、错误对象、请求/响应、存储与指纹等相关来源；语义不明项交业务确认。
- [ ] W04 追踪序列化、过滤、编码、哈希、token、加密、压缩和聚合，保留数据关系及未知边界。
- [ ] W05 对路径核对对象实例、字段、联合条件、时间、序列化结果与发送运行时，排除不成立的拼接。
- [ ] W06 检查 SDK 自动注入业务请求、广泛路径匹配、远程配置切换、错误回退、备用发送及重复包装顺序。
- [ ] W07 检查账号切换、同意状态变化、离线队列、退出/卸载与重试，判断字段是否被重新加入或延迟发送。
- [ ] W08 接收黑盒观察反查代码/配置；定位公共机制后枚举其他调用者及其差异。
- [ ] W09 给候选路径生成黑盒任务：前提、特征、动作、目标/表达式、观察要求、预期结果与反例。

## 5. 两边是否真正相互验证

- [ ] C01 统一案件、版本、场景、观察和路径引用；保留独立/定向发现来源、父任务、兼容配置和结论依赖，不重复计算同源证据。
- [ ] C02 组合字段结构/变换、脚本/栈、方法/端点、条件及版本确认关联；逐字段区分来源、追加/覆盖、序列化与发送，不凭接口名或请求发起栈认定整包来源。
- [ ] C03 对“黑盒有、白盒没解释”逐条定位远程资产、版本差异、注入与模型缺口，或留下未解释任务。
- [ ] C04 对“白盒有、黑盒没观察到”区分未触发、开关/采样、死代码、执行失败及不可观察；不自动判误报。
- [ ] C05 对两侧字段/目标冲突查分歧边，对不兼容版本分别归属证据。
- [ ] C06 完成至少一条 `黑盒 → 白盒 → 新候选 → 黑盒` 或反向往返，并记录扩大了哪些范围。
- [ ] C07 分别报告资产、静态机制、场景、字段解释和候选验证的有界覆盖；两侧共同未知不算通过。

## 6. EO 判断所需的后续链路与事实是否补齐

每条相关数据流使用统一事实记录：`数据类别/来源 → 数量与时间窗口 → 字段变换 → 浏览器首跳 → 下游处理/留存 → 接收主体与访问能力 → 交易/合同关系 → 规则判断及条件`。技术观察、供应商声明和法务判断注明各自来源。

- [ ] E01 将业务字段及派生标识映射到待核查的 DSP 数据类别，分别判断普通业务信息、相关敏感数据和政府相关数据；映射依据由合规复核。
- [ ] E02 核对规则要求的数量、对象去重、组合类别、时间窗口及特殊处理条件；不拿请求条数或一次抓包量代替法定口径。
- [ ] E03 核实有关美国主体、交易方、接收方、供应商/子处理者及 covered person/country of concern 关系；不靠品牌名或实体名单查询单独完成。
- [ ] E04 由法务结合合同与行为核对交易类别、禁止/限制情形及所主张的例外/授权，不以数据出境这一事实代替全部要件。
- [ ] E05 从浏览器字段追到本方 API 接收、日志、网关、风控调用、队列、存储、复制、导出和备份；无法追到的链路有负责人。
- [ ] E06 区分网络首跳、处理/存储区域、法律主体、远程运维/支持与有效访问；核对跨地区人员、共享平台和供应商访问。
- [ ] E07 核查 token/标识与账号/设备的实际关联、持有方映射/密钥与组合能力；TLS、存美国或名称匿名都不自动关闭该项。
- [ ] E08 对适用的受限交易，安排核验 CISA 组织、系统、数据层要求及对应尽调、审计、记录/报告事项；由相应团队确认，前端扫描不能独自完成。
- [ ] E09 每条相关路径形成适用性判断或明确待补事实，标明复核人、依据、版本、条件与剩余任务。

**阶段出口：** 不能只停留在“找到了打点”。需知道哪些链路与 EO/DSP 有关、依据什么判断、需采取什么措施，以及哪些事实尚不足以结案。

## 7. 整改是否落实

- [ ] R01 对确认的问题按根因与可控制位置归组，关联全部已知受影响路径；指定修改方和业务/合规验收方。
- [ ] R02 删除或限制不必要字段，在进入事件/队列/存储前最小化；检查完整 URL、上下文对象、原始凭据与自由扩展属性。
- [ ] R03 对必要 SDK/风控评估收窄启用页面、字段、接口匹配、身份绑定与生命周期；先确认真实可用控制，不虚构厂商开关。
- [ ] R04 按确认的处理/访问限制调整目的地、转发、日志、队列、区域、复制、权限和密钥控制；不能只换域名或只把首跳迁到美国。
- [ ] R05 将远程标签、SDK 版本、运行配置和相关发布入口纳入修改及后续变更控制。
- [ ] R06 在适用且需要的情况下协调历史日志、数据、备份、导出、供应商副本与访问记录的处置；保留要求或法律留存冲突由法务确认。
- [ ] R07 对当前持续暴露与高影响不确定项安排有负责人、时限和复核条件的临时处置，不无限等待完整反混淆。
- [ ] R08 明确上线窗口、业务回归、失败策略和必要回退；回退不能悄悄恢复已判定不允许的路径。

## 8. 怎样证明整改有效

- [ ] V01 白盒检查修改覆盖主路径、错误/重试、Beacon/Worker、队列与备用路径，字段不会在后续被重新加入。
- [ ] V02 黑盒按可比受控条件比较整改前后，配对验证禁止字段不再发送和必要业务成功；记录版本、采样/干预、观察能力与窗口，排除观察失败或功能整体停用。
- [ ] V03 验证登录、风控、支付/交易、诊断等受影响业务，取得业务方验收。
- [ ] V04 后端/云侧检查不必要字段不再进入日志或下游，并按整改目标验证区域、复制、有效权限与密钥边界。
- [ ] V05 对历史处置和供应商动作取得适当证据；无法确认的副本或访问问题继续保留任务。
- [ ] V06 隐私/法务依据修复后的事实复核 EO/DSP 问题；内部结案不等同取得监管安全港或完成所有独立审计义务。
- [ ] V07 每张整改卡附修改记录、双侧与必要下游证据、业务验收、残余未知和结论依赖；明确 SDK/配置、队列、Worker、下游变化后哪些结论需要重验。

## 9. 结案、扩展与防复发

- [ ] F01 交付范围/版本、黑盒接口字段、白盒机制路径、两侧关联差异、EO 事实与复核、整改复验及未结项。
- [ ] F02 明确哪些是试点结论、哪些应用/角色/机制尚未覆盖；按业务清单逐步扩展，不能用一个 SDK 样本代表全部前端 JS。
- [ ] F03 对新增 SDK、字段、端点、标签、配置、下游与访问权限变化设复核触发，关联已有证据失效范围。
- [ ] F04 维护字段/用途/接收与访问约定，给持续允许或临时措施设置适当复审条件。
- [ ] F05 依据已暴露的重复工作和漏报类型安排 blackbox、whitebox、correlation、ai-agents 建设，不以平台完成替代业务问题关闭。
- [ ] F06 定期复盘未解释行为、未验证候选、长期阻塞与复发，落实负责人；适用的合规审计/记录要求另行由责任团队持续执行。

**最终完成口径：** 在声明范围和版本内，相关 JS 采集/透传与后续处理/访问路径已被排查，EO/DSP 相关问题获得有依据的处置与复验；未知、例外和剩余范围显式交接。单次扫描完成不是项目完成。

## 官方核查入口

EO 14117 对应 DSP 的范围涉及特定数据、交易及主体访问条件，技术项目按这些问题补事实，不将“跨境请求”单独作为违法结论。[DOJ Data Security Program](https://www.justice.gov/nsd/data-security)
