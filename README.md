# 阿里云美国独立站：JavaScript 数据传输审查

**目标：查清美国独立站是否存在向其他国家传输数据的路径，定位涉及的接口、字段、代码与配置，支持整改。**

## 背景与当前范围

| 项目 | 约定 |
|---|---|
| 业务背景 | 阿里云面向美国业务的独立站，跨境数据风险排查以 EO 14117 相关问题为背景 |
| 整体目标 | 查清前端 JS 经接口向其他地区传递哪些数据，支持 EO 14117 相关合规排查与整改 |
| 当前工作 | 第一版输入 Host + 一个代码仓，提取相关接口、参数、含义与敏感性线索成表；引用 JS 的拉取深度可配，默认 3 |
| 审查对象 | 前端 JS、公共请求封装、拦截器、SDK 及其引入的 JS；其他代码不展开审查，已有 HTML/配置仅辅助定位 |
| 当前阶段 | 黑盒方案已确定且已验证有效；本项目正在讨论单仓白盒方案，尚未接入目标仓库或实现白盒扫描器 |

分析结论只覆盖本仓前端 JS 及已取得的引用 JS；其他系统链路仅列交接点。接收国家不能仅凭域名、品牌或代码中的 URL 确认，需补部署、转发及接收方事实。

项目原则见 [AGENTS](AGENTS.md)。EO 14117 的实施计划 DSP 针对特定数据、交易及国家/人员访问条件；本项目提供相关技术事实和整改依据，法律适用按这些条件复核。[DOJ 官方说明](https://www.justice.gov/nsd/data-security)

## 黑盒方案：已确定、已验证有效

**通过浏览器插件采集独立站各页面的接口、参数信息和调用栈。**

| 采集内容 | 用途 |
|---|---|
| 页面与接口 | 知道哪个页面触发了什么请求 |
| 参数信息 | 识别实际请求中的数据字段及其载体 |
| 调用栈 | 为白盒反查提供脚本、函数与调用位置线索 |

以上为用户已确认有效的方案，作为白盒的既有输入。具体记录见[黑盒方案](docs/黑盒方案.md)。

## 白盒要解决什么

**输入一个代码仓，回答：什么数据，由谁加入，经过什么处理，在什么条件下，通过哪个接口发往哪里。**

白盒既要独立发现代码中的传输路径，也要利用黑盒接口、参数和调用栈反查代码。代码中新发现的路径再交黑盒定向验证。

第一版收敛为 **Host → 接口 → 参数 → 含义与敏感性线索 → 代码依据表**。本仓 JS 记第 0 层，只递归取得它引用的 JS，默认最多三层；不递归克隆其他仓库或安装整包。无法取得或超过深度的 JS 列未决项。

```mermaid
flowchart LR
    B["黑盒：页面、接口、参数、调用栈"] -->|反查| W["白盒：来源、注入、处理、发送条件"]
    W -->|新增路径与触发条件| B
    W --> R["整改位置与影响范围"]
    W --> H["仓外接收与转发：交接核实"]
```

白盒方案从[这里](docs/白盒方案.md)开始讨论。最终交付三项：

- **数据流清单**：接口、字段、来源、处理、条件、发送目标及代码依据。
- **整改清单**：具体代码/配置位置、影响范围与验证要求。
- **未决清单**：缺失实现、运行配置、黑盒证据或仓外链路及所需材料。

代码存在发送能力与线上实际发送分别记录；技术发现不直接等于法律适用结论。
