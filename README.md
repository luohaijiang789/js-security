# 前端 API 与请求参数自动化提取

**通过一套白盒、两套黑盒收集前端 API 与请求参数，保留代码依据、实际观察和未知项，统一交付 `api_assets.xlsx`。**

项目起于阿里云美国独立站的前端 JS 数据跨境排查。第一阶段只做资产发现与提取，不做 Host 筛选、敏感性识别、风险分级或合规判断。

## 三个方案

| 方案 | 做法 | 本轮边界 |
|---|---|---|
| [前端代码仓JS请求API采集（白盒）](docs/前端代码仓JS请求API采集.md) | 对固定 Commit 的源码做请求与参数静态分析 | 不要求编译/执行；外部依赖只获取一层；仓内必要跨文件追踪保留 |
| [JS 请求采集浏览器插件（黑盒一）](docs/JS%20请求采集浏览器插件.md) | 测试人员操作页面，CDP 记录真实请求及可取得调用栈 | 只覆盖实际触发且可观测场景；采集缺失明确记录 |
| [网站 JS 收集与静态分析（黑盒二）](docs/网站%20JS%20收集与静态分析.md) | 获取部署脚本，分析请求与字段候选 | 脚本引用最多三层；需适配打包代码与页面上下文 |

**三路均待开发。** 插件原理和方案相对清晰，尚待实现及验收；两路静态分析的工具与效果尚未验证。白盒与网站 JS 分析可共享基础能力，但不预设 M2～M4 完整共用同一实现，需用同版源码/产物对照确定。

三路可以独立运行。结果分别标记“仓库静态 / 网站 JS 静态 / 插件实测”，可关联而不抹平版本、调用和字段差异。工作簿包含 API 总表、参数明细、分析缺口，另保留 `analysis.json` 证据底稿。
