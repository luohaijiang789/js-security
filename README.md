# 前端 JavaScript 数据透传白盒审查

## 项目目的

**审查代码仓中的 JavaScript，找出哪些数据被采集、怎样被透传、发往哪里，并定位需要整改的代码与配置。**

项目服务于美国业务的跨境数据风险排查，以 EO 14117 相关问题为业务背景。先把前端数据流查清，为整改及后续合规判断提供依据。

## 重点查什么

“透传”包括业务主动上报，以及公共封装、拦截器、SDK 自动附加或转发数据的行为。

| 环节 | 审查重点 |
|---|---|
| 数据来源 | URL、表单、身份与设备信息、存储、错误上下文、请求和响应 |
| 数据传递 | 对象合并、默认上下文、事件包装、SDK 输入、请求头和参数注入 |
| 数据处理 | 过滤、序列化、编码、哈希、加密与 token 生成 |
| 发送路径 | 直接上报第三方、透传至业务 API、队列延迟发送、重试与备用路径 |
| 生效条件 | 页面、角色、区域、开关、远程配置、执行顺序及账号切换 |

## 怎么审查

从数据来源向发送点追踪，同时从发送点反查字段来源，核对具体对象、字段、条件与时序。

每条路径尽量回答：

**什么数据 → 谁读取或加入 → 经过什么处理 → 在什么条件下 → 经什么接口发往哪里。**

## 交付什么

- **数据流清单**：字段、来源、处理、发送目标、触发条件及代码位置。
- **整改建议**：具体修改点、受影响调用方及需要验证的旁路。
- **待核实事项**：缺失的 SDK 实现、运行配置、实际发送证据或后端转发信息。

白盒结论须有代码或配置依据；代码存在发送能力，不代表线上已经发生。前端首跳之后的处理、访问及法律适用，需要对应团队补证确认。
