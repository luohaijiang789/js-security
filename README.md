# 前端数据采集与透传审计：分析与方案

当前阶段只做分析和方案设计，不开发或运行扫描器。目标是给定美国业务网站、代码仓或两者，形成可复核的数据流证据、覆盖缺口和具体整改建议。静态代码线索、运行时请求、服务端下游和法律判断分别记录，不能互相代替。

## 项目内容

- 根目录的方案文档是本项目的研究与设计成果；以主方案为后续修订入口。
- [`samples/baxia/`](samples/baxia/README.md) 保存公开 CDN 脚本及响应头的研究快照。脚本属于原作者，不是本项目的实现，也不应作为生产依赖使用。
- [`notes/`](notes/) 保存形成方案时的计划、发现和进度记录。

这是文档项目，当前没有可执行的扫描器、构建命令或自动化测试。案例分析只覆盖文档所列证据，不能代替具体业务站点的审计结论。

## 后续试点流程（本轮未执行）

1. **确定试点范围**：选定一个业务应用、对应的生产部署版本、关键页面/流程，并列出可读取的前端、网关、服务端和云配置资料。
2. **建立覆盖分母**：盘点路由、实际加载脚本、SDK、发送点、请求入口和下游；逐项标记已覆盖、未覆盖、无法取得或版本不一致。
3. **人工追踪重点链路**：从字段来源正向追到发送点，从请求逆向追到字段构造；优先核查自动采集、请求改写、同域 API 透传和远程配置。记录文件位置、触发条件、变换及证据断点。
4. **补充验证证据**：在具备授权和环境时，用合成数据验证关键页面请求，并关联网关、后端出口、存储与访问权限。没有证据的下游明确标为未知。
5. **形成方案与整改清单**：每条发现给出证据等级、影响范围、具体修改位置、建议动作、负责方和复验方法；由业务、工程及法务分别确认其负责的判断。

本轮交付为体系主方案、方法取舍、工作表与待验证假设；后续实证阶段再填写真实资产与覆盖表、数据流证据图、待补证据清单和整改卡。是否开发工具，等真实试点暴露的重复工作和漏报类型明确后再决定。
