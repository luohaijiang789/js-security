# S2 引用发现与递归补取执行约定

依据[执行计划 S2](../../docs/site-analysis-plan.md)，本轮先实现 S2.1/S2.2，并提供可验证的串行补取。网络会话、预算恢复及 Worker/source map 等扩展按实际验收更新，不因一条链路可运行就勾选整个 S2。

## 引用与深度

- 复用固定 jshound 的 `imports.specifiers`、`chunkmap.analyse`，使用同一 Babel AST 补充引用位置。不执行目标脚本，也不执行其业务函数。
- HTML 的 script/modulepreload、内联模块、import map，JS 的 import/export、字面量动态 import，以及可确定 publicPath 的 Webpack、可确定模块基址的 Vite 依赖表进入确定引用。推测文件名、任意 JS 字符串、动态表达式单列，不自动下载。
- HTML 为第 0 层，其直接外链/内联模块导入为第 1 层，再依次深入。全部导入资产均分析，包括超过补取上限的已有正文；无父链的 JS 深度为 null。必要时用户可明确指定初始 JS 种子，不自动把所有已加载 JS 当第一层。
- 同上下文按最短已知引用链计算；循环、多父保留所有边，复用相同资产。新出现的短路径会重新评估此前超深度的引用；同 URL 多版本不任选一个。
- 引用行号从 1 开始、列号与 JS start/end 从 0 开始，使用 UTF-16 code units（与 Babel/浏览器一致），保留 BOM 的位移；内联 JS 同时保留局部偏移并还原 HTML 行列。旧 builder 未暴露的位置为 null，不是 API 发送点位置。API 精确位置仍属 S3。

## 补取与保存

- 默认只构图。显式启用补取并提供允许的精确 origin 后，仅取确定脚本引用；允许资源来源和 API Host 是两类信息。
- 每个重定向跳次重新检查 origin；只使用该目标 origin 显式配置的请求头，不从 HAR 自动复制 Cookie/Authorization，不把起点认证头跨域继承。保留系统代理与 TLS 校验。
- 文件数、单文件/总字节、HTTP 超时、补取总时长和有限重试均受预算约束。响应正文必须完整取得且类型符合 JS；HTML 登录页、403、错误 MIME、超限和失败分别记账。
- 每轮保存正文哈希与可恢复 collection checkpoint；恢复前验证正文哈希与路径，不联网时也可重放已有输入。恢复不会把上次未解决错误永久当作已解决。
- 补取属于运行时的新观察，不自动证明与 HAR 原快照同版；来源与获取时间保留。

## 验证顺序

先检查引用提取/import map/打包器，再检查纯图的层数、循环、多父、晚到短路径与版本歧义，最后用本地 HTTP 服务核对实际访问路径、重定向、深度截断、预算和恢复。请求日志中不得出现从 fetch/XHR 等提取的业务 API 探测。公开冻结 JS 用于兼容性检查，不把数量增长解释为全站召回提升。

原 13 请求回归的 HTML 正文固定为 `/main.js`，HAR 生成器现在使用与该 HTML 一致的同源脚本 URL；正文哈希、预期 API 和字段数量不变。CDN 模块基址和 API 请求基址分离仍由独立正常/反例测试覆盖，不用错误的 HAR 来源关系绕过引用缺口检查。
